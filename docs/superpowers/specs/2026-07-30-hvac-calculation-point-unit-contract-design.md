## 1. 背景

真实 Docker Q2 冒烟发现，`POINT007/WCR1_PF` 的初始化单位为 `NULL`。
功率因数虽然无量纲，但当前报文和公式使用 `0.9` 这类比例值，因此其单位应明确
记录为 `1`，而不是留空。

典型值配置服务要求证据包含明确单位，并在测点单位为空时返回 `409`。该校验
可以阻止含义不完整的典型值进入审批和自动补全链路，行为保持不变。

## 2. 修复目标

- 将生产初始化数据和自动化测试夹具中的 `POINT007` 单位统一改为 `1`。
- 建立初始化数据回归契约：所有参与计算的在线模拟量必须具有非空单位。
- 重新验证典型值创建、提交、跨用户审批、自动 Q2、公式、TDengine、Redis、
  API 和 WebSocket 链路。
- 保持现有公式、数据库表结构、典型值审批状态机和 `409` 错误语义不变。

## 3. 数据契约

参与计算的测点满足以下条件时，初始化单位不得为 `NULL` 或空字符串：

```text
data_type = ANALOG
AND is_for_calc = 1
AND status = ONLINE
```

无量纲模拟量统一使用单位 `1`。功率因数继续使用比例值语义：

```text
value = 0.9
unit = 1
```

本次不改成百分数语义，也不会把值转换成 `90 %`，避免改变公式输入。

## 4. 改动范围

### 4.1 生产初始化数据

修改 `src/env/init/03-init-hvac-schema.sql`，将 `POINT007/WCR1_PF` 的单位从
`NULL` 改为 `'1'`。

### 4.2 测试夹具

修改 `src/test/resources/data-test.sql`，保持 H2 测试数据与生产初始化数据一致。

### 4.3 回归测试

增加种子数据单位契约测试：

- 在 H2 中执行现有测试 schema 和数据脚本；
- 查询所有 `ONLINE + ANALOG + is_for_calc=1` 测点；
- 断言不存在 `unit IS NULL` 或空白单位；
- 额外检查生产初始化脚本中的 `POINT007` 明确使用单位 `'1'`，防止生产 SQL
  与测试夹具单向修复后再次漂移。

## 5. 不包含内容

- 不修改 `biz_data_point.unit` 的表级可空约束；
- 不增加测点新增或修改接口的运行时校验；
- 不修改非计算测点、数字量或历史持久数据库；
- 不调整公式值、公式版本或指标单位展示；
- 不修改典型值服务对无单位测点返回 `409` 的行为。

测点新增或修改接口的单位校验作为下一独立任务，在管理功能正式开放和 V1
生产验收前完成。

## 6. 已有数据库处理

初始化脚本只影响空数据目录。已有数据库不会因容器重启自动重放初始化 SQL。

当前 MySQL、TDengine 和 Redis 都是可删除测试数据，因此验收时重新初始化测试
环境。未来持久环境若存在相同数据，应在备份后执行定向更新：

```sql
UPDATE biz_data_point
SET unit = '1'
WHERE point_id = 'POINT007'
  AND unit IS NULL;
```

该更新不纳入本次迁移脚本，避免为尚未进入生产的种子数据缺陷增加永久迁移。

## 7. 验收标准

1. 定向单位契约测试通过。
2. 完整 `mvn test` 回归通过且无跳过项。
3. 全新 MySQL 初始化后，`POINT007.unit = '1'`。
4. 能通过真实 API 为 19 个测点创建典型值配置。
5. 能完成能源管理员提交和平台管理员跨用户审批。
6. 空分钟自动生成 19 个质量 `2` 分钟值。
7. 四项指标均生成 `SUCCESS/dataQuality=2`。
8. TDengine、Redis、最新值 API、历史 API、计算详情 API 和 WebSocket 状态一致。
9. 工作区不新增无关文件，现有未跟踪 `outputs/` 保持不变。

## 8. Docker 验收隔离

本机已有后端占用默认端口并订阅默认 MQTT 主题。回归时使用独立后端端口、唯一
MQTT 客户端 ID 和专用测试主题，避免两个实例互相踢线或竞争写入。测试覆盖的
仍是真实 EMQX、MySQL、TDengine、Redis 和 WebSocket，不使用 Mock 替代。
