# AGENTS 指令分层整改设计

> **文档状态：历史任务设计记录**
>
> 本文保留任务当时确认的设计、假设和取舍，部分内容可能已被后续提交替代。
> 判断当前状态前，请先查看[历史任务目录](../README.md)、
> [项目状态](../../../PROJECT_STATUS.md)、当前代码与测试。


## 状态

已确认，进入实施。

## 背景与问题

Codex 从仓库根目录启动任务。当前根 `AGENTS.md` 为 37,405 字节，再叠加个人全局规则后超过 Codex 默认 32 KiB 的项目指令合并上限，文件后半部分存在无法进入指令链的风险。现有文件还同时保存 Git 流程、架构边界、测试、注释和信息维护细则，重复了 `PROJECT_GUIDE.md`、`PROJECT_STATUS.md` 与现有开发文档的职责。

## 目标

- 根 `AGENTS.md` 作为始终加载的短规则和按需文档路由，目标不超过 10 KiB。
- 保留现有 Git、架构、测试、注释和信息分层要求的有效语义。
- 详细规则按主题存入普通项目文档，只在相关任务中读取。
- 不修改生产代码、构建配置、Hook、CI、业务状态或当前架构。
- 不创建 `web/`、`src/` 子目录 `AGENTS.md`，因为任务从仓库根目录启动。

## 文件职责

| 文件 | 整改后职责 |
|---|---|
| `AGENTS.md` | 强制读取顺序、条件式文档路由、核心 Git 边界、不可突破的架构边界、验证与交付最低要求 |
| `PROJECT_GUIDE.md` | 稳定项目定位、模块职责、数据链路、数据源边界和开发文档导航 |
| `PROJECT_STATUS.md` | 当前完成项、技术债、风险和下一步；本次不改变业务状态 |
| `docs/development/repository-guardrails.md` | Hook、预检、PR 门禁、注释审计生成和合并后清理的完整操作说明 |
| `docs/development/code-comments.md` | Java、Vue、TypeScript 生产代码的完整中文注释与审计判断标准 |
| `docs/development/verification.md` | 后端、前端、外部资源隔离、跨端改动和结果记录的完整验证规则 |

## 规则迁移映射

- 原“Git 开发与提交流程”压缩为根规则；脚本参数和机械流程引用现有 `repository-guardrails.md`。
- 原“现阶段模块化准备与架构边界”的稳定事实以 `PROJECT_GUIDE.md` 为准；根规则只保留禁止越界的硬约束。
- 原“用途优先的业务代码注释”完整迁入 `code-comments.md`；根规则保留触发条件和必须产出审计文档的要求。
- 原“项目信息分层与维护”压缩为根路由；稳定事实与动态状态继续分别由 `PROJECT_GUIDE.md` 和 `PROJECT_STATUS.md` 承担。

## 验证与验收

- 全局 `AGENTS.md` 与项目根 `AGENTS.md` 合计低于 32 KiB。
- 根文件中的每个条件式链接均存在，且能够从仓库根目录解析。
- Git、分支、禁止操作、测试失败不可交付、数据源边界、真实数据、注释审计和文档分层等关键语义均能在新文件中定位。
- 仓库防护测试通过，Markdown 链接与暂存差异检查通过。
- 纯规则与文档整改不运行无关业务测试；如仓库门禁要求额外检查，则执行并如实记录。

## 非目标

- 不拆分前端和后端仓库。
- 不调整 `project_doc_max_bytes`。
- 不改变模型、子代理、Hook、CI、业务代码或项目当前完成状态。
