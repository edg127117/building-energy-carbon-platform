# 测点运行时单位校验设计

## 1. 背景与目标

种子数据契约已经要求 `ONLINE + ANALOG + is_for_calc=1` 的计算测点具有非空
单位，但当前测点新增和修改接口仍可能在运行时写入不满足该契约的数据。

本次在 `BizDataPointServiceImpl` 的写入边界增加校验，确保非法测点在写入
MySQL 和刷新 `MySqlDataPointConfigProvider` 之前被拒绝，避免公式、典型值和
数据质量链路读取到含义不完整的计算输入。

## 2. 业务规则

最终测点状态同时满足以下条件时，`unit` 不得为 `null`、空字符串或纯空白：

```text
status = ONLINE
AND dataType = ANALOG
AND isForCalc = 1
```

不满足单位要求时抛出：

```text
BusinessException(400, "参与计算的在线模拟量必须配置单位")
```

非计算、非在线或非模拟量测点不受本规则限制。状态和类型比较沿用现有枚举字符串，
采用忽略大小写比较，避免合法的大小写差异绕过或误触发校验。

## 3. 新增流程

`add` 保持现有身份初始化和关系校验，在 `save` 之前校验传入测点的最终状态。
只有关系和单位契约均通过后，才写入 MySQL 并刷新测点配置快照。

调用顺序为：

```text
清除客户端 pointId
→ 校验命名规则及设备/系统归属
→ 校验计算测点单位
→ save
→ refreshAll
```

## 4. 修改流程

`update` 先按 `pointId` 读取现有测点。普通编辑不能改变标准身份字段，因此继续
使用现有值锁定以下字段：

- `pointCode`
- `buildingId`
- `systemGroupId`
- `equipId`
- `namingRuleId`
- `familyCode`
- `componentCode`
- `suffixCode`
- `dataType`

单位规则依赖的可编辑字段 `status`、`isForCalc` 和 `unit` 若未随请求提供，则以
现有值补全。这样校验对象与 MyBatis-Plus 默认忽略空字段的更新结果一致，避免部分
更新把旧的空单位测点切换为在线计算状态，或因请求省略字段产生误判。

锁定身份字段和补全单位规则字段后，先执行现有关系校验，再校验最终对象。两项校验
均通过后才执行 `updateById` 和 `refreshAll`。

## 5. 失败原子性

单位校验必须位于 `save`、`updateById` 和 `refreshAll` 之前。校验失败直接抛出
400 业务异常：

- 不写入或修改 MySQL；
- 不刷新 `MySqlDataPointConfigProvider`；
- 不改变当前内存配置快照。

## 6. 测试设计

新增 `BizDataPointServiceImplTest`，使用 Mock Mapper 和配置提供者隔离外部资源，
至少覆盖：

1. 新增在线计算模拟量时，单位为 `null` 或空白均返回 400。
2. 更新并合并旧状态后成为在线计算模拟量、最终单位为空时返回 400。
3. 合法单位可以新增和修改，并在写库后刷新配置。
4. 非计算、离线、非模拟量测点不会被单位规则误拒绝。
5. 拒绝新增时不调用 Mapper `insert`，拒绝修改时不调用 `updateById`。
6. 任一拒绝路径均不调用 `refreshAll`。
7. 更新时客户端不能改变锁定的 `dataType` 等身份字段。

完成定向 Service 测试后执行完整 `mvn test`，且普通自动化测试不连接真实 MySQL、
TDengine、MQTT、Redis 或第三方服务。

## 7. 代码生成器边界

当前代码生成器只输出预览或 ZIP，不会自动覆盖工作区源码。通用模板只负责单表
CRUD，不承载 HVAC 测点单位等领域规则。

`BizDataPointServiceImpl` 是生成后人工维护的业务 Service，生成结果只能选择性
合并，不能整体覆盖。类级中文注释和 Service 回归测试共同锁定这一边界。

生成代码与人工定制代码的长期隔离属于独立生成器增强任务。除非 Demo/V1 前需要
频繁重新生成测点 CRUD，否则该改造在前后端核心链路完成、通过回归并可稳定演示后
再处理。

## 8. 不包含内容

- 不修改数据库表结构、初始化数据或迁移脚本；
- 不修改公式、单位换算或无量纲值语义；
- 不修改典型值审批状态机及无单位测点现有 `409` 语义；
- 不修改代码生成器模板、元数据或 ZIP 输出；
- 不进行模块拆分或其他无关重构。

## 9. 验收标准

1. `add` 和 `update` 都在持久化之前校验最终测点状态。
2. 非法状态返回 400 和指定中文消息。
3. 拒绝时不写 MySQL、不刷新测点配置快照。
4. 合法和豁免场景保持可用。
5. 更新身份字段继续锁定，校验基于合并后的最终对象。
6. 定向测试和完整 `mvn test` 全部通过。
7. 只提交本任务文件，不修改或提交任何旧工作树的 `outputs/`。
