# HVAC WebSocket 实时推送、断线重连与 HTTP 降级设计

> 状态：已确认并完成书面复核。本设计闭环 HVAC 大屏的实时指标推送、连接恢复、HTTP 权威同步和建筑权限隔离，不扩展为 19 测点完整 WebSocket 快照。

## 1. 背景与目标

当前 HVAC 页面已经接入真实建筑、19 测点分钟快照、四项最新指标、计算详情和历史趋势。页面主体仍使用非重叠的 30 秒 HTTP 轮询；后端虽然存在 `/ws/hvac`，但当前端点只广播四项指标状态，前端尚未消费。

现有 WebSocket 还有一个必须在正式接入前修复的安全缺口：握手路径匿名放行，所有客户端共享同一会话池，指标消息向全部连接广播。消息携带 `buildingId` 并不能形成权限隔离；前端过滤只能阻止展示，不能阻止无权用户在网络帧中收到其他建筑数据。

本任务建立以下闭环：

- 页面首次通过 HTTP 获取完整、可授权、可审计的当前状态；
- WebSocket 低延迟通知四项指标变化；
- 连续指标消息合并触发一次 HTTP 权威同步，补齐 19 测点和完整指标状态；
- WebSocket 断线时自动恢复 30 秒 HTTP 轮询；
- WebSocket 按有界退避自动重连，成功后立即 HTTP 对账；
- WebSocket 采用 JWT 认证和建筑订阅，后端只向有权连接发送对应建筑消息；
- 页面明确区分实时通道状态、HTTP 保障状态和业务数据状态。

目标不是用 WebSocket 取代所有 HTTP，而是让两者各自承担适合的职责：WebSocket 负责及时通知，HTTP 负责完整状态、断线补偿和权威校准。

## 2. 当前事实与问题边界

### 2.1 已有能力

- `IndicatorRealtimePublisher` 在 TDengine 持久化成功、Redis 接受最新分钟之后发布 `HVAC_INDICATOR` 消息。
- 消息包含指标实例、指标编码、建筑、设备、分钟、状态、数值、质量、公式版本、失败原因和缺失输入。
- `HvacDemoPage` 通过 `useHvacDashboard` 查询当前建筑的 19 测点快照和全部最新指标。
- HTTP 查询已经使用 JWT、角色和 MySQL 建筑授权，并具备 Redis/TDengine 回退与错误处理。
- 页面已能保留最后一次成功数据、隔离建筑切换后的迟到响应，并使用非重叠刷新避免请求堆积。

### 2.2 当前缺口

- 前端没有建立 `/ws/hvac` 连接。
- 后端 WebSocket 只发布四项指标，不发布 19 测点快照。
- 后端按全局会话池广播，没有 JWT、订阅或建筑路由。
- WebSocket 断线、假连接、重连、认证失败和页面卸载没有前端状态机。
- 当前“真实分钟数据已连接”只表示至少一次 HTTP 查询成功，不能代表实时通道正常。
- 如果直接在 WebSocket 连接后停掉全部 HTTP，19 测点会停留在旧数据，断线期间遗漏的指标也无法补回。

## 3. 已选方案与备选方案

### 3.1 已选：WebSocket 增量通知 + HTTP 权威同步

正常连接时，WebSocket 消息立即更新对应指标卡；同一批连续指标消息在前端合并为一次 HTTP 刷新。HTTP 返回当前建筑完整的 19 测点快照和全部最新指标，用于校准页面状态。

断线时恢复固定 30 秒 HTTP 轮询并继续重连。重连成功后立即执行一次 HTTP 全量同步，补回断线期间未收到的消息，然后停止固定轮询。

该方案复用现有权限和查询能力，不复制 19 测点快照组装逻辑，同时保留接近实时的指标展示。

### 3.2 未采用：WebSocket 推送 19 测点完整快照

该方案可以在连接正常时基本停止 HTTP，但需要新增测点快照发布触发、后端组装、消息 DTO、建筑路由、前端映射和两套状态一致性测试。当前分钟快照 API 已经稳定，V1 没有必要为减少每分钟一次的合并查询复制整条数据链。

### 3.3 未采用：WebSocket 与 30 秒轮询永久并行

该方案改动最少，但每个客户端始终产生固定查询，WebSocket 只带来部分指标提前显示，不能形成明确的“正常实时、异常降级”状态，也不能减少空轮询。

### 3.4 未采用：JWT 放入 WebSocket URL

浏览器原生 WebSocket 不能像 Axios 一样设置 `Authorization` 请求头。把 JWT 放入查询参数实现简单，但 URL 可能进入反向代理、服务器访问日志或诊断记录，因此不采用。

### 3.5 未采用：STOMP、SockJS 或短期票据 API

STOMP/SockJS 会增加协议、依赖和前端运行复杂度；短期一次性票据更适合更高安全等级或跨域公共实时网关，但会新增 HTTP API、Redis 票据状态和失效流程。当前 V1 采用连接后的首帧认证即可满足受控系统需要。

## 5. 总体架构与数据流

```text
MQTT 上行
  → 分钟冻结
  → 四项公式计算
  → TDengine 持久化成功
  → Redis 接受最新分钟
  → IndicatorRealtimePublisher
  → WebSocketRealtimeMessageGateway.sendToBuilding(buildingId, message)
  → HvacRealtimeSessionRegistry
  → 仅发送给已认证且订阅该建筑的 Session
  → 前端 HvacRealtimeClient
  → useHvacDashboard
       ├─ 立即合并指标消息到当前卡片
       └─ 合并触发 HTTP refresh
            ├─ GET 建筑 19 测点快照
            └─ GET 建筑全部最新指标
```

WebSocket 失败不改变既有持久化顺序：TDengine 仍是历史事实来源，Redis 仍是最新指标缓存，HTTP 仍是完整当前状态的权威读取入口。实时发送失败只影响消息时效，不回滚公式结果。

## 6. WebSocket 协议

### 6.1 地址与握手

后端端点内部路径保持：

```text
/ws/hvac
```

应用部署在 `/api` 上下文时，浏览器连接地址为：

```text
ws://<host>:<port>/api/ws/hvac
wss://<host>/api/ws/hvac
```

握手路径可以在 Spring Security HTTP 过滤器中匿名放行，因为浏览器原生 WebSocket 无法设置 Bearer 请求头。匿名握手只允许建立空会话，不代表获得业务数据权限。

客户端必须在连接打开后 5 秒内发送 `SUBSCRIBE`。超时、消息非法或认证失败时，服务端发送脱敏错误后关闭连接。认证完成前，会话不进入任何建筑组，也不接收 `HVAC_INDICATOR`。

### 6.2 客户端消息

订阅：

```json
{
  "type": "SUBSCRIBE",
  "token": "<JWT>",
  "buildingId": "BLD001"
}
```

心跳：

```json
{
  "type": "PING"
}
```

规则：

- 一个连接同时只允许订阅一个建筑。
- 同一连接再次发送 `SUBSCRIBE` 视为重新认证并替换旧建筑订阅。
- `token` 只在加密连接或受控本地环境中传输，不进入 URL、日志、错误响应或前端持久化副本。
- 服务端仅在会话存活期间保存完成复核所需的 Token，关闭时立即清理。
- 未订阅会话发送 `PING` 不获得业务权限，服务端可以返回错误并关闭。

### 6.3 服务端消息

订阅成功：

```json
{
  "type": "SUBSCRIBED",
  "buildingId": "BLD001",
  "serverTime": 1786291200000
}
```

心跳响应：

```json
{
  "type": "PONG",
  "serverTime": 1786291220000
}
```

指标消息继续复用现有业务状态，不增加前端计算字段：

```json
{
  "type": "HVAC_INDICATOR",
  "data": {
    "indicatorId": "...",
    "indicatorCode": "WCR_COP",
    "buildingId": "BLD001",
    "equipId": "...",
    "minuteStart": 1786291140000,
    "status": "SUCCESS",
    "value": 5.21,
    "dataQuality": 0,
    "formulaVersion": "...",
    "reasonCode": null,
    "missingInputs": [],
    "inputs": [],
    "steps": []
  }
}
```

错误：

```json
{
  "type": "ERROR",
  "code": "FORBIDDEN_BUILDING",
  "message": "无权订阅该建筑"
}
```

错误消息只返回用户可理解的稳定编码和脱敏文案，不返回 JWT 解析异常、SQL、Redis、堆栈或内部类名。

### 6.4 关闭码

| 关闭码 | 含义 | 前端处理 |
| --- | --- | --- |
| `1000` | 页面卸载、切换建筑或主动关闭 | 不重连旧连接 |
| `4400` | 协议或消息格式非法 | 进入 HTTP 保障并停止自动重连，避免版本不兼容造成无限循环 |
| `4401` | JWT 无效、过期或登录态失效 | 停止重连，统一清理登录状态并进入登录页 |
| `4403` | 无目标建筑权限 | 停止当前建筑订阅，展示权限错误 |
| `4408` | 订阅或心跳超时 | 启动 HTTP 保障并自动重连 |
| `1011` | 服务端实时处理异常 | 启动 HTTP 保障并自动重连 |
| `1006` | 浏览器观察到异常断开 | 启动 HTTP 保障并自动重连 |

`4400` 至 `4499` 是本系统使用的应用关闭码，不改变 HTTP 状态码契约。

## 7. 后端设计

### 7.1 WebSocket 端点

现有 `WebSocketServer` 保留为传输入口，但不再持有全局业务广播逻辑。端点负责：

- 建立和关闭 Session；
- 解析有限的客户端协议；
- 在 5 秒订阅期限内接收首帧认证；
- 把认证、权限和会话管理委托给明确服务；
- 发送 `SUBSCRIBED`、`PONG` 和 `ERROR`；
- 异常或关闭时调用注册表清理。

端点不访问 Mapper、Repository、TDengine 或公式服务，不自行实现角色和建筑规则。

### 7.2 实时访问服务

`HvacRealtimeAccessService` 负责把 WebSocket 的 `SUBSCRIBE` 转换为与 HTTP 一致的身份和数据范围判断：

1. 使用 `JwtService.parseToken` 校验签名和过期时间；
2. 提取用户 ID 和正式角色；
3. 使用 `TokenCacheService.validateActiveToken` 校验当前单账号登录态；
4. Redis 明确拒绝时返回未认证；Redis 不可用时沿用 HTTP 的可用性优先语义，仅信任已验证 JWT；
5. 使用 `BuildingScopeService.checkAccess` 校验目标建筑；
6. 返回只包含 userId、roles、buildingId、过期时间和会话所需 Token 的认证上下文。

JWT 只承载身份和角色，建筑权限继续实时读取建筑范围服务。该边界避免在 WebSocket 中复制一套与 HTTP 不一致的权限算法。

身份与权限必须区分三类结果：Token 明确无效使用 `4401`，建筑明确无权使用 `4403`，MySQL 等权限事实来源暂不可用且无法完成判断时使用 `1011` 和稳定错误码 `REALTIME_AUTH_UNAVAILABLE`。临时外部资源故障不得伪装成用户无权限，也不得在无法证明建筑范围时放行新订阅；前端对此进入 HTTP 保障并继续普通重连。

### 7.3 建筑会话注册表

`HvacRealtimeSessionRegistry` 是线程安全的单实例会话边界：

- 以 `buildingId → sessionId → authenticatedSession` 保存订阅；
- 同一 Session 只能位于一个建筑组；
- 重订阅先原子移除旧建筑关系，再加入新建筑；
- 发送时只遍历目标建筑的当前快照，不扫描其他建筑；
- 每个 Session 使用串行发送保护，避免并发 `TEXT_FULL_WRITING`；
- 发送失败、关闭、异常或权限复核失败时幂等移除会话；
- 注册表不持久化，不承担多实例同步。

### 7.4 建筑定向网关

`RealtimeMessageGateway` 从：

```java
broadcast(String message)
```

收敛为建筑明确的调用：

```java
sendToBuilding(String buildingId, String message)
```

`IndicatorRealtimePublisher` 直接使用已存在于 `IndicatorLatestState` 的 `buildingId` 调用网关。注册表不得重新解析 JSON 推断路由，避免序列化格式变化造成跨建筑误发。

### 7.5 心跳与权限复核

- 前端每 20 秒发送一次 `PING`。
- 服务端收到 `PING` 时重新校验 JWT 有效期、Redis 登录状态和当前建筑权限，再返回 `PONG`。
- 前端发送 `PING` 后 10 秒内没有收到 `PONG`，主动关闭假连接并进入重连。
- 权限撤销、账号重新登录或 Token 过期最多在下一次心跳时被发现。
- 服务端不会因为一段时间没有指标数据而关闭连接；没有业务数据是正常状态，连接健康只由心跳判断。

### 7.6 异常与日志

- 日志可以记录 sessionId、userId、buildingId、关闭码和稳定错误码。
- 禁止记录 JWT、完整 `SUBSCRIBE` 消息或异常中的敏感 claims。
- 单个 Session 发送失败只清理该 Session，不阻断同建筑其他会话。
- WebSocket 失败继续保持“最佳努力发布”，不向上抛出导致公式事务回滚。
- 协议解析限制消息尺寸和字段范围，不接受任意业务命令。

## 8. 前端设计

### 8.1 传输适配层

新增 `HvacRealtimeClient`，只负责：

- 根据配置建立原生 WebSocket；
- 在 `open` 后发送 `SUBSCRIBE`；
- 解析服务端信封并校验必要字段；
- 管理订阅确认超时、PING/PONG 和主动关闭；
- 向上层发出已订阅、指标、断开、未认证、无权限和协议异常事件。

该层不依赖 Vue `ref`，不查询 HTTP，不修改页面数据，也不自行决定是否轮询，便于使用 Fake WebSocket 和 Fake Timer 完整测试。

### 8.2 地址配置

前端增加显式的 WebSocket 基地址示例配置。业务代码不写死主机、端口或协议：

```text
VITE_WS_BASE=ws://localhost:8081/api
```

地址优先级固定为：存在 `VITE_WS_BASE` 时直接使用；未配置时从当前 `VITE_API_BASE` 推导。推导先用浏览器当前地址解析相对路径，再只把 `http/https` 转换为 `ws/wss` 并保留 `/api` 上下文，最终统一追加 `/ws/hvac`，禁止形成 `/api/api`。生产环境必须得到 `wss://` 地址。

### 8.3 页面状态编排

`useHvacDashboard` 继续负责建筑选择、HTTP 快照和最新指标，是页面实时状态的唯一编排者。新增状态至少包括：

- `CONNECTING`：正在建立连接或等待订阅确认；
- `CONNECTED`：已认证并订阅当前建筑；
- `RECONNECTING`：异常断开且正在有界重连；
- `HTTP_FALLBACK`：实时通道暂不可用，固定轮询保障数据；
- `FORBIDDEN`：当前建筑订阅被拒绝；
- `STOPPED`：页面卸载、退出登录或没有选中建筑。

WebSocket 客户端实例、重连计时器、心跳计时器、合并刷新计时器和 HTTP 轮询都必须有唯一所有者，重复调用不会创建第二份资源。

### 8.4 首次加载

页面进入后顺序为：

1. HTTP 查询授权建筑；
2. 选择记忆中仍有权的建筑或首个建筑；
3. 并行 HTTP 查询该建筑快照和最新指标；
4. 启动 30 秒保障轮询；
5. 建立 WebSocket 并发送当前建筑订阅；
6. 收到 `SUBSCRIBED` 后执行一次非重叠 HTTP 同步，消除首次 HTTP 与订阅成功之间的时间窗口；
7. 该次快照与最新指标均成功后，才停止固定轮询并进入实时正常状态；部分失败时继续 HTTP 保障。

首次 HTTP 失败不使用假数据；页面保留错误状态，同时仍可尝试建立 WebSocket。WebSocket 指标消息只能补充指标，不能伪装成完整 19 测点快照。

### 8.5 指标增量合并

收到 `HVAC_INDICATOR` 后：

1. 校验消息 `buildingId` 等于当前选中建筑；
2. 校验指标实例和稳定指标编码；
3. 早于当前同指标 `minuteStart` 的消息直接忽略；
4. 晚于当前分钟的消息覆盖；
5. 相同分钟消息允许覆盖，用于 Q2 → Q1 → Q0 或失败状态修正；
6. WebSocket 不携带的单位继续保留当前 HTTP 值或页面稳定定义；
7. 更新页面指标时间戳，但不改写 19 测点快照时间戳；
8. 调度一次 500 毫秒尾随 HTTP 同步。

后端对单 Session 串行发送，同一分钟后到达的状态被视为较新的权威修正。前端不执行公式、不补默认输入、不自行改变数据质量。

### 8.6 合并 HTTP 同步

四项公式通常在同一分钟连续产生消息。前端采用尾随合并：

- 第一条消息创建 500 毫秒同步计时器；
- 窗口内后续消息只更新本地指标，不创建额外计时器；
- 计时器到期调用现有非重叠 `refresh()`；
- 如果刷新正在执行，记录一次“刷新待执行”，当前请求完成后只再执行一次；
- 建筑切换、页面卸载或登录失效会取消待执行刷新；
- 历史趋势和计算详情不加入该刷新。

### 8.7 断线与 HTTP 保障

异常断开后立即：

1. 将页面状态改为 `RECONNECTING` 或 `HTTP_FALLBACK`；
2. 执行一次非重叠 HTTP 刷新；
3. 启动固定 30 秒轮询；
4. 按 `1 秒 → 2 秒 → 5 秒 → 10 秒 → 30 秒` 重连，后续保持 30 秒上限；
5. 同一时刻只允许一个连接尝试。

连接持续稳定 60 秒后重置退避次数。收到 `SUBSCRIBED` 后立即 HTTP 对账；对账完成后停止固定轮询。对账部分失败时保留成功部分和最后数据，继续按 30 秒重试失败的完整状态，不把查询失败显示成无数据。

### 8.8 认证与权限失败

- `4401`：调用 HTTP 和 WebSocket 共用的会话失效处理，删除本地 Token 和用户视图，停止连接、轮询和重连，跳转登录页。
- `4403`：保留登录状态，停止当前建筑订阅，显示“无权订阅当前建筑”，并重新获取授权建筑列表或等待用户切换。
- `4400`：认为前后端协议不兼容，停止自动重连并保留 HTTP 保障；页面重新加载或版本更新后才重新尝试，避免持续发送同一非法消息。
- 普通网络失败不得清理 Token，也不得连续弹出错误消息。
- 服务端 `ERROR` 文案只用于当前状态提示，前端逻辑以稳定错误码和关闭码判断。

现有 HTTP 401 副作用从 `request.ts` 提取为可复用会话函数，WebSocket 调用同一入口，避免两个通道出现不同的清理行为。

### 8.9 建筑切换与竞态

切换建筑时：

- 使用 `1000` 主动关闭旧连接，旧连接不重连；
- 停止旧建筑的心跳、重连、合并刷新和轮询；
- 清空旧建筑快照、指标和错误；
- HTTP 加载新建筑后建立新订阅；
- 所有 HTTP 响应和 WebSocket 回调都携带创建时的建筑上下文版本；版本不一致时丢弃；
- 旧连接迟到的 `close`、`message` 或计时器不能改变新连接状态。

### 8.10 页面卸载

离开 HVAC 页面时必须：

- 主动关闭 WebSocket；
- 清理订阅超时、心跳、PONG 超时、重连和合并刷新计时器；
- 停止 HTTP 轮询；
- 取消或隔离无法真正取消的迟到 HTTP 结果；
- 禁止卸载后继续写 Vue 状态或触发重连。

## 9. 页面状态与用户体验

页面顶部现有连接文案改为真实通道状态：

| 状态 | 文案 | 视觉语义 |
| --- | --- | --- |
| `CONNECTING` | 实时连接中 | 蓝色、中性等待 |
| `CONNECTED` | 实时连接正常 | 绿色 |
| `RECONNECTING` | 实时重连中，HTTP 保障 | 黄色 |
| `HTTP_FALLBACK` | HTTP 保障中 | 黄色 |
| `FORBIDDEN` | 无该建筑访问权限 | 红色 |

体验规则：

- 短暂网络抖动只更新状态标识，不连续弹出 Toast。
- 手动刷新始终可用，并继续调用现有 HTTP 权威查询。
- HTTP 更新时间与 WebSocket 连接状态分别表达，不把“连接正常”解释成所有测点都有最新数据。
- 指标卡继续展示计算成功、缺失输入、无效输入或计算异常；网络状态不转换为设备故障。
- 快照的新鲜度继续来自后端 `NORMAL/STALE/NO_DATA`，前端不根据 WebSocket 断线自行修改测点业务状态。
- 历史曲线保持用户查询模式，计算详情保持所打开分钟的证据，不因新实时消息自动跳转。

## 10. 一致性、失败与恢复

### 10.1 权威顺序

```text
TDengine 历史事实
→ Redis 最新指标缓存
→ HTTP 完整当前状态
→ WebSocket 最佳努力增量通知
```

WebSocket 消息可以让页面更快，但不能覆盖更晚的 HTTP 权威结果，也不能让旧分钟回退当前状态。

### 10.2 典型场景

| 场景 | 预期行为 |
| --- | --- |
| WebSocket 正常、HTTP 正常 | 指标立即更新，随后一次合并 HTTP 校准 |
| WebSocket 断开、HTTP 正常 | 页面进入 HTTP 保障并每 30 秒刷新，同时重连 |
| WebSocket 正常、HTTP 暂时失败 | 保留实时指标和旧快照，展示 HTTP 错误并继续有界重试 |
| WebSocket 与 HTTP 同时不可用 | 保留最后数据并标记错误，不生成默认值；两条链分别恢复 |
| 断线期间产生新指标 | 重连后 HTTP 对账恢复当前状态，不要求 WebSocket 补发历史帧 |
| 同一分钟质量升级 | 相同分钟新消息覆盖，HTTP 对账最终确认 |
| 收到旧分钟 | 忽略，不回退页面 |
| 收到其他建筑 | 后端不应发送；前端防御性忽略并记录脱敏诊断 |
| 权限被撤销 | 下一次心跳拒绝并关闭，页面停止该建筑实时订阅 |
| 用户重新登录使旧 Token 失效 | 下一次心跳返回未认证，旧页面退出登录 |

## 11. 安全边界

- WebSocket 握手匿名不等于业务匿名；认证完成前零业务数据。
- 建筑路由由后端注册表执行，前端过滤不是权限控制。
- JWT 不进入 URL、日志、错误消息或服务器长期存储。
- WebSocket 复用 HTTP 的 JWT、正式角色、Redis 登录状态和 MySQL 建筑授权语义。
- Redis 故障降级与 HTTP 保持一致；明确拒绝的 Token 不得降级放行。
- 所有权限错误使用脱敏稳定码，内部异常只写安全日志。
- 生产环境必须使用 `wss://` 或由 HTTPS 反向代理升级连接。
- 本任务不解决多实例会话路由；未来多实例前必须重新设计粘性会话或共享实时总线。

## 12. 自动化测试设计

### 12.1 后端

- 有效 JWT、正式角色、活动 Token 和有权建筑订阅成功。
- JWT 缺失、非法、过期、无正式角色或 Redis 明确拒绝时返回 `4401`。
- Redis 不可用时只在 JWT 已验证前提下降级，语义与 HTTP 一致。
- 无建筑权限返回 `4403`，且会话从未进入建筑组。
- 未订阅连接收不到指标。
- A 建筑消息只发送给 A 建筑连接，B 建筑连接和未认证连接均不接收。
- 重订阅原子移除旧建筑关系。
- 心跳成功返回 `PONG`；Token 失效或权限撤销后关闭并清理。
- 订阅超时、非法消息、正常关闭、异常关闭和发送失败均幂等清理。
- 同一 Session 并发发送保持串行，不出现写入冲突。
- `IndicatorRealtimePublisher` 使用状态中的 `buildingId` 调用定向网关。
- 网关失败不影响公式处理返回，不改变 TDengine 和 Redis 提交结果。
- 普通自动化测试使用 Mock/Fake，不启动真实端口，不连接真实 Redis、MySQL、TDengine 或 MQTT。

### 12.2 前端

- 首次 HTTP 完成后建立订阅，订阅成功停止固定轮询。
- 订阅超时或异常断开立即 HTTP 刷新并启动轮询。
- 重连延迟为 1、2、5、10、30 秒且不创建重复连接。
- 稳定 60 秒后退避归零。
- 重连成功只执行一次 HTTP 对账，成功后停止固定轮询。
- 四条连续指标消息立即更新卡片，但只触发一次合并 HTTP 请求。
- 请求执行期间的新消息只产生一次尾随刷新。
- 旧分钟、其他建筑、非法类型和字段不完整消息不覆盖页面。
- 相同分钟修正允许覆盖，单位保持稳定。
- `4401` 使用统一会话失效入口；`4403` 保留登录但停止当前订阅。
- 切换建筑和页面卸载清理所有连接、计时器和迟到回调。
- 页面状态标识与实际状态一致，短暂断线不产生 Toast 风暴。
- 历史曲线和计算详情不会因实时消息自动请求或跳转。

### 12.3 跨层契约

- 前后端对 `type`、`buildingId`、`minuteStart`、指标状态、质量、错误码和关闭码的解释一致。
- 外部连接地址只追加一次 `/api/ws/hvac`，不存在 `/api/api`。
- WebSocket 指标与 HTTP 最新指标在同一建筑、指标和分钟上最终一致。
- 无权用户在浏览器网络帧中不能收到其他建筑业务消息。

## 15. 风险与控制

| 风险 | 控制 |
| --- | --- |
| 匿名握手被误认为匿名业务 | 5 秒内强制订阅认证，认证前零业务数据 |
| 前端过滤代替后端权限 | 注册表按建筑定向发送，越权连接不入组 |
| 断线漏消息 | 重连成功立即 HTTP 对账，不依赖历史补发 |
| 四项消息造成四次查询 | 500 毫秒尾随合并和非重叠刷新 |
| 重连风暴或重复连接 | 单实例连接状态机和 30 秒退避上限 |
| 假连接长期占用 | 20 秒 PING、10 秒 PONG 超时和幂等清理 |
| Token 或权限撤销后继续收消息 | 每次心跳重新验证登录态和建筑权限 |
| WebSocket 失败回滚公式 | 网关保持最佳努力，持久化和缓存顺序不变 |
| 单体多实例后消息只在本机 | 明确列为未来扩展边界，本任务不伪装已支持 |
| 状态文案误导用户 | 网络状态、HTTP 更新时间和业务数据质量分开表达 |

## 16. 验收标准

1. 页面首次进入仍能通过 HTTP 获得当前建筑完整数据。
2. 有权用户可以认证订阅当前建筑，无权用户被后端拒绝。
3. 未认证或其他建筑连接收不到当前建筑指标帧。
4. 指标计算完成后，当前建筑页面无需等待 30 秒即可看到更新。
5. 连续四项指标消息最多合并触发一次 HTTP 权威同步。
6. WebSocket 正常时停止固定 30 秒轮询；手动刷新仍可用。
7. 断线后立即进入 HTTP 保障并按 1、2、5、10、30 秒重连。
8. 重连成功后立即对账，补回遗漏状态并停止固定轮询。
9. JWT 失效停止重连并统一退出登录；建筑权限失败不清除用户登录。
10. 切换建筑和卸载页面不会留下旧连接、轮询、心跳或迟到写回。
11. 历史曲线、计算详情、19 测点新鲜度、MQTT、公式和数据质量链路没有行为回退。
12. 自动化测试、Docker 冒烟和浏览器全流程结果均如实记录，未执行项明确说明原因。
13. 生产环境地址可配置，JWT 不进入 URL、日志和仓库文件。
14. `PROJECT_GUIDE.md`、`PROJECT_STATUS.md` 和协议说明与最终实现一致。
