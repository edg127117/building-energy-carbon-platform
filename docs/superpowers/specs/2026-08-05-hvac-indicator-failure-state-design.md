# HVAC 指标失败状态展示优化设计

> 状态：已确认方案的任务一设计。本文只描述指标卡与计算详情抽屉的失败状态展示，不包含数据新鲜度和完整率语义修复。

## 1. 背景与目标

当前四张实时能效指标卡在计算失败时，直接同时展示状态、后端原因码和全部缺失语义键。在四列布局中，这些技术文本挤压指标名称和值，造成断行、卡片高度失控和较高的理解成本。

本任务将失败状态改为“卡片给结论，抽屉给证据”：卡片帮助运行人员快速判断哪项指标不可用，详情抽屉继续保留后端返回的原因码和缺失语义键，供排查使用。

## 2. 范围

### 2.1 本任务包含

- 重组四张指标卡的信息层级和响应式布局。
- 为成功、缺少输入、输入无效、计算异常、无记录和未知状态提供简短业务文案。
- 将原因码和缺失语义键从指标卡移入详情抽屉的诊断区域。
- 让指标卡的无障碍名称同时包含指标名称、当前状态和“查看计算详情”操作。
- 调整详情抽屉的失败摘要，使业务结论先于技术诊断信息。
- 补充对应的前端组件测试、页面契约测试和浏览器桌面/移动端验收。

### 2.2 本任务不包含

- 不修改后端 API、DTO、公式引擎、分钟聚合或数据质量流程。
- 不修改测点完整率算法，也不新增 `STALE` 数据新鲜度状态。
- 不把历史成功值当作当前值展示，不在浏览器重算指标或生成默认值。
- 不重做整张 HVAC 大屏，不调整拓扑、公式目录、历史趋势和测点列表。

“旧数据仍显示 NORMAL、完整率 100%”将在任务二中以独立设计、分支和 PR 处理。

## 3. 交互与信息层级

### 3.1 指标卡

每张指标卡固定采用四层信息：

1. 指标名称与文字状态；
2. 指标值和单位，失败时保持 `--`；
3. 一句业务摘要；
4. 来源分钟与“查看计算详情”入口。

失败状态的业务摘要映射如下：

| 后端状态 | 卡片状态 | 业务摘要 |
|---|---|---|
| `SUCCESS` | 计算成功 | 最新分钟计算完成 |
| `MISSING_INPUT` | 缺少输入 | 当前分钟缺少必要输入 |
| `INVALID_INPUT` | 输入无效 | 当前分钟输入数据无效 |
| `ENGINE_ERROR` | 计算异常 | 当前分钟计算未完成 |
| `NO_DATA` | 暂无数据 | 暂无可用计算记录 |
| 未知状态 | 保留后端状态 | 当前指标暂不可用 |

如果后端返回缺失语义键，卡片只显示“缺少 N 项必要输入”，不展示键名。原因码和键名仍原样传入计算详情请求，不丢失诊断信息。

### 3.2 详情抽屉

失败详情继续展示计算摘要、输入证据和后端诊断信息，但把原“失败审计”改为更直接的“异常详情”：

- 首先说明“本分钟未产生指标值，以下信息用于定位数据或公式问题”；
- 状态使用业务文案；
- 原因码和缺失语义键作为技术诊断字段展示；
- 长原因码和键名允许换行，不造成横向滚动。

请求失败、无本地目标、后端无记录和成功详情的既有行为保持不变。

## 4. 响应式布局

- 大屏右侧栏：指标卡纵向排列，内容保持单一阅读方向。
- 页面降为横向指标区时：宽桌面四列，中等屏幕两列，手机单列。
- 卡片采用稳定的最小高度和网格区域，长中文状态不会挤压指标名称和值。
- 正文和状态文字不再使用难以阅读的 7—9px 字号；交互目标保留清晰的键盘焦点。
- 卡片内容允许正常换行，但页面不得因指标文案产生横向溢出。

## 5. 数据流与边界

后端 `latest indicators` 响应仍由 `buildIndicatorViews` 转换为四个固定指标槽位。页面只基于已有的 `status`、`statusLabel`、`minuteStart`、`reasonCode` 和 `missingInputs` 生成展示文案，不改变指标值是否成功的判定。

用户点击卡片后，页面继续把 `indicatorId`、`indicatorCode` 和 `minuteStart` 交给 `useHvacCalculationDetail`；抽屉仍只展示详情 API 返回的事实。页面不会从缺失键推测设备故障，也不会承诺数据何时恢复。

## 6. 测试与验收

### 6.1 自动化测试

- 页面契约测试：确认指标卡不再直接拼接缺失语义键，并存在状态摘要、来源分钟和包含状态的无障碍名称。
- 抽屉组件测试：确认失败状态先显示业务结论，同时保留原因码和缺失语义键。
- 执行前端完整单元测试、TypeScript/Vue 检查、ESLint 和生产构建。

### 6.2 浏览器验收

一次性检查桌面和移动端：

- 四张失败卡片不再出现原因码和长键名堆叠；
- 指标名称、`--`、失败摘要和详情入口层级清晰；
- 详情抽屉仍能看到完整诊断信息；
- 桌面四列、中屏两列、手机单列均无横向溢出；
- 鼠标、键盘焦点和屏幕阅读器名称均能表达当前状态和操作。

## 7. 文档影响

本任务不改变稳定架构和数据链路，因此不更新 `PROJECT_GUIDE.md`。实现完成后更新 `PROJECT_STATUS.md` 中“指标计算详情”的展示状态，明确失败技术信息已从卡片收敛到详情抽屉；数据新鲜度问题仍作为后续独立任务处理。
