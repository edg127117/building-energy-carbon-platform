# HVAC 统一真实历史趋势设计

> **文档状态：历史任务设计记录**
>
> 本文保留任务当时确认的设计、假设和取舍，部分内容可能已被后续提交替代。
> 判断当前状态前，请先查看[历史任务目录](../README.md)、
> [项目状态](../../../PROJECT_STATUS.md)、当前代码与测试。

> 状态：已确认并完成书面复核。本设计在同一历史趋势模块中接入四项能效指标和 19 个冻结原始测点，不包含 WebSocket 或后台管理页面。

## 1. 背景与目标

当前 HVAC 页面已经接入真实建筑、最新 19 测点快照、四项最新指标和计算详情，但“能效运行趋势”仍是占位内容。后端现有两个历史查询能力：

- 单指标精确历史：返回每个成功分钟的指标值、质量和公式版本，主要服务审计与精确分钟追溯；
- 多测点历史：一次查询 1 至 8 个测点，并按查询跨度自动返回 1、5 或 30 分钟分辨率。

本任务建立一个面向运行人员的统一真实历史趋势模块：默认展示四项能效指标最近 24 小时趋势，并允许切换到 19 个冻结原始测点中选择 1 至 8 项进行对比。页面只展示后端事实，不生成随机历史、不在浏览器计算指标、不用前端降采样掩盖后端数据量问题。

## 2. 已选方案与备选方案

### 2.1 已选方案：统一趋势模块 + 指标图表专用接口

页面使用同一个历史区域、时间工具栏和图表组件，内部提供“能效指标”和“原始测点”两种模式：

- 能效指标模式调用新增的批量指标趋势接口；
- 原始测点模式调用现有多测点历史接口；
- 两类响应在前端适配为统一图表模型；
- 图表按工程单位分组，避免不同量纲共用纵轴。

新增指标趋势接口只服务图表查询。现有单指标精确历史接口保持原语义，不修改、不删除，继续承担分钟审计、公式版本和未来精确明细查询。

### 2.2 未采用：只接四项指标

该方案改动最少，但后续接入原始测点时会重复开发时间选择、图表生命周期、错误状态和响应式布局，不符合当前后端能力已经具备的事实。

### 2.3 未采用：直接让前端并行调用四次精确历史接口

24 小时内可运行，但 31 天最多返回约 17.8 万条分钟记录；同时精确接口一次只能查询一个指标，会产生四次请求。浏览器端压缩仍然需要先下载全部数据，不能解决查询和传输成本。

### 2.4 未采用：修改精确历史接口直接返回聚合值

精确历史包含真实分钟、质量和公式版本，是审计契约。将其改为 5 或 30 分钟平均值会使时间点不再代表真实计算分钟，公式版本也可能在一个窗口内发生变化，容易破坏现有调用方和审计语义。

## 3. 范围

### 3.1 本任务包含

- 新增建筑范围内的批量指标趋势查询 API。
- 指标趋势按跨度自动选择 1、5、30 分钟分辨率。
- 1 分钟分辨率直接返回真实成功分钟；5、30 分钟分辨率返回窗口统计。
- 趋势窗口返回平均值、最小值、最大值、成功样本数和最差数据质量。
- 新增前端历史 DTO、API、领域适配、状态编排和 ECharts 图表组件。
- 默认自动加载当前建筑四项能效指标最近 24 小时趋势。
- 支持最近 1 小时、6 小时、24 小时、7 天和最多 31 天自定义范围。
- 原始测点模式从 19 个冻结测点中选择 1 至 8 项。
- 原始测点首次进入不默认选择；用户选择后按建筑记住，下次恢复仍有效的选择。
- 不同单位自动分组为独立图表，同单位序列允许对比。
- 展示加载、空数据、部分序列无数据、请求失败、数据质量和手动重试状态。
- 切换建筑、模式、时间范围和测点时隔离迟到响应，禁止跨建筑或跨条件混显。
- 更新项目状态、自动化测试和真实 Docker 浏览器验收。

### 3.2 本任务不包含

- 不修改公式算法、公式版本或计算详情契约。
- 不在趋势聚合点中伪造公式版本。
- 不把失败分钟转换为成功值；失败分钟在成功趋势中表现为缺口。
- 不新增失败原因历史图、异常审计表格或分钟审计页面。
- 不允许一次选择超过 8 个原始测点。
- 不同时绘制全部 19 个原始测点。
- 不接入 `/ws/hvac`，历史查询不加入现有 30 秒实时轮询。
- 不开发用户、角色、建筑、设备、测点、数据质量或典型值后台管理页面。
- 不增加历史导出、报表打印、告警、预测、基准线或移动端专项重构。
- 不修改 MySQL 或 TDengine 表结构。

## 4. 用户与主要任务

### 4.1 使用者

主要使用者是建筑业主、能效管理员和平台管理员。他们进入 HVAC 大屏时，需要先判断四项能效在最近一段时间是否稳定，再按需查看温度、流量、功率、压力等原始测点之间的关系。

### 4.2 成功标准

- 首次进入页面无需配置即可看到四项指标最近 24 小时真实趋势。
- 用户可以在同一位置切换到原始测点，选择 1 至 8 项进行对比。
- 不同单位不会被压到同一纵轴产生视觉误导。
- Q1/Q2 数据不会被当成普通实测值静默展示。
- 数据缺口保持断线，不连接成连续趋势。
- 7 天和 31 天查询的数据量受后端降采样控制。
- 权限、非法选择和 TDengine 故障均有明确状态，不用模拟数据兜底。

## 5. 总体数据流

```text
HvacDemoPage 历史区域
  ├─ 能效指标模式
  │    → useHvacHistoryTrends
  │    → GET /hvac/buildings/{buildingId}/indicators/trends
  │    → HvacIndicatorQueryService 权限与指标范围校验
  │    → IndicatorMinuteRepository 批量读取 TDengine 成功指标表
  │    → 1/5/30 分钟图表 DTO
  │
  └─ 原始测点模式
       → useHvacHistoryTrends
       → GET /hvac/buildings/{buildingId}/history
       → HvacQueryService 权限与测点范围校验
       → HvacMinuteRepository 批量读取 TDengine 分钟表
       → 现有 1/5/30 分钟历史 DTO

两类响应
  → 前端历史领域适配层
  → 补齐时间轴缺口并按单位分组
  → HvacTrendChart
  → ECharts 真实历史曲线
```

## 6. 指标趋势后端设计

### 6.1 新接口

```http
GET /api/hvac/buildings/{buildingId}/indicators/trends
    ?indicatorIds={id1,id2,id3,id4}
    &from={unixMillis}
    &to={unixMillis}
```

前端统一 HTTP 客户端已经包含 `/api` 基地址，因此前端 API 文件使用 `/hvac/buildings/...`，不得再次拼接 `/api`。

接口权限与现有 HVAC 查询一致：

- `BUILDING_OWNER`
- `ENERGY_MANAGER`
- `PLATFORM_ADMIN`

Controller 角色白名单不能替代 Service 的建筑数据范围校验。

### 6.2 请求规则

- `indicatorIds` 为逗号分隔的指标实例 ID。
- 去空白、去重并保留第一次出现顺序。
- 必须选择 1 至 4 个指标。
- 所有指标必须存在、启用并属于路径中的建筑。
- 任一指标非法时整批返回统一 `400`，不泄露其他建筑是否存在该 ID。
- 时间范围采用半开区间 `[from,to)`。
- `from`、`to` 必填，`from < to`，最大跨度 31 天。
- 极端时间戳相减溢出返回 `400`。

### 6.3 自动分辨率

与现有原始测点历史保持一致：

| 查询跨度 | `resolutionMinutes` | 含义 |
|---|---:|---|
| 小于等于 24 小时 | 1 | 直接返回每个成功指标分钟，不进行二次平均 |
| 大于 24 小时且小于等于 7 天 | 5 | 5 分钟窗口统计 |
| 大于 7 天且小于等于 31 天 | 30 | 30 分钟窗口统计 |

分辨率由 Service 根据跨度决定，调用方不能传入任意 TDengine `INTERVAL` 字符串。Repository 仍对白名单 `1/5/30` 做防御性校验。

### 6.4 趋势聚合语义

指标分钟结果每分钟最多一条，因此 5/30 分钟窗口采用：

- `average`：窗口内成功指标值的算术平均值；
- `minimum`：窗口内成功指标值最小值；
- `maximum`：窗口内成功指标值最大值；
- `sampleCount`：窗口内成功指标分钟数量；
- `dataQuality`：窗口内最差质量，即 `MAX(data_quality)`；
- `time`：TDengine `_wstart`，表示窗口起点。

失败结果存储在独立异常表，不参与成功值聚合。某个窗口没有成功结果时不生成趋势点；前端按时间网格补空并断开曲线，不能跨越缺口连线。

趋势点不返回 `formulaVersion`：一个 5/30 分钟窗口可能包含多个版本，选择其中一个会产生错误审计含义。精确公式版本继续通过现有精确历史或计算详情查询。

### 6.5 响应契约

```json
{
  "buildingId": "BLD001",
  "from": 1785859200000,
  "to": 1785945600000,
  "resolutionMinutes": 1,
  "series": [
    {
      "indicatorId": "INDICATOR_WCR_COP_B1",
      "indicatorCode": "WCR_COP",
      "equipId": "EQUIP_WCR_B1",
      "records": [
        {
          "time": 1785859200000,
          "average": 5.81,
          "minimum": 5.81,
          "maximum": 5.81,
          "sampleCount": 1,
          "dataQuality": 0
        }
      ]
    }
  ]
}
```

系列按请求 ID 首次出现顺序返回，记录按时间升序。合法指标无数据时仍返回空 `records`，使前端保留固定指标槽位。

### 6.6 职责边界

- `HvacIndicatorController`：接收参数、权限入口、调用 Service、返回 DTO。
- `HvacIndicatorQueryService`：建筑权限、指标清理与归属校验、时间校验、分辨率选择和稳定响应顺序。
- `IndicatorMinuteRepository`：新增批量趋势读取接口，只访问 TDengine，不承担权限和业务选择。
- `TdengineIndicatorMinuteRepository`：1 分钟走精确成功行；5/30 分钟使用按 `indicator_id` 分区的 `INTERVAL` 查询。
- 新增专用趋势读取模型，不能把聚合窗口伪装成 `IndicatorMinuteResult`，因为后者明确代表精确公式分钟和版本。

现有 `findHistory(indicatorId, from, to)` 保持不变，防止图表优化影响审计和数据质量重算相关调用。

### 6.7 错误语义

| HTTP | 场景 | 前端处理 |
|---|---|---|
| `400` | 缺参、非法时间、超过 31 天、指标数量非法或指标不属于建筑 | 保留用户选择，显示后端脱敏文案 |
| `401` | 登录失效 | 沿用全局客户端清理会话并跳转登录 |
| `403` | 当前用户无建筑权限 | 显示无权查看该建筑历史 |
| `404` | 建筑不存在 | 提示刷新建筑列表 |
| `503` | TDengine/JDBC 暂不可用 | 保留上次成功趋势并标为过期，提供重试 |

## 7. 原始测点历史设计

### 7.1 复用现有接口

```http
GET /api/hvac/buildings/{buildingId}/history
    ?pointIds={id1,...,id8}
    &from={unixMillis}
    &to={unixMillis}
```

本任务不修改其 1 至 8 项限制、31 天范围、自动分辨率、权限或 DTO。前端只能从当前建筑快照中与 19 个冻结定义匹配成功的测点生成选择项，不接受用户手工输入内部 ID。

### 7.2 选择记忆

- 第一次进入原始测点模式时不默认选择，显示“请选择 1～8 个测点查看历史趋势”。
- 用户完成选择后立即查询，并按建筑保存所选 ID 的顺序。
- 建议存储键：`hvac:history-point-ids:{buildingId}`。
- 再次进入同一建筑时，只恢复仍存在、在线并属于 19 个冻结槽位的 ID。
- 恢复结果超过 8 项时只保留前 8 项。
- 恢复结果为空时保持空选择，不退回系统武断默认值。
- 切换建筑后不能短暂显示原建筑选择或趋势。

## 8. 前端架构

### 8.1 DTO 与 API 层

在 `web/src/types/hvac.ts` 增加：

- 指标趋势响应、系列和记录类型；
- 原始测点历史响应、系列和记录类型；
- 公共历史状态联合类型只在确有复用时定义，不把颜色、图标或布局写进 API DTO。

在 `web/src/api/hvac.ts` 增加：

- `getHvacIndicatorTrends(buildingId, indicatorIds, from, to)`；
- `getHvacPointHistory(buildingId, pointIds, from, to)`。

数组由 API 层稳定序列化为逗号分隔参数，ID 和路径建筑均使用安全编码。请求经过现有统一 JWT 和错误处理。

### 8.2 领域适配层

新增独立历史领域文件，负责把两类响应转换为统一图表模型：

```ts
type HvacTrendPoint = {
  time: number
  average: number | null
  minimum: number | null
  maximum: number | null
  sampleCount: number
  dataQuality: number | null
}

type HvacTrendSeries = {
  id: string
  code: string
  label: string
  unit: string
  precision: number
  points: HvacTrendPoint[]
}

type HvacTrendGroup = {
  unit: string
  series: HvacTrendSeries[]
}
```

适配职责：

- 指标名称、单位和精度来自现有 `INDICATOR_DEFINITIONS`；
- 原始测点名称和单位优先使用后端响应，冻结定义提供稳定显示顺序与精度；
- 使用响应的 `from/to` 固定时间轴边界，并以 `resolutionMinutes` 判断相邻记录间是否存在缺桶；
- 相邻记录间距大于一个分辨率时插入空分隔点，ECharts 使用 `connectNulls: false`，避免跨缺口连线；
- 按单位分组，空单位使用“无量纲”标题，但数值后不显示伪单位；
- 未知质量保留原数值并显示“未知质量”，不能降级成 Q0；
- 不在此层重新平均、插值或补齐业务值。

### 8.3 状态编排

新增 `useHvacHistoryTrends`，负责：

- 当前模式：`indicators | points`；
- 默认最近 24 小时时间范围；
- 1 小时、6 小时、24 小时、7 天和自定义范围；
- 当前建筑的指标实例 ID 和原始测点选项；
- 原始测点选择恢复和持久化；
- 加载、错误、上次成功时间、当前响应和图表组；
- 打开页面后的指标趋势首次加载；
- 模式、范围、测点选择变化后的查询；
- 手动“刷新趋势”；
- 请求版本号隔离迟到响应；
- 切换建筑时立即清除旧趋势、错误和选择，再恢复新建筑选择；
- 页面卸载时使在途请求失效。

历史趋势不加入现有 30 秒轮询。实时快照轮询继续独立工作；历史只在首次加载、用户改变条件或手动刷新时查询，避免持续扫描 TDengine。

如果刷新失败且当前条件与上次成功条件一致，可以保留上次成功曲线并显示“趋势刷新失败，当前显示上次结果”；切换建筑、模式、范围或选择后失败时不得保留不匹配的旧曲线。

### 8.4 图表组件

新增 `HvacTrendChart.vue`，使用现有 `echarts` 依赖的模块化入口，按需注册折线图、坐标轴、Tooltip、DataZoom 和 CanvasRenderer，不新增图表库。系列图例使用画布外的响应式 DOM 列表，不占用 ECharts 坐标系顶部空间。

组件职责：

- 接收一个同单位 `HvacTrendGroup`；
- 一个单位对应一个独立纵轴和图表；
- 同单位多序列使用稳定颜色区分；
- Q0 默认不显示点标记，Q1/Q2 在对应位置显示可辨识标记；
- Tooltip 展示时间、平均值、最小值、最大值、样本数和质量；
- 缺口断线，不跨越无成功数据的时间段；
- 支持 Tooltip、画布外系列图例和横向 DataZoom；
- 容器尺寸变化时通过 `ResizeObserver` 调用 `resize()`；
- Props 更新时替换图表数据；
- 卸载时释放 ECharts 实例和观察器。

图表组件不发请求、不访问 localStorage、不判断建筑权限，也不计算业务指标。

系列图例必须位于 Canvas 之外，并与 ECharts `color` 数组使用同一稳定色板。每个图例项是可操作按钮，保持 ECharts 原生图例的独立显隐能力；同单位多序列允许只保留任意一条曲线，也允许恢复全部曲线。按钮以 `aria-pressed` 和明确的可见/隐藏样式同步当前状态。

纵轴单位必须使用独立 DOM 行显示为“纵轴单位：{单位}”，位于图例与 Canvas 之间；ECharts 坐标系不再绘制 `yAxis.name`。图例行、单位行和 Canvas 各自占据正常文档流空间，窄容器下图例允许换行，从结构上避免名称、单位、坐标标签和折线画布相互遮盖；不能用隐藏单位掩盖布局问题。

## 9. 页面交互与布局

### 9.1 历史区域层级

现有“能效运行趋势”占位区域改为“历史运行趋势”，保留在当前页面底部业务区域，不改顶部、拓扑、指标卡、公式目录和计算详情交互。

历史区域从上到下为：

1. 模式切换：能效指标 / 原始测点；
2. 时间快捷项：1 小时 / 6 小时 / 24 小时 / 7 天 / 自定义；
3. 原始测点模式专属的多选框和“已选 X/8”；
4. 分辨率、查询区间和最近刷新时间摘要；
5. 曲线数量与单位图表数量摘要；
6. 按单位分组的图表；
7. 加载、无数据、部分无数据、错误和重试状态。

默认进入“能效指标”，选择“最近 24 小时”，自动查询当前建筑可用的四项指标实例。

### 9.2 单位分组

四项指标形成三个单位组：

- COP：无量纲，单独图表；
- 冷却塔效率和水泵效率：`%`，同图对比；
- 风系统耗功值：`W/(m³·h)`，单独图表。

指标模式必须明确显示“4 项指标 · 3 个单位图表 · 同单位合并对比”，避免用户把三个单位容器误解为缺少一项指标。每个单位图表继续显示本组实际曲线名称；`%` 图的画布外图例同时列出冷却塔效率和水泵效率，并可分别隐藏，使图中只保留其中一条曲线。

原始测点按后端单位分组，例如温度、流量、功率、压力、效率分别显示。最多 8 项选择可能产生多个单位组，图表区域按纵向排列；桌面保持足够宽度，窄屏改为单列，不把多个工程单位压进双纵轴。

### 9.3 自定义时间

- 使用本地时区选择开始和结束时间，发送 Unix 毫秒。
- 前端即时校验缺失、逆序和超过 31 天；后端仍重复校验。
- 查询区间语义固定为 `[from,to)`。
- 快捷范围以用户触发查询时的当前整分钟作为 `to`，向前计算 `from`。
- 7 天和自定义范围在两种模式中均可使用，因为新增指标趋势接口也具备降采样。

### 9.4 空状态和部分数据

- 原始测点未选择：提示选择 1～8 项，不发送请求。
- 当前建筑没有可用指标实例：显示“当前建筑暂无可查询的能效指标”。
- 全部系列为空：显示所选范围内无成功历史数据。
- 部分系列为空：保留其图例和空状态说明，其他系列正常绘制。
- 趋势只包含成功指标值；失败分钟造成的缺口不能被描述成 0。
- 503 或网络失败不能切换到模拟数据。

### 9.5 可访问性与视觉边界

- 模式、时间范围、测点选择和刷新均可通过键盘操作。
- 当前模式、当前范围、加载和错误不能只靠颜色表达。
- 图表提供可读标题、单位和文字摘要；Canvas 本身不是唯一信息来源。
- 沿用当前深色 HVAC 大屏视觉、间距和色彩，不进行整体视觉重做。
- 动画保持轻量，尊重 `prefers-reduced-motion`，不增加装饰性持续动画。
