# 当前文档状态防回退整改设计

> **文档状态：历史任务设计记录**
>
> 本文记录 2026-08-12 确认的整改范围、约束和验收标准。正文属于任务设计快照，
> 不用于判断当前实现；当前状态应核对[历史任务目录](../README.md)、
> [项目状态](../../../PROJECT_STATUS.md)、当前代码与测试。

## 1. 问题与证据

当前文档分层已经规定：`PROJECT_STATUS.md` 维护动态完成状态，设计冻结书维护稳定范围，
`docs/superpowers/specs` 和 `plans` 只保存历史任务记录。但仓库仍有三类防回退缺口：

1. `docs/设计冻结书-V1.0-19测点.md` 第十一章自称与当前代码一致，却仍把已经完成的
   最小后台、标准多字段 MQTT、WebSocket、计算详情和历史趋势描述为未完成。
2. 基线中的 87 份历史设计和计划里，有 33 份缺少统一历史状态块；其中 17 份计划
   保留合计 516 个未勾选框，单独打开时容易被误解为当前待办。
3. Repository Guardrails 检查 PR 结构和注释风险，但不检查历史文档状态块，也不要求
   PR 明确说明是否同步了动态项目状态。

这不是业务实现缺失，而是当前文档重复维护动态状态、历史文件入口契约未自动检查、
PR 缺少文档同步证据共同造成的治理回退。

## 2. 目标与非目标

### 2.1 目标

- `PROJECT_STATUS.md` 成为唯一动态项目状态入口。
- 设计冻结书只保存稳定范围、公式、测点和安全边界，不再复制当前完成表。
- 每份历史设计和计划在文件顶部都能独立说明其历史性质和当前状态入口。
- Repository Guardrails 自动拒绝缺少历史状态块的新建或修改历史文档。
- 每个 PR 都必须说明状态影响、检查范围和文档同步结论。

### 2.2 非目标

- 不改写历史设计和计划正文，不回填复选框，不把历史步骤伪装成执行记录。
- 不修改 Java、Vue、TypeScript 业务行为，也不重跑无关后端和前端业务测试。
- 不尝试仅靠关键词自动判断某项业务是否真正实现；最终语义仍由代码、测试和人工复核确认。
- 不把本机容器、端口、数据库数据或现场验收状态写入项目文档。

## 3. 方案比较

### 3.1 仅修正当前错误文档

只更新设计冻结书和缺失警告的历史文件。改动最小，但下一份新设计或计划仍可能漏掉警告，
功能 PR 也可能再次忘记同步 `PROJECT_STATUS.md`，不能解决复发问题。

### 3.2 文档修正与结构化 Guardrail（采用）

修正存量文档，同时扩展现有 PowerShell Guardrail、自动化测试和 PR 模板。结构性事实由 CI
强制，业务语义通过 PR 的“文档同步”证据人工复核。该方案复用现有工程流程，改动集中，
不引入新工具或重复 CI。

### 3.3 自动从代码生成能力清单

根据 Controller、路由和组件生成能力表。代码存在不等于功能验收完成，也无法可靠表达现场、
权限、跨层闭环和外部资源边界，容易产生新的无证据完成声明，因此不采用。

## 4. 文档分层整改

### 4.1 设计冻结书

将第十一章改为“能力边界与当前状态入口”：

- 删除动态的“当前状态/证据边界”表；
- 保留 V1 已冻结的业务范围与不包含的控制边界；
- 明确动态完成状态只查看 `PROJECT_STATUS.md`；
- 第十二章历史排期和附录继续保留，不作为当前待办。

### 4.2 历史设计与计划

对 `docs/superpowers/specs/*.md` 和 `docs/superpowers/plans/*.md` 使用统一文件头契约：

- 设计：`文档状态：历史任务设计记录`；
- 计划：`文档状态：历史任务实施计划`；
- 说明正文保存任务当时的假设、步骤和取舍；
- 说明计划复选框不代表当前完成状态；
- 链接 `docs/superpowers/README.md` 和 `PROJECT_STATUS.md`。

本次只在缺失契约的文件顶部增加状态块，不改写历史正文。整改完成后，中央目录和项目状态中
“每份历史文件都有状态警告”的表述才重新成为可验证事实。

### 4.3 当前状态文件

`PROJECT_STATUS.md` 继续记录已完成、未完成、风险、技术债和下一步。本次只修正文档健康描述，
不改变已经由代码核验的业务完成状态，也不把缺少现场证据的事项标记为完成。

## 5. Repository Guardrails 扩展

### 5.1 历史文档契约检查

在 `scripts/Test-RepositoryGuardrails.ps1` 中增加独立检查：

- 枚举当前 Git 版本中的全部 `docs/superpowers/specs/*.md` 和 `plans/*.md`；
- 设计和计划必须分别包含正确的历史状态标识；
- 文件顶部必须包含历史目录和项目状态链接；
- 缺失时输出稳定错误码和具体相对路径；
- 检查完整历史目录，而不是只检查本次差异，避免已有缺口被永久放过。

建议错误码：

- `HISTORICAL_DOC_STATUS_MISSING`
- `HISTORICAL_DOC_INDEX_LINK_MISSING`
- `HISTORICAL_DOC_CURRENT_STATUS_LINK_MISSING`

### 5.2 PR 文档同步契约

PR 模板增加 `文档同步` 章节，并要求三个字段：

- `状态影响`：填写“有”或“无”；
- `检查范围`：列出核对的当前文档和相关代码/测试入口；
- `结论`：说明更新了哪些当前文档，或为何无需更新。

Guardrail 只验证结构、允许值和非空内容，不根据关键词猜测业务完成状态。缺失或无效时使用稳定
错误码，文档流程同时补充对应故障说明。

## 6. 测试设计

扩展 `scripts/tests/Invoke-RepositoryGuardrailTests.ps1`，覆盖：

1. 完整状态块的历史设计和计划通过；
2. 缺设计状态、缺计划状态、缺历史目录链接、缺项目状态链接分别失败；
3. PR 缺少“文档同步”章节失败；
4. `状态影响` 缺失或不是“有/无”失败；
5. `检查范围` 或 `结论` 为空失败；
6. LF、CRLF 和 CR 三种换行继续正确解析；
7. 现有禁止路径、生产文件注释和高置信度注释检查不回退。

验证命令包括 PowerShell 解析、Repository Guardrail 测试、当前仓库本地 Guardrail、
Markdown 相对链接检查和 `git diff --check`。业务代码未变化，因此不运行 Maven、Vitest、lint、
类型检查或前端构建。

## 7. 交付范围

本任务允许修改：

- 设计冻结书、`PROJECT_GUIDE.md`、`PROJECT_STATUS.md`、历史任务中央目录；
- 缺失标准状态块的历史设计和计划；
- PR 模板、Repository Guardrail 脚本及其测试；
- 开发流程说明；
- 本设计及对应实施计划。

不修改生产 Java/Vue/TypeScript、配置、数据库、MQTT、WebSocket 或运行环境。

## 8. 验收标准

- 全部历史设计和计划满足统一文件头契约。
- 设计冻结书不再维护动态能力完成表。
- 当前有效文档不存在本次已确认的“代码已实现但仍写未实现”冲突。
- 缺失历史状态块的测试夹具会被 Guardrail 拒绝。
- 缺失或空白的 PR“文档同步”证据会被 Guardrail 拒绝。
- Repository Guardrail 全部自动化测试、本地检查、链接检查和 `git diff --check` 通过。
- PR 如实记录未执行的业务测试及原因，不把文档检查表述为现场或端到端验收。
