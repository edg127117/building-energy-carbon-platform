## 1. 交付边界与最终行为

复用既有能源分类、有效计量边界、总分表去重、电量汇总、身份/别名、MQTT入口、V2适配器、任务与大屏轮询。上游上传同一计量时段的用电量和CO₂因子，平台计算 `C=Σ(Q×f)`，汇总因子为 `F=C/ΣQ`；分子、分母使用同一批有效电量。没有区域发电量依赖。

```mermaid

    A[电表电量与因子] --> B[既有MQTT与适配器]
    B --> C[身份与时段解析]
    C --> D[输入、版本、回执、待算任务同事务]
    D --> E[受影响建筑和时段重算]
    E --> F[小时、日、月、年查询]
    F --> G[大屏月图与年图自动更新]
```

- 普通自动周期输入复用设备结束时间推导前15分钟，平台分配业务版本，不强制新增bootId、序号或设备修订号。仍须能确定真实计量时段，不能用接收时间猜测历史归属。显式时段/修订及既有兼容路径保留。
- 同值不重复计量、不增加数值版本；不同有效值按已确认的最后成功受理规则自动更正，仅重算受影响时段。可识别原消息在去重窗口内重投，不撤销后续更正。
- 正常V2首报及同值上报复用现有回执，不再额外写区间LIGHT标记。正常周期成功回执从首次持久化保留7天，重投不续期；旧V2标记核对自包含数值和引用后分批清理。
- 更正/冲突完整正文沿用至少180天及引用保护。仍被当前值、未完成任务或历史计算引用的正文保留。业务历史不是只留7天；正常首报减少的是额外标记，不是业务输入或计算结果。
- 回执和热快照清理后，旧消息按新受理事件处理：同值不重算，异值可能重新采用。缺少来源新旧依据时，不能保证识别设备真正最新版；这是已确认的自动取值边界。
- 动态监测单位为 `kgCO₂/kWh`、`tCO₂`；正式核算与其他卡片原有口径保持。无新增配置页、人工更正/核查流程、发电侧因子生成系统或大屏常驻信息，不改正式能源审核规则。

详细契约及数据准备入口见[动态用电监测](dynamic-electricity-monitoring.md)。
