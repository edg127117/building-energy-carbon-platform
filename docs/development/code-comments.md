# IoT 生产代码注释专项规则

通用注释质量由个人全局 `code-comment-quality` Skill 负责；本文件只补充 iot-platform-demo 的业务边界。修改或审查 Java、Vue、TypeScript 生产代码时，两者同时适用。

## 必须优先说明的内容

- 数据属于哪个建筑、设备或测点，以及越权和缺失身份如何处理；
- 数据来自 MySQL、TDengine、Redis、MQTT、WebSocket 还是外部系统；
- 温度、流量、功率、能耗、COP 等量纲、单位、精度和缺失值语义；
- 事件时间、接收时间、整分钟窗口、时区、迟到数据和回退规则；
- 事务、并发、幂等、重试、补偿、缓存失效和失败副作用；
- 后端字段、DTO、接口与前端类型、映射、展示之间的跨层契约；
- 测试替身、演示数据和真实外部资源之间的边界。

注释应解释代码不能直接表达的约束和原因。不要逐行翻译、复述方法名、记录任务历史、保留失效 TODO，或把规划中的控制和自动化能力写成已经实现。

## 风险分级

- **高风险**：权限、数据归属、状态、事务、并发、重试/补偿、多数据源、MQTT、WebSocket、外部资源、公式、聚合、时间语义或跨层契约。检查完整变化文件及相关调用链，并修正受影响的过期注释。
- **普通风险**：局部业务逻辑、DTO 映射、页面状态或错误处理。检查变化及受影响的方法、组件和相邻契约。
- **低风险**：纯注释、拼写、等价重命名或格式。检查变化附近是否出现过期、误导、重复或低价值注释。

PR 的“注释检查”必须填写风险级别、检查范围和结论。普通生产代码 PR 不再强制新增永久审计报告；需要专项全量审计时，可按 [`repository-guardrails.md`](repository-guardrails.md) 手工生成报告。
