# 报警信息独立模块与 B 版接线

报警模块处于活动候选阶段，修正后的本机前后端全量回归已通过。原始模块冻结提交由统一候选整合。B 版在原报警位置读取同一建筑，规则及事件链接使用既有菜单授权。正式月配额、年度评价期计划配额、月与年内累计强度、月环比及同比复用正式服务。后台使用已配置的同建筑读取身份并重查角色和授权。基线、完整性和年末预测缺少确认依据时显示不可用。统一候选及服务器验收另行记录。

## B 版统筹接线清单

| 顺序 | 接线项 | 统筹交付内容 |
| --- | --- | --- |
| 1 | 报警模块与数据库 | 纳入后端、前端及报警迁移。在统筹候选和目标库的 Flyway 历史中核对 V110 的编号与校验和。如目标库已执行同号迁移或已有旧报警表，按实际库状态分配新编号或增量迁移，并同步迁移契约测试。保留已执行脚本和历史数据。[报警迁移](../../src/env/init/V110__mysql_alarm_information.sql) |
| 2 | 设备侧事实 | 复用已生效采集策略、TDengine 原始数据和正式冻结分钟。沿用大金故障适配，其他已确认协议通过 `AlarmFaultSource` 提供设备身份、建筑归属、故障与正常事实。 |
| 3 | 排放侧事实 | 用生效年度计划和正式核算结果实现唯一的 `MonthlyQuotaSource`。按模板接入 `AlarmEmissionSource`，每个启用模板匹配唯一来源，按需提供面积、模型及核算完整性证据。 |
| 4 | 大屏与权限 | 把 `ScreenAlarmSummary` 放到 B 版原报警卡位，传入当前建筑 ID。接通三个既有报警菜单，核对建筑授权和只读来源执行身份。 |
| 5 | 独立测试端 | 在隔离实例接通采集、MySQL、TDengine 与核算测试数据。启用报警调度，按本文验收表确认完整链路。 |

报警候选提供规则、事件、处理、汇总和配置界面。B 版统筹负责接线与集成验收，设备方和能源专业方分别提供协议事实与判定口径。

## 数据与运行边界

- 报警独立持有 `biz_alarm_*` 表。采集配置、TDengine 原始事实、大金故障均只读；不调用控制、核算写入或年度计划变更。
- `alarm.enabled=true` 后启用独立单线程调度，默认 30 秒一轮，单轮最多 100 栋建筑，游标轮转。默认不启用，避免自动改变既有运行行为。配置修改在下一轮判定收敛，停用会立即归档该规则的活动事件。
- 首版默认通信连续缺报 3 周期、配额提醒比例 85%，用于已批准的独立测试方案。通信周期读取已生效采集策略；设备任一实际新鲜测点证明通信，迟到补传、合成质量和未来事件不刷新通信时间。
- 故障读取当前映射下 `VENDOR_EQUIPMENT` / `VENDOR_COMMUNICATION` 活动设备事件。来源级失败不展开为全部设备故障。已有大金当前/历史异常页仍能展开查看其他异常。
- 同设备多事件按通信、质量、数值、故障顺序归为一台。维护屏蔽作用于该设备全部活动事件，新事件继承尚未到期的屏蔽；到期自动恢复可见，确认记录保留。
- 后台锁定建筑后判定、更新事件与审计，多实例去重。数据来源不可用不会恢复旧事件；超过 120 秒未获得新判定时两个汇总值为 `null`。
- 事件保存首次依据与最新依据、触发规则修订号。修订规则后旧事件归档，仍成立则用新版本重开；重复确认保持原确认人。

## 月度配额接线契约

集成方提供唯一 Spring Bean，实现 `com.platform.alarm.MonthlyQuotaSource`。`load(buildingId, month)` 必须复用已集成年度计划服务及正式核算查询，返回 `AlarmModels.Quota`。

| 字段 | 要求 |
| --- | --- |
| buildingId / month | 调用指定建筑和北京时间自然月，默认最近一个已结束月 |
| actual / quota | 同一核算边界与单位 `tCO2e` 的正式实际值和有效月配额，保持 BigDecimal 精度 |
| planVersion | 生效计划版本，不能引用草稿 |
| batchId / evidenceHash | 当前正式核算批次及证据哈希，排除候选和已被替代结果 |
| unavailableReason | 配额、正式结果或来源不可用的简短原因，成功时为 null |

无接线 Bean 时返回“月度配额数据源尚未接入”，不产生零预警。适配器执行身份沿用统筹任务已批准的后台只读身份和建筑授权，不创建管理员捷径。

当 `actual × 100 >= quota × 提醒比例` 时创建一条预警，`actual > quota` 升级为超配额，仍为同一事件。实际值下修至提醒线以下后恢复。跨月归档前期事件，即使新月结果未出也不沿用前期条数。

事件的 `evidence` 是最新依据，`triggerEvidence` 是首次触发依据。排放依据中 `actual`、`quota`、`ratioPercent` 均用十进制字符串，另含 `month`、`thresholdPercent` 和 `unit`；前端直接显示，不重算比例。设备通信依据包含 `lastCommunicationAt`、`monitoringSince`、`intervalSeconds` 和 `allowedDelaySeconds`。从未收到有效通信时 `lastCommunicationAt` 为 null，超时从监测启用时间起算，不把启用时间伪装成末次通信。

## 旧规则兼容

每栋建筑初始提供通信超时、设备故障和月度配额预警三项规则。配置页另可新建数据质量不达标、通用测点条件规则，按设备类别和空间圈定范围，分别命名、启停并保存不可变版本。

- 通信超时按已生效采集策略的应报周期判断。恢复需满足规则保存的连续正常周期数，重复轮询同一份上报不增加计数，缺报重新计数。既有规则未配置恢复周期时沿用 1，新建界面初始为 2，可修改。
- 质量规则将正式冻结分钟的实际 Q0/Q1/Q2 与本规则场景质量要求比较，Q0 可信度最高。可配置条件连续成立及连续恢复时长，缺数不当作质量合格。
- 旧单层测点条件继续读取同一设备的新鲜 Q0 原始测点值。规则支持“全部满足 / 任一满足”、大小比较、相等或不等及区间判断。阈值使用测点单位。数字状态按设备协议设置编码与中文名称，界面选择中文，执行仍使用原始数值。映射与规则版本一起保存。已有数字规则可在条件行的状态设置入口补齐中文选项。
- 报警域持久化观测游标与连续计时，建筑锁内更新。未知、过期或不对齐的数据中断连续计时并保留现有事件，不能借用重复调度满足持续条件。
- 大屏按通信离线、数据质量不达标、数据合理性异常、设备故障与状态矛盾顺序归类。同设备多事件只计一台，分组加总等于设备总数。通用条件可选择归到数值类或故障状态类。

## 八项扩展的交付边界

本节描述已批准的活动候选扩展，独立开发及本机模拟验收；不代表服务器发布或正式基线。配置仍保存即生效，不增加审批工作流。只写报警域，B版画布、年度配额、核算公式和南向协议由各自模块负责。

| 项目 | 本次实现范围 | 兼容与限制 |
| --- | --- | --- |
| 1. 回差与连续恢复 | 通用条件的触发树与恢复树独立设置；恢复须同时满足配置的正常周期数和持续分钟 | 中间回差区间保留活动事件；重复轮询不推进周期；旧规则没有独立恢复树时沿用原解除条件 |
| 2. 跳变与卡值 | 窗口首末值绝对变化/百分比；运行前置状态相等时检查窗口变化容差 | 缺历史、迟到、坏质量、时间断档不证明连续；百分比基准为零为不可判定；不使用随机补点 |
| 3. 条件树与关联设备 | 最多三级、20个叶子，ALL/ANY嵌套；同建筑跨设备引用，明确主告警设备 | 空间/类别范围作用于主设备；关联点仍须在线且属于本建筑；按主设备去重，不跨建筑、不执行脚本 |
| 4. 采样与质量时序 | 优先每点已APPLIED策略，缺策略用显式应报周期/延迟；配置对齐容差、有效期及场景Q0/Q1/Q2要求 | 原始状态保留数值编码；未知数据中断连续计数并保留既有活动事件；一个规则取数失败不影响其余规则 |
| 5. 排放与模板目录 | 七个内置模板，正式只读来源；后端受控provider可注册有中文参数的数字模板 | 模板目录不等于算法或数据已接入；无正式来源、证据或方法确认时显示不可用；不在前端重算排放 |
| 6. 通用故障来源 | `AlarmFaultSource` 聚合故障事实，保留大金适配器 | 只处理适配器已解析的设备故障事实，不猜厂商位码；通用来源以active=false明确正常覆盖，来源失败保留事件 |
| 7. 运营处理 | 按事件真实测点查原始前后趋势，维护屏蔽时长可选，恢复后允许人工关单 | 趋势单次最多24小时/20点/每点2000样本，截断和来源失败明确提示；活动事件不能直接关单，复发另开事件 |
| 8. 共享状态字典 | 建筑级DIGITAL字典、测点绑定、只增版本、规则冻结快照、显式同步关联规则 | 老规则内嵌states及数字规则继续读取；升级删除正在使用的编码会拒绝并整批回滚，不改写历史事件 |

新增字段 `advanced` 可空，原有规则JSON和旧构造契约保留。新字典和关闭状态存放于报警表；未部署的V110统一包含本次结构，统筹任务集成时核对迁移号和目标库是否已使用该号，不能覆盖已经执行的迁移。

### 排放模板的输入与判定

扩展来源实现 `AlarmEmissionSource`，只读正式结果、计划、有效模型和缺数事实。来源返回指定建筑与期间、观测游标、单位、正式批次/计划/模型版本及证据。内置排放原始量统一为tCO2e，强度为kgCO2e/m²，完整率为%；不匹配的单位由来源完成转换，报警拒绝混用。一个模板命中多个来源时拒绝任意选取。`MONTH`取最近已结束月；`YEAR`取该年起至最近已结束月，年初尚无闭月时为不可用。

| 模板 | 正式输入 | 判定 |
| --- | --- | --- |
| 配额进度 | 同期间排放与有效配额；年度另带年度预算进度证据 | 实际/配额×100与触发、恢复百分比比较；年度累计和年度预算进度不可互相代替 |
| 排放强度 | 来源完成面积及单位换算后的正式强度、面积/计算依据 | 与同单位上限及恢复线比较，不在报警中计算新强度公式 |
| 环比/同比 | 同边界、同单位、可比的两期正式值 | 当前减参照的有符号差值；百分比除正参照值，下降不当作增长报警 |
| 基线偏差 | 正式实际值、指定生效基线模型及结果 | 有符号超出量或百分比，模型缺失不回退任意历史均值 |
| 核算完整性 | 正式完整率、已确认缺点/缺因子事实 | 低于最低完整率或存在已确认缺因子触发；达到恢复线且缺因子解除才恢复；读取失败属于未知 |
| 年末预测 | 已确认年累计值、年度配额、LINEAR_DAY方法确认与模型证据 | 截至闭月累计/已结束天数×全年天数，预测值/年度配额×100；未确认方法不运行 |

自定义算法通过 `AlarmTemplateProvider` 注册目录与实际执行器；目录声明支持期间、单位、中文参数名和专业输入。界面从目录生成数字参数，后台检查必填、数值范围和注册唯一性。只增加目录记录不会自动获得算法。多种模板复用既有排放分组，算法新增事件归类必须属于已有分类。暂不提供任意脚本、自定义SQL、在线训练或自动控制。

### 必须列明的外部输入

- 设备方：状态编码及中文枚举、厂商故障字段/位码及解除方式、实际采样周期与时钟/迟到约定。未提供时可在独立数据中验证通用契约，不能宣称厂商协议已适配。
- 能源专家及核算模块：各模板单位、建筑/面积/排放边界、可比期间、阈值与恢复线、完整率和缺因子口径、生效基线模型、年末预测方法确认。测试参数只证明软件链路。
- B版统筹：正式月配额与扩展 `AlarmEmissionSource` 适配器，正式执行身份与建筑范围，采集/时序/计划/核算模块实际可用性，大屏真实buildingId和刷新/导航接线。

本任务不新增频繁审查或审批；上述输入是判定正确性所需事实，接入时明确提供即可。

## B 版独立测试端验收

使用模拟设备从正常采集入口送入数据，通过数据库和时序查询核对原始数据、冻结分钟及正式测试核算结果。观察后台自动判定，再从报警 API、运营页和 B 版大屏核对同一建筑的结果。配置页用于修改规则、核对版本并验证下一轮判定。用例中的阈值和周期仅为测试样例。

| 场景 | 操作与通过标准 |
| --- | --- |
| 迁移和启动 | 核对迁移历史、报警表结构及旧规则读取。启用 `alarm.enabled=true`，确认自动扫描后汇总更新时间推进。重复扫描或重启后，同一观测保持一个活动事件，连续计数保持一致。 |
| 离线与恢复 | 用模拟设备按策略上报、暂停至缺报门槛、恢复上报。核对补传、未来时间和过期数据的处理。恢复达到配置的连续正常周期才解除，同一份上报重复读取只计一次。 |
| 质量、条件与窗口 | 分别模拟低于所需质量等级、同建筑关联设备条件、跳变和运行中卡值。回差可用触发线 5、恢复线 3 的样例，按 8 → 4 → 2 → 2 分周期送入新观测，依次看到触发、维持、首个恢复周期、第二个连续正常周期后恢复。再验证失联、时间不对齐或历史断档时的未知状态。 |
| 设备故障与来源隔离 | 模拟同建筑且身份匹配的厂商故障和正常恢复事实，核对故障归类与解除。模拟故障来源失败，保留既有事件并显示不可用原因。 |
| 正式排放及缺源 | 为每个拟启用模板准备同建筑、同期间、同单位的正式测试结果，检查触发、恢复、计划和批次证据。覆盖跨月、计划版本替换、缺结果或模型及多来源冲突。检查同口径月配额规则的启用范围，避免同一口径重复计数。 |
| 配置与运营处理 | 对照原型核对图标、颜色、单行条件与中文状态，验证规则保存、版本历史、旧规则兼容、字典绑定与显式升级。用同一事件核对首次依据、趋势、确认、备注、维护屏蔽到期、恢复后关单及复发新事件。 |
| 权限与建筑切换 | 用有权、只读和无权账号分别检查菜单、直接访问 API、规则写入及事件处理。切换建筑时核对卡片、弹窗、列表和趋势，旧请求迟到时仍显示当前建筑。 |
| 三处一致性 | 在 B 版实际画布验证弹窗位置、缩放、刷新、关闭和跳转。大屏设备数按主设备去重并排除维护屏蔽，运营列表可以有同一设备的多条事件。排放按活动事件计数。事件详情的触发版本可追溯到配置页。数据缺失时显示原因和不可用状态，有效零值显示 0。 |
| 既有模块回归 | 核对 B 版既有画布和图表、采集、核算及年度计划的正常路径。检查报警处理写入集中于报警表，来源数据和专业核算结果保持其原有流程。 |

真实设备接入后，单独验收厂商状态码、故障解除语义、采集周期、时钟、丢包补传和长期运行。

本机模拟用例使用 H2、时序存储替身和受控时钟验证报警服务和 HTTP 契约。集成方可复用以下场景和快照。

- `AlarmChainTest`、`AlarmControllerTest` 覆盖缺报与补传、配额、权限、事件处理、事务回滚及 HTTP 契约。
- `AlarmExtendedEvaluationTest`：条件树真/假/未知、跳变/卡值、历史连续性、采样与故障来源隔离。
- `AlarmEmissionExtensionTest`：七模板的正式身份、期间、单位/版本证据、缺源和自定义执行器。
- `AlarmDictionaryTest`、`AlarmEightFeatureContractTest`：字典版本与事务回滚、真实Service及HTTP往返、跨设备触发/回差/恢复、大屏汇总、趋势、维护时长与关单。
- 前端真实页面与条件树用例验证配置保存、共享中文状态、模板目录、独立恢复、历史关单和来源失败；浏览器在隔离画布回放测试产生的接口结果，截图不代表B版整页验收。
- 模拟验收输出 `target/alarm-eight-screen-replay.json` 和 `target/alarm-eight-http-replay.json`；浏览器截图位于 `target/alarm-browser/eight`。这些为本地生成产物，不作为正式业务数据入库。
