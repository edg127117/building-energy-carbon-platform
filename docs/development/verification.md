# 变更验证说明

本文件供开发者快速理解验证原则。Codex 的可执行验证矩阵位于 [`.agents/skills/iot-change-verification/SKILL.md`](../../.agents/skills/iot-change-verification/SKILL.md)，两处不要复制维护完整命令表。

## 基本原则

- 验证范围由当前差异、受影响调用链和风险决定，不由文件数量决定。
- 先运行最接近变化的定向检查，再运行该技术栈要求的完整门禁。
- Java 生产代码通常需要相关测试和完整 Maven 测试。
- Vue/TypeScript 生产代码通常需要相关 Vitest、完整测试、lint、类型检查和构建。
- 字段、接口、权限、状态、时间、单位或跨层契约变化必须同时验证后端和前端。
- 普通自动化测试不得连接真实 MySQL、TDengine、Redis、MQTT Broker、现场设备或第三方服务。
- 纯文档或流程变化只运行直接相关的链接、解析、脚本、Guardrail 和 Git 差异检查，不机械运行无关业务测试。

## 结果记录

提交和 PR 必须如实记录：

1. 实际执行的命令；
2. 已通过和已失败的结果；
3. 跳过或未执行的项目及原因；
4. 自动化未覆盖、仍需人工或专用环境确认的内容。

不得复用历史测试数量，不得把仓库层、接口层或局部测试通过描述为端到端功能已完成。关键门禁失败或未执行时，不得将分支描述为可合并。
