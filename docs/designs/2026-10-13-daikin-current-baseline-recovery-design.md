# 大金旧隔离按现场新基线恢复修订

本修订已获用户批准，仅补齐已超时异常在当前设置不同于旧目标时的恢复路径。它替代原控制设计中这一场景必须恢复旧目标才能解除隔离的限制；原指令不重发、不改目标，也不标记为执行成功。正常控制的身份、建筑范围、动作许可、主从关系、控制器串行、180 秒最短观察及 300 秒期限均保留。

## 恢复条件与结果

- 仅当前有效平台管理员可处理已经发送、超过期限且仍占用设备的 `UNKNOWN`、`UNCONFIRMED` 或已关闭异常。普通控制关闭、旧设备许可撤销时，仍允许这条只读恢复路径。
- 管理员填写现场已确认的开关与整数设温。正式身份、建筑、来源、映射和原主从关系必须保持一致；来源不能正在同步或存在其他控制器占用。
- 每次观察只调用厂家读取接口。全套规范设置和运行状态连续三次一致，间隔至少 30 秒、跨度至少 60 秒，最新证据不足 30 秒，才产生绑定当前管理员、旧操作及正式身份的恢复证明。失败、变化、过大间隔使连续证据失效。普通控制样本不能充当恢复样本。
- 完成操作再次进行只读核验，在事务内复查权限、身份、证明和读租约。最终样本、异常关闭、设备及控制器占用释放和审计一起提交，任一失败全部回滚。
- 结果为 `CLOSED / RECOVERY_CURRENT_BASELINE_RELEASED`，仅表示异常已恢复。原请求值、目标快照、原始基线、幂等信息、厂家结果、旧关闭说明和全部事件保留。新现场基线及恢复理由独立写入审计，不新增成功执行结论。
- 撤销的设备许可不会自动恢复。后续管理员仍通过现有设备开放接口配置许可，不直接改数据库记录。

## 页面与限时窗口

设备控制详情在管理员身份下提供“核验当前基线”和“按已确认基线解除隔离”。观察自动轮询，最多五分钟；切设备或离开页面停止轮询，完成请求不自动重试。普通调温及批量开放流程保持原简化设计。

部署保持三个控制开关关闭。独立单台测试窗口可配置设备 ID 列表和截止时间；列表不授予设备许可，最后五分钟停止接收新控制，已有操作继续回读。窗口的启闭由测试环境运维脚本负责，截止后恢复关闭。当前获准仅开放窗口，真实动作必须另有明确指令。

## 验收边界

完成本机 Java 和前端门禁，以及隔离 MySQL 的迁移链校验、数据库审计失败回滚、独立双进程竞争；验证期间运行库历史、控制表及部署版本保持不变。备份版本、数据库和配置并准备回滚后部署，仅在测试入口验收。真实恢复前重新只读核对现场基线；恢复后核对旧目标未变、占用释放、许可未隐式开放及邻机未变化。恢复验收不代表新的控制动作已经完成现场验收。

不新增或改写迁移，不改变天气、电量分析和监测业务。
