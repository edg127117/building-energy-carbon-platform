# 碳管理基础闭环设计

## 1. 文档状态与确认门

本文记录“碳管理基础闭环”已经讨论确认的后端设计。当前状态为**设计已确认，对应后端活动候选
已实现并完成隔离软件验证，尚未批准为当前正式版本**。

当前实现和隔离验证不代表任何排放因子、专业口径、真实建筑、真实设备或现场数据已经验收，
也不代表生产容量、长期运行或正式碳核算结果已经获批。

本文以当前仓库代码、[`PROJECT_GUIDE.md`](../../PROJECT_GUIDE.md)、
[`PROJECT_STATUS.md`](../../PROJECT_STATUS.md) 和已经合并的第七闭环公开契约为基础。历史 Excel、
会议材料和截图只用于研发流程理解与确定性公式验算，不是正式权威因子库。

## 2. 目标与范围

### 2.1 目标

在第七闭环“多能源活动数据归集、单位归一与折标准煤计算”之上，形成研发阶段最小可用的
后端碳管理软件闭环：

1. 排放因子来源和版本治理；
2. 因子组合版本、审核、生效和停用；
3. 活动数据与因子确定性匹配；
4. 范围一固定燃烧化石燃料计算；
5. 范围二外购电力和外购热力计算；
6. 月度、季度、年度排放量及占比；
7. 年度总排放量、年度单位面积强度和年度单位人数强度；
8. 依赖变化的自动影响识别、持久化重算批次和正式结果批次审批；
9. 活动数据、因子、公式、分母和结果的全链路追溯。

### 2.2 本期包含

- 范围一：固定燃烧化石燃料；
- 范围二：外购电力、外购热力；
- 位置法外购电力因子；
- 建筑级月度、季度和年度计算；
- 研发参考与正式使用性质分离；
- 完整和明确不完整的研发结果；
- 自动发现受影响的历史年度、归并重算任务、计算候选结果和发布经批准的正式结果；
- 权限、职责分离、建筑范围、幂等、并发、审计和超时恢复；
- 后端 API、数据库结构、自动化测试和容量验证。

### 2.3 本期不包含

- 前端、可视化和菜单页面；
- 移动源、范围三；
- 市场法、绿电合同、绿证、自建光伏抵扣、余电上网抵扣和零碳电力声明；
- 位置法与市场法双重报告；
- 余热、蒸汽、热水温差、焓值和复杂热量换算；
- 碳评价、等级、基准线、预算、配额、交易、诊断、归因和减排建议；
- 碳移除、负排放、抵扣和净排放；
- 园区、组织或多建筑合并核算结果；
- Excel 批量导入；
- RabbitMQ、Kafka 等外部消息队列和外部因子服务；
- 远程控制和指令下发。

自动重算批次可以包含多个相互独立的“建筑 × 核算年度”计算项，仅用于任务归并和批次审批，
不产生园区、组织或多建筑合并排放结果。

## 3. 上游依赖与公开输入契约

### 3.1 依赖原则

碳模块只消费第七闭环稳定、公开、可测试的周期结果和计量边界汇总契约：

- 禁止读取第七闭环内部表、Repository 或 Mapper；
- 禁止扫描 TDengine 全年原始时序数据；
- 禁止复制活动量聚合、去重、质量门禁、封账或计量边界逻辑；
- 禁止使用 `tce` 计算二氧化碳当量；
- `tce` 只能作为并列能源折算证据保留，不进入碳排公式。

### 3.2 碳活动量输入端口

在第七闭环公开边界增加 `CarbonActivityInputPort`。端口由能源计量边界汇总模块适配，碳模块
只依赖端口模型。端口至少返回：

- 建筑标识；
- 周期类型、半开时间区间和时区；
- 能源品种、使用范围和流向；
- 权威活动量、原始单位、归一单位和单位版本；
- 周期快照标识及证据摘要；
- 计量关系版本、汇总口径版本和折标版本；
- 质量策略版本、覆盖率、锁定状态、例外和活动水位；
- `DEVELOPMENT_SIMULATION` 或 `FORMAL` 结果性质。

端口必须隐藏 MySQL 和 TDengine 表结构。碳模块不得通过 HTTP 回调本应用自身；单体内通过稳定
Java 端口协作。

### 3.3 周期输入

底层统一保存：

- `MONTH`；
- `QUARTER`；
- `YEAR`。

年度计算按活动数据实际可追溯周期分段，不强制把所有数据拆成月度：

- 月度快照按月计算；
- 季度快照在因子覆盖完整季度时允许计算；
- 年度活动量在因子覆盖完整年度时允许计算；
- 活动周期跨越两个因子版本时拒绝该段计算；
- 禁止按天数比例、月份比例或平均值自行拆分活动量。

年度结果是有效计算段之和，不使用一个“年度最新因子”重新计算全年活动量。

## 4. 核算口径

### 4.1 范围一

首版只计算固定燃烧化石燃料的 CO2 排放：

```text
CO2质量
= 活动量
× 低位热值
× 单位热值含碳量
× 碳氧化率
× 44 / 12
```

活动量、低位热值和含碳量单位换算必须显式且可测试。固定燃烧首版不补算 CH4、N2O 或其他
温室气体。

### 4.2 范围二

外购电力采用位置法：

```text
外购电力CO2e = 归一电量 × 适用位置法电力排放因子
```

外购热力采用直接因子：

```text
外购热力CO2e = 归一热量 × 适用热力排放因子
```

首版不扩展市场法、合同工具、可再生能源权益、余热和复杂蒸汽或热水换算。

### 4.3 统一结果单位与气体覆盖

权威结果单位统一为：

- 明细和强度计算基准：`kgCO2e`；
- 总量对外单位：`tCO2e`；
- 面积强度：`kgCO2e/m²`；
- 人数强度：`kgCO2e/人`。

固定燃烧当前只计算 CO2，使用 `GWP=1` 转换为 CO2e。结果必须记录：

- 因子结果基准：`GAS_MASS` 或 `CO2E_DIRECT`；
- 气体代码；
- GWP 数值及来源版本；
- `gasCoverage=CO2_ONLY_FOR_STATIONARY_COMBUSTION`。

首版结果不得描述为完整七类温室气体盘查。电力、热力因子已经是 CO2e 直接因子时禁止再次
应用 GWP。

## 5. 因子来源、因子组合与公式模型

### 5.1 因子来源版本

`biz_carbon_factor_source` 保存稳定来源身份；`biz_carbon_factor_source_version` 保存不可覆盖的
来源版本。来源版本至少记录：

- 来源名称、发布机构、文号或稳定标识；
- 来源版本、发布年份和发布日期；
- 适用地区和适用说明；
- 证据引用；
- `DEVELOPMENT_REFERENCE` 或 `FORMAL` 性质；
- 创建人和创建时间。

来源版本是不可变证据，不用来源名称字符串替代。历史 Excel 或截图以后如需录入，只能创建
`DEVELOPMENT_REFERENCE` 来源版本。

### 5.2 因子稳定身份和组合版本

`biz_carbon_factor` 保存稳定身份，至少固定：

- 因子编码；
- 范围类型；
- 能源品种；
- 因子类别：固定燃烧、电力位置法或外购热力；
- 结果基准和气体覆盖。

`biz_carbon_factor_version` 保存不可覆盖的完整组合版本，至少记录：

- 版本号和来源版本；
- 建筑专项、地区、全国或不依赖地区的适用层级；
- 建筑标识或地区代码；
- 有效期；
- 输入单位及单位版本；
- 标准状态要求；
- 研发参考或正式性质；
- 生命周期状态和配置修订号；
- 审核、激活、停用信息；
- 公式版本和舍入策略版本。

`biz_carbon_factor_component` 保存该组合不可变的参数明细。

固定燃烧组合必须完整引用：

- `LOWER_HEATING_VALUE`；
- `CARBON_CONTENT_PER_HEAT`；
- `OXIDATION_RATE`。

电力和热力组合必须包含：

- `DIRECT_EMISSION_FACTOR`。

计算只匹配完整组合，禁止分别自动搜索多个参数后临时拼接。实测参数替换任一默认参数时必须
创建并激活新的完整组合版本。

### 5.3 公式和舍入策略版本

`biz_carbon_formula_version` 只保存代码注册算法的版本元数据，不保存可执行任意表达式。首版
允许：

- `STATIONARY_COMBUSTION_CO2_V1`；
- `PURCHASED_ELECTRICITY_LOCATION_CO2E_V1`；
- `PURCHASED_HEAT_CO2E_V1`。

`biz_carbon_rounding_policy_version` 保存结果单位、结果精度和舍入方式。公式和舍入版本被计算
结果固定引用，后续版本不能改写历史结果。

## 6. 生命周期与使用性质

### 6.1 生命周期

因子组合版本和分母版本使用：

```text
PENDING_REVIEW -> APPROVED -> ACTIVE -> DISABLED
PENDING_REVIEW -> REJECTED
```

- `PENDING_REVIEW`：待审核，不能参与计算；
- `APPROVED`：专业审核通过，尚未投入计算；
- `ACTIVE`：在有效期内可以参与匹配；
- `DISABLED`：停止参与新计算；
- `REJECTED`：审核未通过。

创建后参数内容不可修改；修订必须生成新版本。状态迁移使用期望修订号进行乐观锁校验。

### 6.2 审核与激活

- 创建人与审核人必须分离；
- 审核人与激活人可以相同；
- 激活前必须验证来源、公式、单位、参数完整性、有效期和重叠版本；
- 激活在一个短事务内关闭或停用被明确替代的重叠旧版本；
- 停用只影响新计算；
- 历史结果继续引用原版本；
- 研发自审必须完整执行审核和激活步骤，不允许跳过状态机。

### 6.3 使用性质

生命周期和使用性质独立：

- `DEVELOPMENT_REFERENCE` 因子可以是 `ACTIVE`，但只能用于研发模拟；
- `FORMAL` 因子必须审核并激活后才能用于正式计算；
- 研发参考因子不能被升级为正式性质，必须新建正式来源和因子版本；
- 活动数据、因子、公式、分母任一为研发性质时，结果只能是
  `DEVELOPMENT_SIMULATION`。

## 7. 因子匹配

### 7.1 公共过滤条件

匹配算法版本固定为 `CARBON_FACTOR_MATCH_V1`。候选必须同时满足：

1. 范围类型一致；
2. 能源品种一致；
3. 因子类别一致；
4. 组合状态为 `ACTIVE`；
5. 使用性质与本次计算模式兼容；
6. 因子有效期覆盖完整活动周期；
7. 活动单位可以转换到因子输入单位；
8. 标准状态要求一致；
9. 结果基准和气体覆盖可被当前公式处理。

零个候选返回因子缺失；最高优先级多个候选返回因子冲突。禁止按版本号、创建时间或更新时间
静默选择“最新”版本。

### 7.2 固定燃烧优先级

1. 建筑专项实测组合；
2. 地区适用组合；
3. 全国组合；
4. 来源明确声明不依赖地区的组合。

### 7.3 外购电力优先级

1. 核算建筑所在省级位置法因子；
2. 全国位置法因子；
3. 否则失败。

电力不使用建筑专项、不依赖地区或研发通配因子。

### 7.4 外购热力优先级

1. 供应方或建筑专项热力因子；
2. 地区热力因子；
3. 全国热力因子；
4. 否则失败。

### 7.5 不使用 `GLOBAL`

地区适用性只允许：

- `BUILDING_SPECIFIC`；
- `PROVINCE`；
- `NATIONAL`；
- `NOT_REGION_SPECIFIC`。

`DEVELOPMENT_REFERENCE` 是使用性质，不是地区。首版不设置自动研发通配地区，也不在匹配失败
时静默使用测试因子。

### 7.6 零值和负值

- 电力、热力直接因子允许为零；
- 零因子必须有明确来源、适用条件并经过审核和激活；
- 因子缺失不能按零处理；
- 固定燃烧低位热值、含碳量必须大于零；
- 碳氧化率必须大于零且不超过一；
- 首版拒绝全部负因子，不处理抵扣、移除和负排放。

## 8. 单位、精度和舍入

### 8.1 单位边界

碳模块只使用第七闭环公开单位契约支持的确定性固定比例转换，例如：

- `kWh` 与 `MWh`；
- `kg` 与 `t`；
- `MJ` 与 `GJ`。

碳模块不处理：

- `L` 与质量单位之间的密度换算；
- `m³` 与 `Nm³` 之间的工况换算；
- 蒸汽、热水温差和焓值换算；
- 软件猜测的燃料密度和标准状态。

活动单位不能确定性转换到因子输入单位时显式失败。

### 8.2 精度

- 活动量、参数和因子使用十进制；
- 中间计算使用 `MathContext.DECIMAL128`；
- 中间步骤不舍入；
- 未舍入结果按 `DECIMAL(38,18)` 保存；
- 总量输出 `tCO2e`，保留六位小数；
- 年度强度保留六位小数；
- 占比返回零至一之间的比例值，保留十二位小数；
- 舍入方式为 `HALF_UP`；
- 同时保存未舍入值、最终值和舍入策略版本；
- 不调整最后一个品种以强行保证舍入后占比等于一。

## 9. 建筑分母档案与强度

### 9.1 独立版本化档案

`biz_carbon_denominator` 保存建筑和分母类型的稳定身份；
`biz_carbon_denominator_version` 保存不可覆盖版本。分母类型只允许：

- `BUILDING_AREA`；
- `RESIDENT_POPULATION`。

版本至少记录：

- 建筑和核算年度；
- 数值和单位；
- 来源、来源版本和证据；
- 有效期；
- 研发参考或正式性质；
- 审核、生效和停用状态；
- 配置修订号、创建、审核和激活证据。

### 9.2 分母标准

- 建筑面积必须大于零，归一单位为 `m²`；
- 常驻人数必须大于零，归一单位为“人”；
- 版本必须覆盖完整核算年度；
- 同一建筑、年度和分母类型只能匹配一个有效版本；
- 多版本冲突时对应强度为空并返回冲突原因；
- 缺失面积时不生成面积强度；
- 缺失人数时不生成人数强度；
- 分母缺失或冲突不影响排放总量；
- 不推算、不按月份加权、不均摊、不继承上一年度、不补零。

### 9.3 首版唯一强度口径

首版只允许：

```text
年度单位面积强度
=（年度范围一总量 + 年度范围二总量）÷ 建筑面积

年度单位人数强度
=（年度范围一总量 + 年度范围二总量）÷ 常驻人数
```

单位：

- `kgCO2e/m²`；
- `kgCO2e/人`。

首版不计算范围一强度、范围二强度、电力强度、热力强度或燃料品种强度。月度、季度只返回
排放量和占比，不返回强度。

底层保留周期类型和分母版本引用能力。未来启用月度、季度强度时，只增加对应分母口径和计算
入口，不修改历史年度结果，不推翻因子库和追溯结构。

## 10. 汇总与占比

每个结果保存：

- 范围一排放量；
- 范围二排放量；
- 总排放量；
- 各能源品种排放量；
- 范围一、范围二和各能源品种占比；
- 年度面积和人数强度或不可用原因。

占比统一以总排放量为分母：

```text
范围一占比 = 范围一总量 ÷ 总排放量
范围二占比 = 范围二总量 ÷ 总排放量
能源品种占比 = 该品种排放量 ÷ 总排放量
```

总排放量为零时，占比为空并返回“总量为零，无法计算占比”，不返回零占比。

## 11. 计算执行、并发和恢复

### 11.1 普通请求的同步有界计算

普通月度、季度和年度计算请求采用同步有界计算。同步计算成立的前提是只读取第七闭环已经
聚合、封账的周期快照，不扫描全年原始时序数据。

年度单次计算规模限定为：

```text
一栋建筑
× 一个核算年度
× 最多十二个月度段或等价的有限周期段
× 有限能源品种
× 对应因子组合
```

月度、季度接口同样只允许一栋建筑和一个明确周期。

必须设置可配置的：

- 上游快照硬上限；
- 计算明细硬上限；
- 数据库查询超时；
- 总计算超时；
- 慢计算阈值。

具体初始数值在实现阶段根据当前数据模型和容量测试确定并记录，不得在没有测试证据时宣称
不会阻塞。

### 11.2 并发和幂等

- 年度请求一次只允许一栋建筑和一个核算年度；
- 同一建筑、周期和核算口径同时只允许一个 `CALCULATING` 批次；
- 使用建筑范围内唯一幂等键；
- 相同幂等键和相同请求摘要返回原批次；
- 相同幂等键但请求摘要不同返回冲突；
- 数据库唯一约束和短事务共同保证并发互斥；
- 批次使用非空 `active_lock_key` 表示运行锁，完成或失败时清空；
- MySQL 唯一索引保证同一计算键只有一个非空运行锁。

### 11.3 事务拆分

禁止将整个计算过程包在一个长事务中：

1. 短事务创建批次，固定请求摘要、截止时间和运行锁，状态设为 `CALCULATING`；
2. 在事务外固定上游快照、因子、公式和分母版本，并执行确定性计算；
3. 短事务一次性保存明细、汇总、证据，更新完成状态并释放运行锁；
4. 失败时使用独立短事务保存安全错误、失败状态并释放运行锁。

计算开始后固定的版本集合不得因并发激活或停用而变化。

### 11.4 普通请求的超时恢复

批次保存：

- `startedAt`；
- `deadlineAt`；
- `completedAt`；
- 执行耗时；
- 快照数量、明细数量；
- 慢计算标识和安全错误代码。

普通同步请求执行期间服务崩溃后，批次可能停留在 `CALCULATING`。首版按以下方式恢复：

- 查询或使用相同幂等键重试时，原子检查 `deadlineAt`；
- 超时仍未完成的批次转为 `FAILED_TIMEOUT` 并释放运行锁；
- 相同请求可以在旧批次终态后创建新的计算批次；
- 不在后台猜测进度、续算或复用未完整落库的中间结果。

### 11.5 两条执行路径

首版保留两条边界明确的执行路径：

- 用户发起的一栋建筑、一个明确周期的普通计算使用同步有界接口；
- 依赖变化引起的历史自动重算使用 MySQL 持久化批次和计算项，由 Spring 定时工作线程领取并
  执行，不占用 HTTP 请求等待完整批次完成。

两条路径复用同一套确定性公式、因子匹配、版本固定、结果表和追溯结构，但拥有不同的调度、
恢复和审批状态。首版不强制引入 RabbitMQ 或 Kafka。

### 11.6 外部消息队列升级条件

出现以下任一情况后再评估外部消息队列：

- 单次包含大量计量边界或明细；
- 调用外部因子服务；
- 自动重算并发或积压明显增加，MySQL 任务领取成为瓶颈；
- 需要跨服务投递、独立扩缩容或更强的事件分发能力；
- 容量测试证明当前工作线程或数据库连接池不能在约定恢复时间内处理任务。

多建筑或多年自动重算本身不是引入外部消息队列的充分条件，是否升级必须由容量和运行证据决定。

## 12. 计算结果与完整性

### 12.1 结果表

- `biz_carbon_calculation_batch`：请求、周期、模式、幂等、运行锁、状态和执行统计；
- `biz_carbon_calculation_item`：活动段、能源品种、因子组合、公式、未舍入和最终结果；
- `biz_carbon_calculation_summary`：范围、能源品种、总量、占比、年度强度和完整性；
- `biz_carbon_result_relation`：候选结果、当前正式结果和被替代结果之间的版本关系；
- 每条明细和汇总保存内容摘要及证据哈希。

### 12.2 批次状态

- `CALCULATING`；
- `COMPLETED_COMPLETE`；
- `COMPLETED_INCOMPLETE`；
- `FAILED`；
- `FAILED_TIMEOUT`。

计算批次状态与结果发布状态分离。`SUPERSEDED` 是旧正式结果的发布状态，不是普通计算批次
状态；它只表示经批准的新正式结果已经替代旧结果，旧结果仍可查询、复算和审计。

### 12.3 完整性

- `LOCKED_COMPLETE` 活动快照正常计算；
- `LOCKED_WITH_EXCEPTIONS` 允许计算并继承全部例外；
- `LOCKED_PARTIAL` 在研发模式下允许生成已知部分，结果为
  `COMPLETED_INCOMPLETE`；
- 正式模式遇到 `LOCKED_PARTIAL` 必须失败；
- 因子缺失、冲突、单位不兼容或标准状态不一致不能通过猜值继续；
- 研发批次可以保存成功项和失败项，但总量必须返回覆盖率、失败项和不完整状态；
- 正式批次任一必要活动段失败时不生成可用总量。

### 12.4 结果不可覆盖

- 计算结果不可原地修改；
- 新计算或重算批次记录候选结果及其拟替代的旧结果；
- 旧结果保留原活动、因子、公式、GWP、舍入和分母版本；
- 候选结果在获准发布前不得覆盖或改变原正式结果的有效性；
- 新正式结果发布后，旧结果标记为 `SUPERSEDED`，但不得删除。

## 13. 自动重算

### 13.1 定义与触发边界

自动重算是指：当碳核算依赖的数据或规则版本发生变化时，系统自动识别受影响范围，生成重算
批次并计算候选结果。

自动重算不等于每收到一条设备迟到消息就立即计算。设备迟到消息先由能源数据链路完成纠偏；
只有活动数据快照发生有效变化并影响已有碳结果时，才触发碳重算。

以下变化可以触发重算：

- 迟到设备数据导致活动数据快照被新版本替代；
- 排放因子新增、修订、启用或者追溯生效；
- 原缺失的排放因子得到补充；
- 碳核算公式版本发生变化；
- GWP 版本发生变化；
- 建筑面积或常驻人数分母版本发生变化；
- 具备动态职责和建筑范围的人员手动发起重算。

尚未关闭的核算周期接收到迟到数据时，按正常数据聚合处理，不属于历史重算。系统不得仅凭
规则版本已创建或处于待审核状态就触发正式结果重算；只有其按适用规则生效并确实影响既有结果
时才创建重算任务。

### 13.2 最小计算项、影响范围和批次归并

重算的最小计算单元固定为：

```text
建筑 × 核算年度
```

系统先根据新旧版本适用范围和历史结果的固定证据分析影响，再按照以下条件归并批次：

- 相同触发原因；
- 相同数据修正窗口；
- 相同组织及权限边界；
- 相同核算年度，或者确由同一变化影响的一组相关核算年度。

设备数量和迟到消息数量只影响批次内的证据和计算项，不产生逐设备、逐消息审批。一个批次可以
包含多个建筑和年度，但每个候选结果仍独立对应一个建筑和年度，且批次不得跨越审批人的建筑
数据权限范围。范围超过配置上限、审批权限不能完整覆盖或存在部分争议时必须拆分批次。

系统使用触发来源、变化版本、影响范围和修正窗口生成稳定触发指纹。数据库唯一约束保证同一
有效变化不会重复创建批次；归并只合并尚未领取且审批边界一致的兼容任务，不修改已经固定范围
或进入审批的批次。

### 13.3 设备迟到数据处理链路

统一处理链路为：

```text
迟到消息
→ 去重及质量判断
→ 修正活动数据
→ 生成新快照版本
→ 分析碳结果影响
→ 创建重算批次
```

不得由单条迟到消息直接触发一次碳重算。系统设置可配置的归并窗口，将短时间内同一建筑、同一
周期的有效快照变化合并处理，避免重复计算和任务风暴。

超过数据修正时限或者涉及已锁定核算周期的数据，不得直接修改活动快照或碳结果，必须进入上游
异常处理或人工确认。碳模块只消费经公开端口提供的新快照版本和修正证据，不绕过第七闭环直接
处理设备消息或修改活动数据。

### 13.4 研发模拟与正式结果审批

自动计算与正式结果替换分开处理。

研发或模拟重算：

- 自动识别影响、创建批次并生成新结果；
- 不需要人工审批；
- 结果标记为 `DEVELOPMENT_SIMULATION`；
- 不得发布为正式核算结果，也不得替代正式历史结果。

正式重算：

- 系统自动识别影响、创建批次并计算候选结果；
- 原正式结果在候选结果审批和发布完成前继续有效；
- 候选结果不得直接覆盖正式结果；
- 具备审批职责且拥有批次内全部建筑数据权限的碳核算审核人员一次审批整个批次；
- 审批通过后，系统在短事务中发布批次内全部合格候选结果；
- 旧结果标记为 `SUPERSEDED`，并保留查询、复算和审计能力。

审批针对冻结的合格计算项集合，不针对设备或单条数据。因子维护人员、数据修正人员或者重算
发起人员不得审批自己引起的正式结果变更；触发原因、责任主体和审批人必须在审批前完成职责
分离校验。

### 13.5 状态、失败隔离与重试

自动重算批次正常状态为：

```text
PENDING_CALCULATION
→ CALCULATING
→ PENDING_APPROVAL
→ PUBLISHING
→ COMPLETED
```

异常状态包括：

- `FAILED_RETRYABLE`：暂时失败，允许按固定策略自动重试；
- `DEAD`：超过最大重试次数，停止自动执行并进入人工处理；
- `REJECTED`：候选结果未获批准，不发布也不替代原结果。

研发或模拟批次可以从计算完成直接进入 `COMPLETED`，跳过 `PENDING_APPROVAL` 和正式发布。

进入审批前必须冻结审批范围并隔离失败项：

- 计算成功且数据完整的项目进入待审批范围；
- 可重试项目按照配置的最大次数和退避策略重新执行；
- 重试耗尽的项目标记为 `DEAD`，不进入审批范围；
- 失败项不得替换原正式结果；
- 一个失败项不得阻塞其他合格项目形成可审批批次；
- 已隔离失败项后续恢复时创建关联的恢复批次，不得加入已冻结或已审批的原批次。

批次保存整体流程状态，计算项保存各自执行、重试和审批资格状态。批次进入
`PENDING_APPROVAL` 后，不允许增加、删除或重新计算其待审批项；范围变化必须创建新批次。

### 13.6 持久化执行、并发和恢复

首版使用 MySQL 持久化重算触发、批次和计算项，由 Spring 定时工作线程执行，不强制引入
RabbitMQ 或 Kafka。至少新增：

- `biz_carbon_recalculation_trigger`：变化来源、触发指纹、修正窗口和影响分析状态；
- `biz_carbon_recalculation_batch`：归并范围、结果性质、审批边界、流程状态和执行统计；
- `biz_carbon_recalculation_item`：建筑、核算年度、旧结果、候选结果、重试和审批资格；
- 对触发指纹、活动批次锁和建筑年度活动计算项设置必要唯一约束。

碳模块内因子、公式、GWP 和分母版本的适用状态发生变化时，必须在同一数据库事务中保存不可变
的依赖变化记录；不得只发送可能随进程崩溃丢失的内存事件。活动快照变化通过第七闭环公开的
版本变更契约提供，碳模块持久化消费游标、来源事件标识和触发指纹后再确认消费，保证可恢复且
重复投递不重复建批。

工作线程通过数据库租约或等价的原子领取机制获取任务，限制并发并防止重复执行。每个计算项
继续使用短事务创建或领取、事务外确定性计算、短事务保存完整结果、独立短事务记录失败的模式。
服务重启后，未过期租约不被重复领取；过期租约经原子校验后进入重试或 `DEAD`，不得复用不完整
中间结果。

系统必须具备：

- 持久化任务和重启后继续执行；
- 触发、批次和计算项三级幂等控制；
- 工作线程、批次和建筑年度并发限制；
- 领取租约、计算超时和超时恢复；
- 有界自动重试和固定退避策略；
- 失败隔离和人工处理入口；
- 防止同一变化重复创建批次；
- 批次规模、计算项数量和单项明细数量硬上限；
- 执行耗时、积压、重试、超时和慢计算监控。

归并窗口、数据修正时限、最大重试次数、退避时间、租约和计算超时、工作线程并发数以及批次
规模上限均为显式配置。具体数值在实现和容量测试阶段确定，不在缺乏证据时写死或宣称无延迟。

### 13.7 一致性和可追溯性

每次重算必须固定并记录：

- 原活动数据快照版本和新快照版本；
- 排放因子及因子版本；
- 公式版本；
- GWP 版本；
- 面积和人数分母版本；
- 触发原因、变化来源、修正窗口和影响范围；
- 原结果、新候选结果及逐项差异；
- 批次、计算项、重试、审核人和全部操作时间；
- 新旧结果之间的替代关系。

历史结果不得原地覆盖。正式候选结果只有经过一次批次审批并成功发布后，才能通过版本关系替代
旧结果。发布事务必须同时固定新结果的正式状态和新旧替代关系；发布失败时原正式结果继续有效，
批次不得被标记为 `COMPLETED`。

## 14. 追溯证据

每个计算明细至少追溯：

- 建筑、周期、时区和核算模式；
- 范围一或范围二；
- 活动快照、活动水位、计量关系和汇总口径版本；
- 能源品种、活动量、原始单位、归一单位和单位版本；
- 因子来源及来源版本；
- 因子稳定身份、组合版本和全部参数版本；
- 地区适用层级、匹配算法版本、候选优先级和匹配原因；
- 公式、GWP 和舍入策略版本；
- 未舍入值、最终值及单位；
- 上游质量、覆盖率、例外和完整性；
- 计算批次、幂等键、请求摘要、操作人、开始、完成和耗时；
- 研发模拟或正式性质；
- 内容摘要和证据哈希。

## 15. 权限、职责和审计

### 15.1 正式角色

- `BUILDING_OWNER`：查看授权建筑的碳结果；
- `ENERGY_MANAGER`：具备相应动态职责时维护规则和运行计算；
- `PLATFORM_ADMIN`：仍需动态职责和建筑范围，不自动绕过。

### 15.2 动态职责

新增：

- `CARBON_RULE_MAINTAIN`；
- `CARBON_RULE_REVIEW`；
- `CARBON_RULE_ACTIVATE`；
- `CARBON_CALCULATION_RUN`；
- `CARBON_RECALCULATION_TRIGGER`；
- `CARBON_RECALCULATION_APPROVE`。

结果查看继续使用正式角色和建筑范围，不增加无必要的重复查看职责。

`CARBON_RECALCULATION_TRIGGER` 用于人工创建重算触发，不替代普通计算职责；
`CARBON_RECALCULATION_APPROVE` 用于审批正式重算批次。审批人必须覆盖批次全部建筑范围，并通过
因子维护、数据修正、重算发起和审批的职责分离检查。

### 15.3 审计

所有动作写入现有公共审计证据链，领域来源为 `CARBON_MANAGEMENT`，至少覆盖：

- 来源版本创建；
- 因子组合和分母版本创建；
- 审核、拒绝、激活、停用；
- 计算开始、完成、不完整、失败和超时；
- 重算影响识别、触发去重、归并、领取、重试、隔离和死亡；
- 正式候选批次审批、拒绝、发布和旧结果替代；
- 幂等命中和幂等冲突；
- 建筑越权、职责拒绝和匹配冲突；
- 新正式结果替代旧正式结果。

审计不保存未脱敏附件、凭据或外部文件内容。

## 16. HTTP API

API 使用 `/v1`、稳定 DTO、统一 `Result<T>`、服务端 `traceId` 和仓库现有错误处理边界。

### 16.1 因子来源

- 新增来源版本；
- 查询来源及历史版本；
- 查询单个来源版本。

来源版本不可修改和删除。

### 16.2 因子组合

- 新增完整组合版本；
- 查询身份、版本和组件；
- 审核或拒绝；
- 激活；
- 停用。

不提供直接修改参数、删除已引用版本和批量覆盖接口。

### 16.3 分母档案

- 新增建筑年度分母版本；
- 查询建筑、年度和历史版本；
- 审核或拒绝；
- 激活；
- 停用。

### 16.4 计算和查询

- 运行建筑月度计算；
- 运行建筑季度计算；
- 运行建筑年度计算；
- 查询批次列表和状态；
- 查询明细、范围汇总、能源品种汇总和年度强度；
- 查询完整追溯证据；
- 使用相同幂等键查询或重新发起超时恢复。

### 16.5 自动重算

- 授权人员手动创建重算触发；
- 查询重算触发、影响范围、批次、计算项、重试和差异；
- 审批或拒绝冻结的正式候选批次；
- 对 `DEAD` 项执行人工处理后的显式恢复；
- 查询正式结果的新旧替代关系。

自动快照变化通过第七闭环公开的可恢复版本变更契约进入影响分析；因子、公式、GWP 和分母变化
通过与业务变更同事务保存的依赖变化记录进入影响分析。不得通过公开 HTTP 接口伪造系统事件。
不提供逐设备或逐消息审批接口，也不提供向已冻结批次增删计算项的接口。

所有列表和明细接口必须有建筑范围、有界分页或固定上限。

### 16.6 错误契约

至少区分：

- 参数和周期无效；
- 未认证、角色不足、职责不足、建筑越权；
- 来源、因子、分母、公式或批次不存在；
- 因子缺失、因子冲突、分母冲突；
- 单位不兼容和标准状态不一致；
- 状态冲突、版本冲突和激活重叠；
- 幂等冲突和并发计算冲突；
- 上游结果不完整或依赖不可用；
- 计算上限、查询上限和超时；
- 重算触发重复、批次范围已冻结、审批范围不完整和职责分离冲突；
- 重试耗尽、任务租约冲突和候选发布失败；
- 内部安全错误。

错误响应不得暴露 SQL、表名、堆栈、外部文件路径或未脱敏数据。

## 17. 数据库迁移与初始数据

迁移只新增本模块必要的 MySQL 表、索引、约束、职责定义和固定算法元数据，包括自动重算触发、
批次、计算项、租约、重试、候选结果和替代关系所需的持久化结构。

允许预置：

- 固定公式算法代码；
- GWP 计算框架，不预置未经确认的非 CO2 GWP 数值；
- 周期、状态、使用性质和适用层级枚举；
- 动态职责定义；
- 自动重算状态和不含业务数值的调度配置项定义；
- 研发舍入策略版本。

禁止预置：

- 任何已生效排放因子数值；
- 建筑面积和常驻人数；
- 历史 Excel 中的生产可用参数；
- 默认建筑、默认地区和默认计算结果。

测试在隔离事务中创建确定性研发因子、活动快照和分母。历史材料以后如需录入，只能创建
`DEVELOPMENT_REFERENCE + PENDING_REVIEW` 版本，不能随迁移自动激活。

## 18. 验证矩阵

### 18.1 公式和单位

- 固定燃烧公式逐参数复算；
- 电力、热力直接因子；
- CO2 到 CO2e 的 GWP=1；
- 防止直接 CO2e 因子重复应用 GWP；
- 固定比例单位换算；
- 密度、工况和标准状态不明确时拒绝；
- 零因子、负因子和参数边界；
- DECIMAL128、中间不舍入、最终舍入和历史策略版本。

### 18.2 匹配和状态

- 建筑专项、地区、全国、不依赖地区优先级；
- 电力和热力各自允许的适用层级；
- 零候选、多候选、时间重叠和单位冲突；
- 完整组合要求和参数替换新版本；
- 审核、拒绝、激活、停用；
- 研发参考和正式用途隔离；
- 乐观锁、并发激活和历史版本不可覆盖。

### 18.3 周期、汇总和强度

- 月度、季度和年度活动周期；
- 因子覆盖完整活动周期；
- 跨因子版本活动量拒绝自动拆分；
- 范围一、范围二、总量和能源品种汇总；
- 全部占比统一使用总量；
- 总量为零时占比为空；
- 年度唯一两项强度；
- 月度、季度不生成强度；
- 分母缺失、冲突或未覆盖全年不影响总量。

### 18.4 普通计算的权限、并发和恢复

- 正式角色、动态职责和建筑范围；
- 创建人与审核人分离；
- 研发完整自审；
- 幂等命中、幂等冲突和同建筑周期并发；
- 前后短事务和失败独立落库；
- 超时批次转 `FAILED_TIMEOUT` 并释放运行锁；
- 普通同步计算在服务中断后不续算、不复用不完整中间结果；
- 审计事件、traceId 和安全错误。

### 18.5 自动重算

- 单条迟到消息不直接触发碳重算；
- 未关闭周期的迟到数据按正常聚合处理；
- 新旧快照有效变化和已有结果影响分析；
- 因子、缺失因子补充、公式、GWP 和分母版本变化触发；
- 触发指纹去重、归并窗口和已冻结批次不可追加；
- 计算项最小单位固定为建筑和核算年度；
- 多建筑、多年度批次按建筑权限边界拆分；
- 研发模拟跳过审批且不能替代正式结果；
- 正式候选审批前原结果继续有效；
- 批次审批、职责分离、原子发布和 `SUPERSEDED` 关系；
- 可重试失败、最大重试、`DEAD`、失败隔离和恢复批次；
- 数据库租约并发领取、超时回收、服务重启续执行和重复执行防护；
- 发布失败回滚且原正式结果继续有效。

### 18.6 容量和目标引擎

- H2 或 Mock 只用于隔离服务和契约验证；
- MySQL 8 执行完整 Flyway 空库迁移和关键约束验证；
- 使用第七闭环公共端口替身进行确定性合成闭环；
- 目标容量测试覆盖单建筑年度上限、重复请求和并发请求；
- 自动重算容量测试覆盖触发风暴、归并、积压、多建筑年度批次、失败重试和重启恢复；
- 记录 HTTP 线程池、数据库连接池、数据库查询和总执行时间；
- 验证硬上限、查询超时、总超时和慢计算证据；
- 本次容量结果不描述为生产 SLA；
- 运行相关定向测试后执行 `mvn test` 和必要打包门禁。

不运行真实设备、现场网络或生产外部资源。自动化、合成、目标数据库和现场验收分别报告。

## 19. 研发验收口径

完成实现后，只有同时满足以下条件才能称为“碳管理后端研发软件闭环候选”：

- 因子来源和因子组合可新增、修订、审核、激活和停用；
- 历史版本、历史结果和追溯证据不可覆盖；
- 匹配确定、可解释，缺失和冲突显式失败；
- 范围一、范围二公式、单位、精度和舍入可确定性复算；
- 月度、季度和年度排放量及占比正确；
- 年度只生成确认的面积和人数强度；
- 分母缺失不影响总量且不伪造强度；
- 每个结果可追溯到活动快照、因子组合、公式、GWP、舍入和分母版本；
- 权限、建筑范围、职责分离、并发、幂等、审计和错误契约通过自动化验证；
- 普通同步有界计算、短事务、超时恢复和容量边界取得本次测试证据；
- 自动重算能够发现有效变化、归并持久化任务、隔离失败并在重启后继续执行；
- 正式历史结果只有在一次批次审批和原子发布后才被新结果替代。

该结论仍不代表：

- 正式权威排放因子已确认；
- 完整温室气体盘查已完成；
- 正式碳排结果已生成；
- 真实数据库生产迁移、真实设备、真实建筑、现场数据或长期运行已验收；
- GB/T 47474—2026 或其他标准整体符合。
