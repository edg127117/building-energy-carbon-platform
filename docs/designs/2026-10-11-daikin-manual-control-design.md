# 大金单台人工控制：离线实现与启用边界

## 1. 批准范围及既有约束

用户已批准本机离线实现、单台关联从机的独立厂家联调例外，以及依据现场结果修正稳定核验、超时、主从许可和部署验收设计。本轮仅修改代码和离线验证，不部署、不调用真实控制接口；现场最后确认的关机、26°C 状态不作操作。当前仍为活动候选，常规控制未启用，完整现场验收尚未完成。单次联调例外不自动开放其他设备或动作。

- 原监测、数据质量、建筑授权、设备接入审批及正式身份约束保留。
- 原“不包含控制”的约束仅为本文的单台内机人工操作增加受控例外：开关、设定温度、模式、风向、风速；一次请求只改变一项。
- 自动策略、批量控制、外机控制、遥控器权限修改、联动设备控制及故障复位继续排除。
- 初次实现与自动化测试只使用离线模拟；后续独立厂家联调单独标记。生产控制与协议确认均默认关闭，迁移不授予任何用户职责、不开放任何设备。
- 前端仅在既有设备详情增加简易控制与结果区域，后续布局可重建，服务端契约保持独立。

## 2. 模块与公开契约

`daikin.control` 负责权限、身份、设备能力、操作状态、占用及审计；`daikin.client` 负责固定来源的厂家协议。`DaikinReadonlyClient` 保留只读白名单，控制只能经独立适配器。读取和控制共享同一来源的 `DaikinSession`、Token、并发及速率预算；该共享预算属于单进程，跨进程总速率尚需部署联调。

平台入口为 `/api/v1/hvac-control`（应用上下文 `/api`）：

| 方法与路径 | 含义 |
| --- | --- |
| GET `/devices/{equipmentId}/options` | 返回当前可用动作、范围、禁用原因和预检版本 |
| POST `/devices/{equipmentId}/operations` | 提交 `{action,value,idempotencyKey,revision}`，HTTP 202 返回持久化操作 |
| GET `/operations/{operationId}` | 查询操作状态及回读值 |
| GET `/devices/{equipmentId}/operations?page=1&size=20` | 同建筑设备历史，最大每页 100 条 |
| POST `/operations/{operationId}/recheck` | 只读核验，不再次发送命令 |
| POST `/operations/{operationId}/close` | 提交 5–500 字原因，关闭 UNKNOWN/UNCONFIRMED 记录，保留隔离 |
| POST `/operations/{operationId}/confirm` | 云端稳定后提交现场确认说明，重新只读核验后完成并释放占用 |
| POST `/operations/{operationId}/release` | 核对 UNKNOWN/UNCONFIRMED/CLOSED，稳定只读核验及现场说明后解除隔离，不撤销厂家命令 |

动作枚举为 `ON_OFF / TEMPERATURE / MODE / AIR_FLOW / FAN_SPEED`，请求值统一为字符串。客户端不得提交厂家身份、URL、凭据或建筑；未知业务字段拒绝。外部错误只返回稳定 `HVAC_CONTROL_*` 代码，不透传厂家报文或凭据。

## 3. 权限与目标确认

每次操作从数据库复核启用账号、当前角色、菜单可见性和当前建筑范围。常规模式下管理员和能源管理员均需 `HVAC_DEVICE_CONTROL`。按用户批准的测试期简化要求，新增默认关闭的 `daikin.control.test-access-enabled`：显式开启后，当前启用的平台管理员复用已有全建筑/菜单规则，无需逐人授予控制职责；不新增多层审批或恢复职责。开关不赋予业主或第三方控制权限，不绕过设备、能力或隔离。读取历史、结果、核验及人工处理仍鉴权；后期正式启用前统一收紧测试授权。

设备必须同时满足：

1. 正式台账未删除、已启用 `DAIKIN_UNIT` 身份、已绑定待接入记录、未缺失的内机目录。
2. 已启用且类型/配置相符的产品，当前项目与建筑映射一致。
3. `biz_daikin_control_grant` 明确开放，绑定平台设备、身份、来源、厂家 id、建筑、映射版本、关系摘要、动作取值和确认版本/人员/证据；风向另需 `air_flow_confirmed`。
4. 厂家 URL 身份在来源内唯一；任何缺失、歧义、迁移或版本变化均拒绝。

预检和实际发送之间重新读取设备快照，并在读取后复核权限、目标及开关。`revision` 覆盖身份、授权版本、关键状态、能力和当前值；预检超过 30 秒或版本变化记为 NOT_SENT。权限撤销不依赖 JWT 或 Redis 缓存生效。

操作记录保留原建筑归属，查询与人工结束要求其与设备当前建筑一致。跨建筑迁移前必须处理未结束操作；本候选不提供跨归属强制解锁接口，不能通过迁移设备绕过未知结果占用。

已发送操作由系统继续有界只读核验，不依赖原操作人员仍持有控制职责；人员撤权拦截新控制和结果访问。身份、建筑或授权版本变化仍使核验失效并保留隔离。

## 4. 设备能力与协议候选

依据用户提供的《百润餐饮栖霞总部 API 协议》操作章节构造候选协议：PUT `/v2/operations/{onOff|temperature|mode|airFlow|fanSpeed}/{equipId}`；控制和单内机 GET `/v2/equipments/inunit/{equipId}` 均用厂家管理点 `id` 寻址，`unitId` 保留用于响应身份核对。请求为单字段字符串 JSON，经既有签名与 AES/Base64 封装。2026-10-12 的真实只读核对已确认认证、分页清单、管理点 id 的单机 GET 与加密空参数查询；按 unitId 查询会返回成功但无设备数据。适配器仅规范已知状态枚举的大小写，未知状态仍拒绝。独立厂家联调已验证开关和温度 PUT 的路径、字符串参数及受理响应，模式、风向、风速 PUT、错误返回和频控仍待验证；不能将这些证据提升为完整平台控制验收。

- 开关、模式和风速仅采用协议枚举与设备能力列表共同支持的值；未知/缺失列表拒绝。
- 温度为 16–32 °C 整数，并同时满足设备默认范围、步长 1、当前制冷/制热模式及上下限；不猜测未知模式或范围。关闭 `temperature-celsius-confirmed` 时禁止温度下发和温度回读核验。
- 风向必须逐设备确认支持后才提供协议候选枚举；没有可靠能力字段时不推断支持。
- 控制器必须明确在线、未强制停止、未退役；设备必须明确无通信故障、无设备故障、未维护，且状态为 operating/stopped。关键布尔缺失不视为正常。
- 群控从机或关系不明继续拒绝。Master/Slave 不再单凭角色决定放行；控制器、管理点、内机、主从标记和排序后的关联编号形成关系摘要，须与开放清单相符。变化必须重新确认，不因测试管理员权限而放行。滤网提示本身不等同于设备故障。
- 原“主从有关联即全部拒绝”的候选规则由经批准的关系摘要和动作取值许可替代；原监测、设备接入审批、建筑范围与故障联锁保留。
- `approved_actions` 按动作保存已确认的字符串取值，例如 `{"ON_OFF":["off"],"TEMPERATURE":["26"]}`；温度也可保存明确批准的 `minimum/maximum` 整数范围，并与设备限制取交集。无动作许可或无关系摘要时全部拒绝。当前现场证据仅支持指定内机的关机、26°C；不自动写入真实设备许可，开机、其他温度、模式、风速和风向仍需各自确认后配置。

## 5. 发送、并发与结果语义

V67 原样保留已部署的天气菜单迁移。控制基础迁移顺延为 V68，增加设备开放清单、操作、物理设备占用、来源冷却和事件表，并登记职责；V69 增量增加关系/动作许可、基线设置、固定期限、稳定进度、读租约、控制器占用及逐次样本。两个控制脚本仅变更尚未部署的编号，内容保持不变；已部署天气 V67 的原始字节和校验和保持不变。旧许可因缺少关系和动作证据不能继续控制。操作、占用及审计在同库事务内提交；HTTP 不在数据库事务中执行。审计失败时发送意图回滚，不能继续下发。

`operator_id + idempotency_key` 唯一；相同键和请求返回原记录，不同内容返回冲突。来源行锁、物理设备键与 `(sourceId,controllerId)` 控制器键唯一约束共同限制在途操作。旧版本未建立控制器槽的物理占用也纳入检查。一次请求只改变一个动作，云端稳定仍保留占用直至现场确认。H2 并发测试属于离线证据；本轮隔离 MySQL 两 JVM 验证已补齐占用与租约竞争。完整应用多实例、死锁注入及总体请求预算仍待验收。

| 状态 | 准确含义及后续行为 |
| --- | --- |
| PREPARING | 已记录意图并占用，尚未发送；过期转 NOT_SENT |
| SENDING | 已持久化单次发送许可；中断恢复只能转 UNKNOWN，绝不重发 |
| ACCEPTED | 厂家返回 `10000`，只表示受理 |
| OBSERVED_MATCH | 仅兼容历史单次相符记录，新操作不再进入此状态 |
| OBSERVED_STABLE | 云端稳定回读，等待现场确认，保留设备及控制器占用 |
| CONFIRMED | 稳定回读及人工现场确认完成，释放占用；不表示存在厂家执行回执 |
| REJECTED | 厂家已知失败码，释放占用，不自动重试 |
| NOT_SENT | 预检拒绝，未发送，释放占用 |
| UNKNOWN | 响应丢失、异常或未知返回码；保持占用，回读一致仍保留 UNKNOWN |
| UNCONFIRMED | 已受理但有界核验未确认，保持占用 |
| CLOSED | 关闭记录本身保留隔离；独立解除隔离后仍为 CLOSED，以原因码和原事件区分，绝不伪报执行成功 |

自动只读核验首次约发送后 15 秒，之后每 30 秒一次；至少观察 180 秒，连续至少 3 个有效相符样本且跨度至少 60 秒才标记云端稳定。发送前保存开关、设温、模式、风速和风向基线；请求项须相符，其他设置须保持不变。关机须同时为 off/stopped，开机须同时为 on/operating；室温自然波动不作为判定条件。任何不一致或读取错误重置连续进度，但保留样本和固定的发送后 300 秒期限。到期未稳定转 UNCONFIRMED 并停止后台轮询；UNKNOWN 始终保留未知发送结果，稳定观察也不能提升成功。

每个样本分别保存请求时间、读取完成时间；当前没有可信设备采样时间，`device_sample_at` 保持空，响应 `resTime` 不当作设备新鲜度。前端明确显示云端读取证据，不能声称物理执行已确认。

后台及人工核验共享 30 秒数据库 CAS 租约和代数；过期读取不能覆盖新租约的样本。连续读取间隔超过 60 秒时重新积累证据，避免中断很久后拿旧稳定进度解除隔离。浏览器关闭不会中断后台任务，前端轮询覆盖 300 秒核验窗并允许重新打开历史。进程恢复只读，SENDING 中断只转 UNKNOWN。10003/10008 使来源冷却 60 秒。Token 失效、通信超时、HTTP 异常及状态入库失败均不触发控制重发；读取沿用既有有限续期重试。

关闭未知/未确认记录只停止观察，不解除隔离。现场确认和解除隔离均要求新鲜只读重查、有效稳定证据及 5–500 字人工说明；记录原厂家码和历史状态，UNKNOWN 不进入 CONFIRMED。当前保守恢复要求请求项和其他设置仍符合原基线；身份变化或状态不能稳定时保持隔离，需现场/厂家查明后处理，不能凭关闭按钮、迁移身份或反向补发绕过。

界面不乐观覆盖实时值；展示请求值、回读值和操作状态，历史按服务端分页。设备切换隔离旧响应；不确定操作保留原幂等键，避免网络错误造成第二条指令。

## 6. 默认关闭与离线验证

`daikin.control.enabled=false`，`daikin.control.wire-confirmed=false`。生产适配器还要求 `daikin.device-client.enabled=true` 才装配；仅打开控制总开关而未确认协议时返回 PROVIDER_UNAVAILABLE。关闭控制不影响既有只读监测的独立配置，也不清除未确认操作或审计。

测试配置关闭控制开关，生产客户端配置通过 `!test` 排除，即使宿主机配置误启用也不创建真实 HTTP 客户端。控制测试自行装配内存 H2、固定时钟及内存 transport/fake gateway；`.example.test` 仅用作请求 URI 断言，不执行 DNS 或 HTTP。`DaikinControlOfflineFlowTest` 覆盖五项动作从真实 Service、持久化、真实签名加密适配器到模拟设备更新与回读的闭环；MockMvc 和安全链测试覆盖 HTTP 契约与认证，前端使用请求模拟覆盖交互和迟到响应。

验收要求：默认无外部读取/写入；无权或设备限制拒绝且写入次数为零；每个幂等操作最多一次 PUT；审计失败不得发送；响应丢失不得重发或伪报成功；五项合法操作均可持久化并得到准确的回读状态；前端不能越权、提交隐藏字段或把受理标成执行成功。定向测试之外需通过仓库 Java/Vue 完整门禁。具体本轮结果随交付报告，不能引用历史测试代替。

本机重跑：仓库根目录执行 `./mvnw.cmd "-Dtest=DaikinControl*Test,DaikinReadonlyClientTest,DaikinDeviceClientBeansTest" test`；`web` 目录执行 `npm run test:run -- src/modules/dashboard/api/hvac-control.test.ts src/modules/dashboard/composables/use-hvac-control.test.ts src/modules/dashboard/components/HvacControlPanel.test.ts`。这些测试无需服务器或厂家连接；Windows 受限沙箱若阻止 Mockito 动态附加，应以 JVM `-javaagent` 预加载本地已有 Byte Buddy 代理，不跳过用例。

## 7. 真实联调待办与启用顺序

服务器专项验收及编号协调已完成：已部署天气 V67 原始字节与历史校验和保持不变；未部署的控制基础/稳定迁移顺延为 V68/V69，内容保持不变。以前轮结构/合成数据验收为基础，本轮使用运行库实际结构及升级必需的 Flyway、菜单、角色、职责元数据建立隔离 MySQL 8.0.46；未复制用户凭据、设备遥测或审计内容。候选 JAR 的迁移资源与源码逐字节一致，没有旧控制编号残留。

迁移编号冲突已解除，数据库实际升级路径可用。后续已按实际服务器发布清单整合控制候选与天气前端、电量分析代码，保留原功能实现；Java 全量回归、前端全量测试、静态/类型检查及构建通过。最终候选 JAR 的全部 MySQL 迁移与隔离验收 JAR 和当前源码逐字节相同，控制相关开关默认关闭；部署脚本只读路由检查通过，服务器前后发布文件、指针及 Flyway 历史未变。当前具备默认关闭的测试发布条件，尚未部署或调用真实控制接口，现场设备没有被操作。两 JVM 检查仅证明控制存储竞争，不替代完整应用多实例、总体厂家频控及现场验收。
