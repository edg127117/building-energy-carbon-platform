## 3. 资料依据与评价规则

### 3.1 证据分层

主参考为用户提供的《GB/T 17981-2025〈空气调节系统经济运行〉指标体系·开发参考》，重点是第 3 节指标表、第 5 节判定和第 9 节口径事项。本文保存本期所需的规则摘录及解释边界，不提交附件原件或个人存储路径。

[国家标准官方信息页](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=054E25A1C1B52CC054F50A9653DBD5A5)已核实标准名称、编号和实施信息；全文公式、表注和适用条件尚未逐条复核。专家参考材料已经给出可执行的研发比较规则，正式原文复核状态不能被误写成“没有评价标准”。

[OIML R 75-1 第 8 节](https://www.oiml.org/en/files/pdf_r/r075-1-e02.pdf)仅作为流量、温度与热量积分关系的技术参考，不替代 GB/T 17981 的适用性确认，也不表示平台软件取得计量器具认证。

### 3.2 EERp 规则摘录

| 项目 | 专家参考材料内容 | 本期处理 |
| --- | --- | --- |
| 分子 | 制备总冷量 | 固定制备端边界与计量位置 |
| 分母 | 冷机、冷水泵、冷却水泵和冷却塔风机耗电，不含末端 | 对照配置逐项检查覆盖和去重 |
| 方向 | 越大越好 | 固定为正向能效比较 |
| 全年累计 | 引导值 4.0，先进值 5.0 | 本期研发评价使用 |
| 典型工况 | 引导值 4.2，先进值 5.2 | 仅保留资料说明，不实现本期评价 |
| 比较符号 | 应大于引导值，宜大于先进值 | 严格使用 `>`，不改为 `>=` |

原文核实前，规则来源类型为 `EXPERT_REFERENCE`，标准核实状态为 `METADATA_VERIFIED_TEXT_PENDING`，使用性质为 `DEVELOPMENT_REFERENCE`；上述字段不能因配置审核通过自动升级为正式标准核验。

### 3.3 全年研发评价区间

| EERp 值 x | 结果代码 | 结果说明 |
| --- | --- | --- |
| x < 4.0 | BELOW_GUIDANCE | 低于引导值；参考材料第 5 节称“急需节能降耗” |
| x = 4.0 | AT_GUIDANCE | 等于引导值，未满足严格大于引导值的要求 |
| 4.0 < x <= 5.0 | GUIDANCE_ONLY | 满足引导要求，未满足严格大于先进值的要求 |
| x > 5.0 | ADVANCED | 满足先进要求；参考材料称“先进节能” |

“等于引导值”和中间区间采用客观比较描述，不声称这些名称是标准正式等级。EERt 的末端阈值不进入本规则。不得套用参考材料总述中不区分方向的“超了引导值”说法。

比较基于计算精度下尚未作展示舍入的值；保存原值、展示值和舍入版本。配置只允许 EERp 的有限规则结构，校验先进值大于引导值，区间无重叠且覆盖所有合法结果。新规则版本须有来源和审核，不能修改已有版本以改变历史等级。

## 5. 冷站配置和计量覆盖

### 5.1 配置对象

EERp 配置引用一个建筑内的冷站系统身份和计量边界。至少包括：冷站类型、关系版本、设备及测点引用、覆盖对象、制备端计量位置、电量分项角色、冷量来源、业务生效区间、来源证据、研发性质和修订号。多台冷机和多组泵按配置处理，不写死数量或测点编码。

配置必须说明冷量来自单机出口组合还是冷站制备端总表。制备端与交付端不能凭单位相同而互换；旁通、混水或测点不在同一水路时，不得自动配对。共用设备在没有经确认的独占归属或上游分摊结果时保持未分配，本期不新增分摊算法。

### 5.2 去重和来源切换

- 电量选择完整总表或互不重复的分表组合；总表和覆盖于其中的分表不得重复计入。
- 冷量选择冷站总量或互不重复的机组制备量；总量和机组分量不得同时相加。
- 权威性以覆盖对象和生效区间校验，不能仅通过测点 ID 不同认定互不重复。
- 每个覆盖对象同一时段选择 `METER_CUMULATIVE` 或 `FLOW_TEMPERATURE`；不同非重叠机组可有不同来源，但必须合计完整覆盖冷站。
- 来源变更须审核并给出明确生效边界；分段不可重叠，出现缺口时年度结果不完整。不得以主源失败为由自动使用副源补齐。
- 配置、关系、介质或处理策略在年内变化时，按实际生效时间分段，固定各段版本；不按天数比例拆分无法提供边界读数的累计量。

冷量计算测点契约必须执行建筑权限、点归属、物理量及单位匹配和计算场景质量门禁。不能让客户端自选宽松场景；查询展示策略不能代替计算策略。新场景默认沿用无正式策略时仅允许 Q0 的安全行为，空允许集合仍表示全部拒绝。对齐处理标记与 Q 等级分别保存，不把保持值自动标成实测 Q0。

周期模块增加明确的原生量模式，使制备冷量无需 tce 规则即可形成周期事实；不得通过伪造折标参数或全局忽略 `TCE_RULE_UNAVAILABLE` 实现。已有折标链及其审核、封账语义保持原样，新增入口必须有独立契约和兼容回归。

## 7. 冷量计算、时间与质量

### 7.1 冷量表路径

使用上游累计量算法处理起止锚点、复位、回绕、换表和已审核修正。不使用最大读数减最小读数替代事件处理，不把负差自动清零。累计量两个有效端点不等于中间每个采样时刻都有记录：是否足以证明该段总量完整，应依累计量语义、计量事件及相应质量规则判断，不能套用温差积分的采样覆盖率。

### 7.2 流量与温度路径

在水介质与已确认参数适用范围内，采用固定参数近似式：

```text
P_c(t) = rho × cp × Vdot(t) × [T_return(t) - T_supply(t)] / 3600
Q_c = 对 P_c(t) 按时间积分
```

`rho` 单位为 kg/m3，`cp` 为 kJ/(kg·K)，`Vdot` 为 m3/h，温差为 K，制冷功率为 kW；积分时长以小时计，冷量为 kWh。流量计在供水侧或回水侧的安装位置与介质参数适用条件一并保存。

密度、比热、适用温区和处理规则必须来自同一明确参数版本。首批不实现动态物性库；超出有效参数范围时拒绝该段。既有 1000 和 4.18 常数仅可作为显式研发样例参数，不能直接继承为所有现场的正式默认。

### 7.3 对齐与积分

- 精确同步样本直接组合；非同步样本仅在已配置并审核的有限时长保持前值规则下组合，不使用未来样本向前填充。
- 时间节点包含相关测点更新、允许保持时长到期、质量拒绝、配置生效及区间边界；保持值必须保留原始事件时间和使用时长。
- 每路样本必须满足允许时差、最长保持时间和自身质量门禁。被拒绝或失效的样本不能通过过滤后连接前后两个“好点”而被跨越。
- 先组装对齐后的流量和温差，再计算制冷功率。不能将各路独立分钟均值、月均值或年均值相乘作为权威冷量。
- 积分复用既有算法，固定积分策略版本。前值保持输入与阶梯积分配套；梯形积分只用于规则明确允许的端点序列，不能跨配置变化、保持到期、缺测或异常段进行平滑。
- 长缺口拆为无效区间，不在缺口两端连线积分。时间精度使用事件毫秒与精确时长，适配时不得因现有秒级计算而静默丢弃亚秒时长；精度不足须明确拒绝或补齐公共算法契约。
- 年度输入按有界段处理，处理段边界和年度/月度边界均不得重复积分或遗漏；不得每次年度查询扫描全年原始数据。

### 7.4 零值、负值和完整性

负流量、反向温差、非法单位、非有限值、介质越界、不同水路以及未确认映射均返回明确拒绝原因，不取绝对值或补零。零流量、零温差和停机的合法判定依赖已审核规则；未配置规则时保留未确定状态，不能仅凭停机标记生成整段零冷量。

有效零冷量段与缺测段必须可区分。冷量为零不自动抹去同段冷站实际用电；电量边界按所选统计规则独立完整覆盖年度，不通过只保留产冷时段人为提高 EERp。

完整性按每个必需覆盖对象分别验证，再判断年度组合是否完整，不对各测点覆盖率取简单平均。任何未被规则合法覆盖的区间导致年度 `INCOMPLETE`。研发完整样例覆盖完整年度；专业完整性规则未确认不授权现场补齐、外推或降低门槛。

## 8. 年度计算、结果和追溯

自然年度区间为版本化时区中的年初至次年年初，不写死 365 天或全年小时数。底层分段冷量和电量使用相同区间；已有周期结果被精确组合，不能按时长比例猜测分段电量。

```text
EERp_year = sum(Q_c_segment) / sum(E_station_segment)
```

只有完整年度、计量边界完整且分母大于零才生成 EERp。各段比值不做算术平均；分母为零时 EERp 为空，不能输出无穷大。中间计算使用十进制精度，舍入只用于固定版本的结果表达，不改变第 3.3 节比较含义。

结果至少分别记录：

| 分类 | 字段内容 |
| --- | --- |
| 身份与范围 | 结果 ID/修订、建筑、冷站、边界、年度、半开区间与时区 |
| 输入 | 冷量、电量及单位，各分项数量、来源与快照集合 |
| 计算 | 公式版本、介质版本、对齐/积分/舍入规则，未展示舍入的 EERp |
| 状态 | `calculationStatus`、`completeness`、`evaluationStatus`、原因列表及受影响区间 |
| 评价 | 阈值、区间结果、参考来源、规则版本、标准核实状态 |
| 证据 | 关系、测点、质量、计量事件、来源选择、参数与处理标记；实际使用的输入或不可变输入快照 |
| 性质与审计 | 原始数据真实/合成性质、结果 `DEVELOPMENT_SIMULATION`、触发人、时间、traceId、前序结果引用 |

读取真实采样也不能把研发计算结果标为正式，合成样例不能标为真实采样。计算成功与可评价分别判断：规则缺失或不适用时可保存完整计算值，但评价返回具体原因；标准全文未核验本身不阻止已经确认的附件规则产生研发评价。

已完成结果不得原地覆盖。追溯应能够重建本次输入、选择过程和比较结果，不只提供版本号、JSON 标签或哈希。上游原始事实并不保证保留全部历史修正，因此首次计算须固定实际使用的事实快照；若无法取得或保存可复算证据，则标记证据不足，不能声称完整追溯。

## 9. 配置治理、接口和持久化

配置、参数和评价规则使用稳定身份与不可覆盖版本，经过草稿、提交、审核和生效。引用历史版本时检查业务有效期与本次固定版本集合，不用“当前最新”替代历史。维护、审核、计算和重算接入动态后台职责及建筑范围；研发自审仍完整执行两个动作，不能绕过现有职责分离。

拟提供 `/api/v1/energy-efficiency` 下的冷站配置版本、计算规则版本、计算任务、年度结果和追溯查询接口。Controller 只处理入口，业务及事务在 Service；具体 DTO 和错误代码须与上述公共契约同时冻结并生成 OpenAPI。只读结果查询不触发隐式重算，前端不会参与计算。

MySQL 保存配置、版本、审核、计算任务、结果索引和证据清单；TDengine 保存派生制冷功率、周期与年度数值及必要数值证据；Redis 仅作可丢弃缓存。跨数据库不假定分布式事务：先固定任务与证据、幂等写入数值，再确认 MySQL 可见结果；未完成或写失败结果不得冒充当前成功版本。

首版显式发起计算和有界重算，不增加自动依赖调度引擎。同一幂等键和请求摘要返回已有任务，摘要冲突明确拒绝；有界分段任务保存进度，失败可恢复，旧执行不得覆盖新修订。单任务时间跨度、测点数、分段数、单页记录数、超时和并发上限必须有有限配置与测试，超限明确拒绝，不截断后声称完整。

审核、恢复或重算失败保留原因、traceId 和输入身份；修订过期、跨建筑、规则缺失、单位不兼容、来源重叠、锚点不足、时间错配、质量拒绝、零分母、输入不完整、证据不足和资源超限均需稳定错误/业务状态。HTTP 请求错误与合法请求产生的“不可计算/不可评价”结果分开表达。

本设计不预占 Flyway 编号，不创建 SQL 或正式配置种子。编码前按最新主线与并行任务协调迁移；已应用脚本不修改，新增结构和规则不得覆盖电力因子或其他模块数据。研发参数只进入明确的测试配置或经审核的研发版本，不自动激活为生产规则。
