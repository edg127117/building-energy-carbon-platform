# 可配置设备接入与业务绑定设计

> **文档状态：活动候选设计，尚未实现、尚未验证、尚未批准为当前正式基线。**
>
> 当前权威基线仍以 [`PROJECT_STATUS.md`](../../PROJECT_STATUS.md)、当前代码和自动化测试为准。
> 本候选只有在完成实现、范围匹配的自动化验证、独立验收并经用户批准后，才能转为正式版本能力。

## 1. 结论

本次不重写云端适配器，也不要求每台设备发送 `buildingId`、`deviceId`、`pointCode`。
目标是在现有“云端协议转换、本地业务归属”边界上补齐两类能力：

1. 云端按**产品协议模板**适配报文。同一协议的新设备只产生新的设备身份，不修改 Java；
   JSON 字段、嵌套路径、单位或倍率变化优先通过新模板版本处理。
2. 本地平台允许设备先被发现、后由管理员绑定建筑、空间、系统、设备和测点；绑定完成前只进入
   有界待处理区，不写入 TDengine 正式时序数据，也不参与聚合、质量任务和公式计算。

这里的“先发现”不等于“完全不配置协议”：云端必须已有能识别该报文结构和稳定设备身份的产品协议模板。
同型号新设备不需要新增模板；全新且当前内核无法识别的报文结构，仍需先增加模板或协议插件。

第一阶段建设建筑与空间、设备与测点、产品型号与测点模板、待绑定设备和接入向导页面。
云端协议模板仍由运维以受控方式维护，不开发可视化协议编辑器。

## 2. 背景与当前证据

当前仓库已经具备：

- 独立的 [`telemetry-adapter`](../../telemetry-adapter)，能按云端 MySQL 模板把一条 JSON 报文转换成
  一条标准多指标报文；
- JSON Pointer 嵌套字段读取、设备身份、设备时间、序号、倍率、偏移量、单位和必填字段配置；
- 本地 `device/telemetry/up` 标准报文入口；
- `外部身份 → 设备 → 建筑 → 期望协议` 预注册，以及设备专属测点别名校验；
- 标准报文通过预检后复用现有 TDengine、分钟聚合、Q0/Q1/Q2、公式、Redis、WebSocket 和查询链路。

当前缺口是：

- 未预注册设备只由 [`UnknownDeviceHandler`](../../src/main/java/com/platform/iot/identity/UnknownDeviceHandler.java)
  记录日志和监控后拒绝，没有待绑定记录；
- 新设备必须在首次正式上报前通过 SQL 预创建设备、身份和全部测点别名；
- 建筑、空间、系统分组、设备和测点虽已有部分后端接口，但没有对应业务管理页面；
- 没有产品型号和测点模板，新增同型号设备仍需逐个建立测点与别名；
- 云端协议模板当前由 MySQL 直接维护，没有版本包校验、发布和回滚工作流；
- 真实云服务器、现场网络、更多型号设备和长时间运行仍未验收。

本设计是对历史[可配置多字段适配器设计](../superpowers/specs/2026-08-11-configurable-multifield-telemetry-adapter-design.md)
中“后续待绑定设备”的正式展开，不改变已实现数据链的当前事实。

## 3. 目标与非目标

### 3.1 目标

1. 同一产品型号新增物理设备时，不修改云端适配器代码，也不要求预先创建建筑归属；
2. 新 JSON 结构在现有解析能力范围内时，只新增或升级协议模板；
3. 平台安全记录未知设备的身份、协议、首次/末次发现时间、上报次数和有限样例；
4. 管理员通过接入向导完成建筑、空间、系统、设备、产品型号和测点映射；
5. 绑定、启用和正式入库之间具有明确状态，不让未确认数据污染业务时序；
6. 同型号设备可以从产品测点模板批量生成测点和设备专属别名；
7. 保持现有 HVAC 数据质量、公式和展示链，不在本次重算业务指标；
8. 为后续更多 JSON 设备提供可测试、可回滚、可追踪的接入流程。

### 3.2 第一阶段非目标

- 不开发云端可视化协议编辑器；
- 不允许运行时上传 Java、脚本或表达式代码；
- 不支持 Modbus、BACnet、Protobuf、二进制、加密、压缩或私有握手协议；
- 不自动猜测建筑、空间、设备类型、单位和业务语义；
- 不让未知设备直接写入正式 TDengine；
- 不回放绑定前的未知设备样例；绑定后从下一条合格报文开始正式采集；
- 不恢复已经下线的旧电表 Demo，也不建立一条平行的旧业务链；
- 不新增能耗、碳排公式、报表、天气、控制或下行指令；
- 不在本次处理 WebSocket 多实例、微服务拆分或无限量原始报文归档。

## 4. 既有硬约束处理

| 既有约束 | 本候选处理 | 说明 |
|---|---|---|
| Spring Boot 单体后端与 Vue 前端 | 保留 | 本地设备接入管理继续在当前平台内实现 |
| 云端适配器只负责协议接入和转换 | 保留 | 不在云端保存建筑、设备归属、用户和正式遥测 |
| 本地 MySQL 管业务、TDengine 管时序、Redis 管缓存 | 保留 | 待绑定记录属于本地 MySQL 业务数据 |
| 平台不信任设备上报的 `buildingId` | 保留 | 建筑归属只由本地绑定产生 |
| 未知设备不写正式时序 | 保留并增强 | 从“只告警”增强为“有界发现记录 + 仍不正式入库” |
| 首包前必须完成全部预注册 | 明确替代 | 改为“可先发现，正式入库前必须完成绑定并启用” |
| 云端模板通过 MySQL 驱动 | 保留 | 第一阶段只补充受控版本交付规范，不开发前端编辑器 |
| 旧 `device/data/up` 只用于迁移 | 保留 | 新设备只走标准多指标链 |
| 浏览器不生成假数据、不重算后端指标 | 保留 | 页面只展示真实管理数据和后端返回的样例 |
| 当前无控制能力 | 保留 | 本设计只处理上行接入 |

## 5. 总体架构

```text
设备原始报文
  → 云端 EMQX 原始 Topic
  → telemetry-adapter 稳定解析内核
  → 产品协议模板（云端 MySQL，按版本维护）
  → device/telemetry/up 标准多指标报文
  → 本地标准报文入口
       ├─ 身份已绑定且已启用 → 设备专属测点别名 → 正式时序链
       ├─ 身份未知           → 待绑定设备有界记录 → ACK，不写正式时序
       └─ 身份已知但协议冲突 → 安全拒绝与告警，不自动改绑

本地管理端
  → 建筑/空间/系统管理
  → 产品型号/测点模板
  → 待绑定设备
  → 接入向导
  → 设备/测点管理
  → 启用后接入正式时序链
```

### 5.1 云端适配器职责

云端只回答“这是什么设备身份、报文包含哪些标准指标、值和时间是什么”，不回答“设备属于哪栋建筑”。
因此设备发现发生在“协议已识别、业务尚未绑定”这一层，而不是对任意未知字节流自动建档。

稳定内核继续承担：

- MQTT 订阅、QoS、ACK、重连和载荷限制；
- JSON 对象和 JSON Pointer 读取；
- 一包多字段展开；
- 数值类型、必填、倍率、偏移量和单位转换；
- 设备时间优先、云端接收时间回退、序号透传；
- 标准多指标报文生成与发布；
- 模板快照刷新失败时继续使用上一完整快照。

以下变化不修改适配器 Java：

- 新增同一产品型号的设备；
- 身份值从一台设备变成另一台设备；
- 字段名、JSON 嵌套路径、必填性、单位、倍率或偏移量变化；
- 同一 JSON 能力范围内新增标准指标；
- 在相同标准语义下发布新的模板配置版本。

以下变化需要扩展适配器代码或新增协议插件：

- MQTT 以外的新传输，或需要网关主动轮询；
- 非 JSON、数组动态展开、二进制、Protobuf、加密、压缩或签名；
- 需要跨多包组帧、状态会话、复杂条件分支或校验和；
- 一项源数据需要当前模板能力无法表达的复杂计算；
- 厂商协议需要专有 SDK 或握手流程。

第一阶段不为这些未来协议提前设计万能脚本引擎。出现真实设备后，以独立协议插件扩展并单独验收。

### 5.2 本地平台职责

本地平台负责：

- 发现标准报文中的未知外部身份；
- 保存建筑、空间、系统分组、设备、产品型号、测点和外部身份绑定；
- 将产品模板实例化为具体设备测点与设备专属别名；
- 校验登录角色、建筑范围、设备状态、协议、单位、范围和跨建筑归属；
- 绑定并启用后把标准指标送入现有正式数据链；
- 保存接入操作审计，不把业务归属反向同步给云端适配器。

## 6. 标准报文契约

设备不需要直接发送平台五字段报文。云端适配器继续输出当前标准契约：

```json
{
  "standardVersion": "1.0",
  "profileCode": "ENERGY_METER_1039",
  "profileVersion": 1,
  "deviceIdentity": {
    "type": "SERIAL_NO",
    "value": "energy-meter-001"
  },
  "eventTime": 1785398400000,
  "receivedTime": 1785398400123,
  "timeSource": "SERVER_RECEIVED",
  "seq": null,
  "metrics": [
    {
      "code": "VOLTAGE",
      "value": 221.401,
      "unit": "V",
      "sourceField": "/param/ID255/1#/U"
    }
  ]
}
```

约束：

- 标准报文不携带可信 `buildingId`；即使未来兼容字段存在，本地也不得据此改变归属；
- `deviceIdentity.type + deviceIdentity.value` 是物理来源身份，不是平台设备主键；
- 身份优先来自 SN、序列号、MAC、网关与从站地址组合等稳定值；没有稳定身份的硬件必须由设备或网关补充；
- `profileCode` 表示兼容的标准语义族；仅配置修订增加 `profileVersion`，若标准指标代码或单位语义发生
  不兼容变化，必须创建新的 `profileCode`；
- `eventTime` 优先使用设备时间，其次允许云端接收时间；`timeSource` 必须如实说明来源；
- 没有设备时间和递增 `seq` 时，不能把云端接收时间包装成设备时间，也不能精确证明丢包率；
- `metrics.code` 是产品协议层的标准指标语义，不直接等于平台 `pointId`。

### 6.1 两类示例报文的处理

嵌套电表报文可配置：

```text
身份路径：/SN
电压路径：/param/ID255/1#/U
电流路径：/param/ID255/1#/I
功率路径：/param/ID255/1#/P
功率因数路径：/param/ID255/1#/Pf
频率路径：/param/ID255/1#/F
正向电能路径：/param/ID255/1#/EPP
反向电能路径：/param/ID255/1#/EPN
```

平铺能碳报文可配置 `/MAC`、`/current_energy`、`/current_co2` 等路径。两个报文都不要求修改
当前 JSON 解析内核，但必须先由设备方确认单位、累计/周期语义、发送周期、设备时间和序号。

## 7. 领域模型

### 7.1 产品型号

新增 `biz_device_product`，表达可重复使用的产品接入模板：

| 字段 | 含义 |
|---|---|
| `product_id` | 平台内部稳定 ID |
| `product_code` | 平台唯一产品编码 |
| `product_name` | 展示名称 |
| `manufacturer`、`model` | 厂商和型号 |
| `equipment_type_code` | 对应平台设备类型 |
| `expected_profile_code` | 允许的云端兼容协议族 |
| `identity_type` | 预期身份类型 |
| `status` | 草稿、启用或停用 |

`profileVersion` 不在本地逐设备锁死；同一 `profileCode` 的版本必须保持指标代码和单位语义兼容。
不兼容变化通过新 `profileCode` 和新产品版本处理。

### 7.2 产品测点模板

新增 `biz_product_point_template`：

| 字段 | 含义 |
|---|---|
| `template_point_id` | 模板测点内部 ID |
| `product_id` | 所属产品型号 |
| `metric_code` | 标准报文指标代码 |
| `point_name_template` | 实例化后的默认测点名称 |
| `suffix_code`、`unit` | 平台标准语义与单位 |
| `min_value`、`max_value` | 可选运行范围 |
| `for_calc` | 是否允许进入既有公式输入 |
| `required_flag` | 激活前是否必须映射 |
| `sort_order`、`status` | 展示和启停 |

同一产品内 `metric_code` 唯一。模板只提供确定性默认值，不根据字段名自动猜测语义。

### 7.3 待绑定设备

新增 `biz_pending_device`：

| 字段 | 含义 |
|---|---|
| `pending_id` | 待绑定记录 ID |
| `identity_type`、`identity_value` | 外部设备身份，组合唯一 |
| `profile_code`、`last_profile_version` | 最近上报协议 |
| `first_seen_time`、`last_seen_time` | 首次和末次发现时间 |
| `report_count` | 上报计数，更新必须避免丢失并发增量 |
| `latest_event_time`、`latest_time_source` | 最近事件时间及来源 |
| `latest_metrics_json` | 大小受限的最新标准指标样例 |
| `sample_truncated` | 样例是否被截断 |
| `status` | `DISCOVERED`、`BOUND` 或 `IGNORED` |
| `bound_identity_id` | 绑定完成后关联现有身份记录 |

第一阶段只保留**最近一份规范化指标样例**，不保存原始厂商完整报文，不建立待绑定时序库，也不提供回放。
样例字段数、单字段字符串长度、JSON 总大小和保留时长必须配置上限；过期 `DISCOVERED`、`IGNORED`
记录由有界清理任务处理。删除待绑定样例不影响已绑定设备的正式数据。

### 7.4 设备、身份和别名

复用现有：

- `biz_equipment`：具体物理设备；新增可空 `product_id`，用于记录产品型号；
- `biz_device_identity`：外部身份到设备、建筑和 `expected_profile_code` 的可信绑定；
- `biz_data_point`：具体设备的标准测点；
- `biz_point_alias`：设备专属指标别名。

标准多字段别名继续使用当前兼容格式：

```text
{identityType}:{identityValue}:{metricCode}
```

产品模板在绑定事务中实例化为具体 `biz_data_point` 和 `biz_point_alias`，因此现有正式接入热路径不需要
为产品模板做远程查询，也不需要改变 TDengine 身份模型。

## 8. 状态与数据流

### 8.1 接入状态

```text
未知身份首次标准上报
  → DISCOVERED
  → 管理员选择产品、建筑、空间和设备
  → 配置检查通过，创建停用身份和测点别名
  → BOUND
  → 管理员确认并启用身份/设备/必要测点
  → ACTIVE（由正式档案状态派生，不写入 pending_device）
  → 可停用身份或设备
  → DISABLED（由正式档案状态派生）
```

`IGNORED` 只表示管理员暂不处理该身份。再次上报更新最后发现时间和计数，但不自动恢复为待处理，也不写正式数据。

### 8.2 未知设备上报

1. 标准入口完成报文结构与大小校验；
2. 本地身份查询未命中；
3. `PendingDeviceService` 按身份组合键插入或更新待绑定记录；
4. 样例只保存标准指标代码、值、单位和时间元数据，并执行大小限制；
5. 消息 ACK，避免未知身份成为永久毒消息；
6. 记录成功、失败和截断的低基数指标；
7. 不调用 `HvacIngestionService`，不写 TDengine。

待绑定记录写入短暂失败时，进行有限重试后仍 ACK，并记录错误指标和日志。设备后续周期上报会再次触发发现，
不能因管理库故障无限阻塞标准 Topic。

### 8.3 绑定事务

管理员提交接入向导后，本地 MySQL 在一个事务内：

1. 锁定待绑定记录并确认状态仍为 `DISCOVERED`；
2. 校验操作者是 `PLATFORM_ADMIN`，并校验目标建筑、空间和系统归属一致；
3. 校验产品型号已启用，身份类型和 `profileCode` 匹配；
4. 选择已有设备或创建新设备；
5. 建立停用的 `biz_device_identity`；
6. 按产品模板创建或复用测点，并创建设备专属别名；
7. 检查必填指标、单位、重复别名、跨设备和跨建筑关系；
8. 将待绑定记录更新为 `BOUND` 并关联身份记录；
9. 提交后刷新身份与测点配置缓存；
10. 管理员在确认页单独执行启用操作。

缓存刷新失败不能回滚已提交数据库事务，但必须让热路径继续使用旧完整快照并报告“配置待生效”；
启用操作在缓存确认可见后才返回成功。

### 8.4 已绑定设备上报

正式入口保持现有顺序：

```text
外部身份绑定
  → profileCode 校验
  → 整包指标别名、设备/建筑、状态、单位和范围预检
  → 逐指标复用现有幂等写入
  → 分钟聚合
  → 数据质量与公式
  → 查询、Redis 与 WebSocket
```

身份已存在但 `profileCode` 不匹配时，按安全冲突拒绝并告警；不得创建第二条待绑定记录，也不得自动修改产品或协议。

## 9. 页面与接口

第一阶段页面全部放入受控后台路由注册表，只允许显式路由，不从数据库组件字符串动态加载。

### 9.1 建筑与空间管理

建议路由：`/system/buildings`

- 建筑列表、新增、编辑、停用；
- 选中建筑后的空间树和系统分组；
- 删除前展示设备、测点和授权引用，存在引用时禁止物理删除；
- 复用现有建筑、空间和系统分组 Service，补齐权限、校验和适合页面的聚合查询；
- 第一阶段只允许 `PLATFORM_ADMIN` 修改，其他角色是否开放查看另行确认。

### 9.2 产品型号与测点模板

建议路由：`/system/device-products`

- 产品型号列表、草稿创建、复制、启用和停用；
- 选择兼容 `profileCode` 和身份类型；
- 配置标准指标到平台测点模板的明确映射；
- 启用前校验必填指标、单位、重复代码和设备类型；
- 已被设备使用的产品版本不可原地破坏性修改，必须复制为新产品版本。

云端协议模板不在此页面编辑。本页只维护本地业务模型与云端 `profileCode` 的兼容关系。

### 9.3 待绑定设备

建议路由：`/system/device-onboarding`

- 按状态、身份、协议、首次/末次时间筛选；
- 查看规范化的最新指标样例、单位、时间来源和上报次数；
- 标记忽略或恢复待处理；
- 启动接入向导；
- 展示协议冲突、配置待生效和启用结果；
- 列表不展示无限增长日志或原始敏感载荷。

建议接口：

```text
GET  /api/device-onboarding/pending
GET  /api/device-onboarding/pending/{pendingId}
PUT  /api/device-onboarding/pending/{pendingId}/status
POST /api/device-onboarding/pending/{pendingId}/bind
POST /api/device-onboarding/identities/{identityId}/activate
POST /api/device-onboarding/identities/{identityId}/deactivate
```

所有写接口使用明确请求 DTO、后端权限和建筑归属校验；重复提交通过状态和唯一约束实现幂等冲突提示。

### 9.4 设备与测点管理

建议路由：`/system/devices`

- 按建筑、空间、系统、设备类型、产品和状态筛选设备；
- 查看设备身份、协议、最后发现时间和测点完整度；
- 查看和编辑设备测点、范围、计算标记和状态；
- 展示来源别名，但不允许跨设备或跨建筑移动；
- 停用身份只停止后续正式接入，不删除既有 TDengine 历史。

## 10. 云端协议模板交付

第一阶段不建设可视化前端，协议配置采用以下受控流程：

1. 为每个产品协议准备唯一 `profileCode` 和版本；
2. 以版本化 SQL 或结构化配置包保存模板与字段映射，进入代码审查；
3. 在隔离环境验证样例报文、必填字段、单位、时间、序号和标准输出；
4. 通过受控部署写入云端 MySQL，先保持停用；
5. 校验模板唯一命中指定 Topic 后启用；
6. 发布失败或结果异常时停用新版本并恢复上一完整版本；
7. 记录模板版本、变更原因、样例摘要和验证证据，不保存密码或真实敏感载荷。

当前仓库尚未实现通用配置包导入命令。第一阶段可以继续使用受控 SQL；只有当产品模板维护频率形成真实运维负担时，
再单独实现无界面的校验/导入 CLI 或受保护管理 API。

## 11. 安全、可靠性与审计

### 11.1 权限和归属

- 首阶段只有 `PLATFORM_ADMIN` 可以创建建筑、产品、绑定设备和启停身份；
- 页面权限只是体验层，Controller 与 Service 必须重复执行角色和建筑边界校验；
- 不接受客户端提交的 `buildingId` 直接覆盖身份绑定；
- 绑定事务校验空间、系统、设备、测点和建筑的一致性；
- 协议冲突视为安全事件，不自动迁移。

### 11.2 敏感信息与载荷

- 外部身份可能属于设备敏感标识，只在业务库和授权页面中展示；
- Micrometer 标签不使用完整身份值，避免高基数和信息泄漏；
- 待绑定样例只保存规范化指标，不保存 MQTT 密码、Token 或原始未知字段；
- 列表接口对身份值提供按需脱敏展示，详情由有权限用户查看；
- 清理任务必须有批次上限、超时和可观测指标。

### 11.3 时间、重复和丢包

- `DEVICE_REPORTED` 与 `SERVER_RECEIVED` 必须在样例和正式数据中可区分；
- 没有设备 `timestamp` 时只能说明云端收到时间；
- 没有单设备递增 `seq` 时只能估计名义周期缺口，不能声称精确网络丢包；
- 生产可靠性优先要求设备端缓存补传、QoS 1、设备时间和序号；
- 待绑定样例不参与正式幂等和数据质量统计。

### 11.4 审计

至少记录：

- 创建、修改、启停产品型号；
- 待绑定设备忽略、恢复、绑定；
- 身份启用、停用和协议变更；
- 建筑、设备、测点和别名的关键变化；
- 操作者、操作时间、对象 ID、变更前后摘要和结果。

审计记录不保存密码、Token 或完整原始载荷。

## 12. 迁移与兼容

1. 现有 HVAC 设备身份、设备、测点和别名原样保留，不自动迁移为待绑定设备；
2. 现有标准多指标入口和 TDengine 写入契约保持不变；
3. 现有未知设备由“日志拒绝”切换为“有界发现记录后拒绝正式入库”；
4. 可选为现有设备补充产品型号，但不作为第一阶段上线前置条件；
5. 旧 `device/data/up` 迁移入口不用于新设备发现；
6. 产品模板实例化后仍落到现有具体测点与别名，避免下游聚合和公式同时改造；
7. 数据库迁移必须先检查外部身份、产品编码、模板指标和别名唯一冲突；
8. 回滚代码时保留新增表和数据，停用发现入口，不删除业务档案和历史。

## 13. 实施分段

为保持一个任务、分支和 PR 只处理一个明确问题，建议按以下可独立验收的工作包推进：

### 工作包 A：领域基础与发现后端

- 产品型号、产品测点模板和待绑定设备表；
- 未知设备有界 upsert、清理、指标和测试；
- 不开发页面，不改变正式已绑定链。

### 工作包 B：绑定事务与管理 API

- 产品模板管理 API；
- 待绑定查询、忽略、绑定、启停；
- 设备、测点和别名批量实例化；
- 权限、建筑一致性、缓存生效和审计。

### 工作包 C：建筑、空间、系统、设备和测点页面

- 受控后台路由与菜单；
- 建筑/空间/系统页面；
- 设备/测点页面；
- 空态、错误态、权限态和并发提交处理。

### 工作包 D：产品与接入向导页面

- 产品型号/测点模板页面；
- 待绑定列表、详情和接入向导；
- 启用确认与配置生效反馈。

### 工作包 E：真实设备与端到端验收

- 为已确认的两类 JSON 报文建立协议模板；
- 单包身份、字段、单位和入库核对；
- 未绑定、绑定、启用、协议冲突、停用全流程；
- 断线、重复、字段缺失、数据库短暂失败和 24 小时运行；
- 自动化、本地集成、云端部署和现场硬件证据分别报告。

数据质量任务、典型值管理、WebSocket 安全增强和浏览器全流程回归继续作为独立任务，不混入上述 PR。

## 14. 验证与验收标准

### 14.1 自动化验证

- 同一未知身份并发上报只产生一条待绑定记录，计数和最后时间正确；
- 样例超限被确定性截断，不保存未允许字段；
- 未知设备无论发现记录是否成功都不写 TDengine；
- 已绑定身份不进入待绑定流；
- 已知身份协议冲突被拒绝且不自动改绑；
- 产品模板启用前完成指标唯一、单位、必填和设备类型校验；
- 绑定事务任何一步失败均不留下半套身份、测点或别名；
- 两栋建筑同名设备不串绑、不串点；
- 启用后下一条合格报文进入原有正式链；
- 停用后新报文被拒绝，既有历史仍可查询；
- 普通测试不连接真实 MySQL、TDengine、Redis、Broker 或现场设备；
- 前端覆盖加载、空态、错误、权限拒绝、重复提交和迟到响应。

### 14.2 第一阶段业务验收

1. 不预创建设备时，已配置产品协议的真实设备能出现在待绑定列表；
2. 管理员能查看身份、协议、最近样例和时间来源；
3. 管理员能选择或创建建筑、空间、系统和设备，并从产品模板生成测点；
4. 绑定但未启用时不写正式时序；
5. 启用后无需修改云端 Java，下一条报文进入正确建筑和测点；
6. 同型号第二台设备只新增本地绑定，不新增云端协议模板；
7. 新 JSON 结构在当前能力范围内只新增云端配置模板，不修改适配器代码；
8. 未知设备、协议冲突和单位错误均不能污染正式数据；
9. 页面操作、后端权限和建筑范围无法通过直输 URL 或伪造请求绕过；
10. 实现结果、自动化测试、隔离集成、云端部署和现场验收分别给出证据。

## 15. 待确认事项

以下内容不阻塞先开展工作包 A，但必须在相关工作包开始前确认：

1. 待绑定样例的最大 JSON 大小、保留天数和清理批次；
2. 产品型号是否需要区分“厂商产品版本”和“平台模板版本”；
3. 建筑、设备和接入页面除 `PLATFORM_ADMIN` 外的只读角色范围；
4. 现有设备是否补录产品型号，还是仅新设备使用；
5. 第一批真实设备的正式单位、累计/周期语义、发送周期、时间戳和序号；
6. 云端协议配置继续只用受控 SQL，还是另立任务建设无界面导入 CLI；
7. 现场并发指标具体指设备数、MQTT 连接数、消息速率还是管理端用户数；
8. 第一阶段是否需要绑定前有限回放；本设计默认不回放。
