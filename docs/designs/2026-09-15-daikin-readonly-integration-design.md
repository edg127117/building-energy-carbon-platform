## 1. 状态、依据和批准边界

- 状态：设计待批准。业务范围已由用户确认，本 PR 只新增设计和状态入口，不实现代码、数据库迁移、菜单迁移或部署。

- 厂家尚未提供接口账号、项目授权和联调联系人。协议字段和样例不是现场实际能力证明。
- 当前实现状态见 [PROJECT_STATUS.md](../../PROJECT_STATUS.md)，稳定架构见 [PROJECT_GUIDE.md](../../PROJECT_GUIDE.md)。本文所有“新增、扩展、迁移”均指批准后的目标，不代表已实现。

## 2. 已确认的一阶段范围

| 范围 | 目标 |
|---|---|
| 接入基础 | 厂家认证、Token 续期、签名加密、设备清单同步、项目到建筑及设备身份关联 |
| 当前监测 | 内外机状态、室温与设定温度、风量档位、风向、外机压缩机状态、通信与故障状态 |
| 历史 | 接入后的温度曲线、平台观测到的状态变化、厂家日/月/年运行时长 |
| 明确异常 | 厂家故障、通信异常、滤网提示、平台取数失败和数据过期；记录持续和恢复 |
| 运维接入 | 现场没有设备清单，先获取厂家设备；确认建筑及真实楼层/区域即可正式接入，房间后补 |

不包含任何控制下发（含滤网提示重置）、策略生成、短信/微信通知、工单、人工关闭异常、故障诊断、节能判断或自动控制。不因新增异常列表而建设通用规则引擎。

### 2.1 已确认参数

| 参数 | 约定 |
|---|---|
| 状态采集 | 目标每 1 分钟一轮；周期可配置，实际可达性受厂家限流、更新周期和设备规模约束 |
| 取数异常 | 同一采集对象连续 3 个计划轮次失败形成异常；轮内重试不重复计数 |

| 状态变化、异常、厂家运行时长 | 保留 1 年 |
| 运行时长任务 | 每日北京时间 03:00，昨日及以前日统计为主要对象 |
| 历史补取 | 首次尝试最近 1 年；每日复查最近 7 天，恢复后补遗漏区间 |
| 月年统计 | 同步当前月、年累计值，标记未结束；月初、年初复查上一周期 |

## 4. 协议覆盖与字段语义

### 4.1 厂家调用清单

| 方法与路径 | 用途 |
|---|---|
| POST `/token`、`/token/refresh` | 获取和续期厂家 Token，独立于平台 JWT |
| GET `/v2/equipments` | 设备清单及基础状态，按协议分页 |
| GET `/v2/equipments/{equipId}` | 指定设备状态 |
| GET `/v2/equipments/abnormal` | 厂家异常设备列表 |
| GET `/v2/equipments/inunit`、`/v2/equipments/inunit/{unitId}` | 内机清单和详细状态 |
| GET `/v2/equipments/outunit`、`/v2/equipments/outunit/{unitId}` | 外机清单和压缩机状态 |
| POST `/v2/runtime/inunit`、`/v2/runtime/outunit` | 内外机日/月/年运行时长 |

仅允许上述 11 项认证/读取能力；运行时长虽为 POST，业务仍是只读。15 项 `/v2/operations/*` 不生成调用入口，不接入控制按钮。定时采集优先用能覆盖目标字段的批量接口；单设备接口用于必要核对，不对所有接口每分钟全量重复调用。

### 4.2 数据分类

| 类别 | 协议字段示例 | 处理 |
|---|---|---|
| 温度 | `roomTemp`、`temperature` | 分别为室内温度与设定温度；字段、单位和来源独立，温度数值适用质量使用门禁 |
| 风量档位 | `fanSpeed` | low/middle/high/automatic/middleLow/middleHigh/unknown；是档位，不是 m³/h、m/s 或转速 |
| 风向 | `airflowDirection` | 厂家风向编号及自动值；不自行换算成角度 |
| 状态 | `onOff`、`mode`、`unitStatus` | 保留厂家原值和规范化状态，未知枚举显示未知并可追溯 |
| 异常与维护 | `errorType`、`errorCode`、`inCommunicationError`、`inEquipmentError`、`inMantenanceMode`、`isFilterDirty` | 逐字段解释；维护和滤网提示不能全部归为故障 |
| 控制器 | `isConnectionUp`、`inForcedStop`、废弃状态 | 控制器连接状态不等同于平台取数状态或设备开关 |
| 能力/设定 | `fanSpeedSetList`、`modeSetList`、`DefaultSetpointRange`、冷热上下限及遥控器权限 | 只读展示设备能力，绝不转换为可操作控制 |
| 外机 | 压缩机开关字段、型号 | 文档表格与样例存在大小写、类型差异，联调前不锁定解析假设 |
| 关系 | `siteId`、`lcNo`、`id`、`unitId`、`masterSlaveFlag`、`masterSlaveIds` | 保留层级与原始标识；主从关系不等于内外机物理连接关系 |

`arth1` 在文档中称遥控器温度，测量含义和单位未明确，不替代 `roomTemp`，待厂家确认后启用对应展示。未返回、不支持、明确 unknown、解析失败和质量禁止均不能用零值或正常状态替代。

文档没有提供实测风量、风速、功率、电量及历史温度接口。错误码出现某种传感器名称也不代表相应数据接口已授权可用。新增厂家能力需另行确认范围。

## 5. 目标数据链路与模块边界

保持 Spring Boot 单体、既有前端模块和存储分工；不新建独立业务平台或微服务。大金客户端作为南向适配模块，负责 HTTP、分页、加密和字段规范化；领域逻辑不散落在 Controller 或页面。

```text
厂家 API
  → 大金只读适配（认证、限流、分页、规范化、来源证据）
  → 平台统一接入应用契约
      ├─ 清单发现 → 待接入区 → 归属确认/审批 → 既有设备身份
      ├─ 数值观测 → 既有数值接入与质量使用边界 → TDengine
      ├─ 类型化状态观测 → 状态保存/变化与异常投影 → MySQL
      └─ 厂家运行时长 → 统计版本与任务检查点 → MySQL
  → 带建筑权限的 /api/v1 只读查询 → 既有运维页面
```

统一接入契约是内部应用入口，不新增未经鉴权的公网入库接口。若部署需要跨进程传输，使用现有受保护 MQTT/HTTP 边界，不能让适配器直接修改资产或审批表。字符串、布尔状态不强塞 BigDecimal 数值报文，不套用平均值聚合。

数值链路复用前须核对非旧 19 测点的产品/身份支持；不为满足旧公式而伪造测点，不让大金温度自动进入冷站公式。状态接入契约扩展及状态存储属于本设计新增部分。

### 5.1 逻辑数据模型（物理表名、迁移编号在编码前按当时主线确定）

| 数据对象 | 关键约束 |
|---|---|
| 大金连接配置 | 不可变来源 ID、密钥引用、启用状态、版本、超时/限流；密钥不在普通查询返回 |
| 项目建筑映射 | 来源+厂家项目→平台建筑，版本化；未经确认不自动映射 |
| 厂家设备目录扩展 | 来源、项目、控制器、设备种类及厂家 ID 组合键；关联既有 pendingId，不建第二套正式台账 |
| 身份/归属版本 | 平台设备、厂家身份、建筑/空间/系统、生效时间；重绑和搬迁不改写历史 |
| 当前状态 | 设备及来源、字段值、字段观测时间、厂家时间（可空）、解析/缺失标志、映射版本；旧轮次不能覆盖新轮次 |
| 状态变化事件 | 前后值、观测时间、上次观测时间、gap 标志、归属快照、轮次；按设备/字段/轮次幂等 |
| 异常实例 | 来源层级、类型、影响范围、首次/最近发现、恢复时间及证据；活动实例唯一键防止重复开启 |
| 运行时长版本 | 来源/厂家设备/粒度/区间唯一业务键，值、单位、修订、采集时间、是否完整、历史归属依据 |
| 采集任务检查点 | 来源/任务/目标区间、分页进度、租约、下次重试、结果；失败任务可恢复，不凭内存判断完成 |

温度详细点不重复放入状态 MySQL 高频全量表；当前状态保留最新值，变化才记事件。每次有效轮询更新观测时间，值未变不产生变化事件。不能因压缩事件而丢失过期判定依据。跨存储用稳定观测 ID、可重试检查点及幂等写入，不宣称存在分布式事务或 MQTT PUBACK 等于业务完成。

## 6. 设备接入与归属

1. 管理员配置来源并确认厂家项目与平台建筑映射。首次拉取目录，后续低频同步及人工触发；频率按厂家限流配置，不作为本次硬编码业务参数。
2. 未映射项目的设备仅管理员可见；已映射项目可按授权建筑展示给有接入申请职责的运维人员。响应、数量、筛选和导出均在后端限制范围。
3. 待接入阶段显示最新识别信息及必要样例，不默认保存完整温度/状态历史；不得以未绑定为理由公开设备。
4. 运维确认建筑、真实楼层/区域空间、系统及设备种类，关联已有设备或创建新台账；可批量选择，按设备校验和报告成功、冲突、失败。
5. 批量采用逐设备原子申请/执行和稳定幂等键；沿用公共审批服务，不实现第二个审批引擎，不静默跳过错误或宣称整批原子成功。绑定后保持停用，再经既有启用流程进入正式采集。
6. 现有 BindRequest 的非空数值测点约束对仅有状态的外机不适用：新增类型化接入绑定契约，复用身份、归属、事务及审批执行逻辑，状态型产品允许无数值测点；旧产品必填测点规则保留。不得创建虚假温度/电量点。
7. 设备缺失于一次目录结果不删除、不解绑、不视为已恢复；只有完整同步成功才记录本轮缺失。设备身份更换、重绑和归属调整走现有敏感治理及关系版本，不自动接受厂家名称变化为归属变化。

厂家 ID 唯一范围尚待确认；在此之前采用来源+项目+控制器+内外机种类+原始 ID 的保守组合并保存完整来源字段。厂家 id 与 unitId 不互换。更换凭据不应改变稳定来源身份，跨来源合并需明确人工核对。

历史按采集时归属保存。新增房间信息只影响生效后的记录；历史更正须显式、可审计，不能执行普通关联时批量重写。补取运行时长早于平台绑定时间的记录标记“厂家历史、归属未验证”，只在当前授权设备详情中明确展示，不自动计入历史房间统计。

## 7. 采集、时间与异常

### 7.1 每分钟观测

- 后台按来源调度，页面只读平台结果，打开多个页面不增加厂家请求。
- 有界并发、单来源租约及速率预算；上一轮未结束不堆积无界任务。记录未完成轮次和覆盖范围，不能把调度落后算作厂家设备故障。
- 单页成功只更新实际返回且有效的设备字段；整轮成功要求计划页全部完成。部分分页失败不得清空未覆盖设备或恢复异常。
- 网络超时/临时服务错误有限退避重试；鉴权错误先单次协调续期，失败进入来源异常；限流遵守厂家等待指示，重试不突破速率预算。具体超时、重试上限由规模和限流确认后配置。
- 接收时间与厂家观测时间分开。若厂家不提供可靠测量时间，只能称“平台观测”，不能用响应 resTime 冒充设备测量时间。
- 只收到旧厂家时间时，不刷新其测量新鲜度；成功 HTTP、有效解析和成功持久化分别记录。页面时间以可查询的正式观测为准。

### 7.2 状态与恢复

| 事件 | 动作 |
|---|---|
| 单次失败 | 保留最后值和原时间，显示更新失败，不推断设备离线 |
| 连续 3 个计划轮次失败 | 同一来源/目标形成取数异常，内部重试不增加失败轮数；成功有效观测后重置计数 |
| 超过 5 分钟未有效观测 | 字段/设备标记过期；从首次应采集时间起无数据也可判定，但不生成假值 |
| 厂家明确故障 | 当轮打开或更新厂家故障实例，不等待 3 轮 |
| 取数恢复 | 恢复对应取数异常；厂家故障仍等明确正常字段才恢复 |
| 字段缺失/unknown/解析失败 | 保留旧字段及其原时间，标记本轮缺失/未知/无效；不清除原故障 |
| 状态在断采后不同 | 记录“恢复后观测到变化”和缺口；不把新时间写成实际开关时刻 |

过期独立定时扫描，采集器停机不能导致永不过期。平台全停期间无法实时告警，恢复时依据持久化时间标记“恢复后发现”，不伪造当时已经发出告警。

全源故障只形成一条来源异常并关联影响设备；设备详情仍显示过期影响，集中列表不为每台生成相同来源故障。来源横跨多个建筑时，运维只见自身建筑影响，不泄露其他建筑设备数、名称或凭据。

异常无人工关闭、工单或消息推送。滤网提示、维护信息单独分类，不擅自设为严重故障；未知厂家故障保留原代码及安全描述。

## 8. 历史查询与保留

- 温度按滚动 90 天保留详细数据，查询可覆盖 90 天但采用有界分段/分页；原有最多 31 天的 HVAC 查询限制不整体放宽，新查询与旧链路隔离。
- 风量档位、风向、开关、模式按变化事件保留 1 年，可显示时间线，不平均档位、不连线跨越缺口、不声称记录操作人员。
- 状态变化按观测时间、已恢复异常按恢复时间滚动保留 1 年；尚未恢复异常保留当前实例，不因首次发现超过 1 年而消失。超期明细可清理，保留开放实例的最小首次发现依据。
- 厂家运行时长按统计区间结束日保留 1 年；当前未结束月/年结果保持当前版本。修订证据遵守同一窗口，不无限保留完整厂家响应。
- 清理使用分批任务及进度，不大事务全表删除；待接入目录不能无条件复用旧短期遥测样例清理规则。复用公共审计时遵守现有保全/保留治理。
- 非温度数值字段只有专业含义确认且在范围内才启用历史；厂家未提供的业务数据不随机生成、不插值补造。

## 9. 厂家运行时长同步

采用 Asia/Shanghai 每日 03:00 持久化调度，任务幂等键按来源、设备种类和目标统计区间生成。日期请求映射按厂家确认的时区/边界处理，不能把北京时间任务直接等同于厂家统计时区。

1. 首次按厂家允许跨度分批尝试最近 1 年；不支持的区间明确标缺失，不无限重试永久错误。
2. 每日获取昨日及以前日结果，复查最近 7 天；同步当前月、年累计并标记“未结束”，月初/年初复查上一周期。
3. 停机后依据检查点补遗漏区间，最近数据优先，历史补取不挤占分钟采集预算。
4. 同一统计键保留可追溯修订，数值变化不简单追加后求和；厂家日/月/年结果独立保存，不能日值求和冒充厂家月年值。
5. 空结果、明确零、失败分开；不覆盖成功值为零。失败有限重试，最终记录来源异常并保留待补任务。
6. 区间超过平台保留窗不持续补取。厂家 totalRuntime 与设备分项含义、单位及一致性待确认，不自行定义不明分母或统计公式。

## 10. 页面入口与权限

遵守 [前端边界](../../web/AGENTS.md)，复用唯一入口、外壳、共享组件和既有模块。以下是拟实施变更，不是现有菜单状态。

| 入口 | 变化 |
|---|---|
| 智慧运维 → 设备管理 → 待接入设备 | 从配置管理迁移现有页面；建议目标 `/operations/devices/pendingDevices`，增加厂家同步、范围过滤、归属与批量申请 |
| 智慧运维 → 设备管理 → 设备台账 | 复用现有入口，显示厂家关联及只读监测入口；原档案写权限保留 |
| 智慧运维 → 实时监控 → 暖通空调监控 | 扩展现有入口，支持已授权建筑的内外机列表、当前状态及历史下钻，保持继承 HVAC 内容可用 |
| 智慧运维 → 报警管理 → 实时报警/历史报警 | 复用已有注册入口，补当前占位页业务，不新增“大金异常中心”菜单 |
| 能碳配置管理 → 数据接入 | 厂家凭据、协议、产品模板、采集参数留在配置侧；复用适用页面，HTTP 连接设置为必要扩展 |

旧 `/system/device-onboarding` 和 `/configuration/ingestion/pendingDevices` 仅一对一兼容新入口；菜单迁移保持原授权集合，不自动授权整个运维系统。新运维使用者按服务器显式授权进入。页面布局复用现有模式，本设计不扩展为前端整体改版。

只按两层使用方式组织，不新增四套业务角色：

- 有授权运维：查看本建筑监测与异常；有既有提交职责者可以同步、核对、提交绑定及接入启停申请。适配旧接口管理员限制时新增范围受控入口，不直接移除所有管理员校验。
- 平台管理员：配置厂家接入参数、项目映射、授权，并在拥有现有审核职责时处理审批。提交与审核冲突校验继续沿用，不因菜单迁移绕过。

账号业务角色沿用既有体系，不把“运维”直接当作已存在角色代码；使用现有建筑授权、菜单叶子权限及后台提交/审核职责。后台从资源解析可信建筑，禁止信任请求传入 buildingId。待接入及读详情每次也校验来源项目范围。

## 11. 平台查询契约方向

新增平台 API 使用 `/api/v1`、独立 DTO、PageResponse 或有界游标分页、OpenAPI 和契约测试。下列为设计拟定路径，编码前核对现有路由冲突；不能与厂家 `/v2` 混为同一服务。

| 拟定路径 | 职责 |
|---|---|
| POST `/api/v1/daikin/sources/{sourceId}/sync-jobs` | 有权限人员触发清单同步，返回任务 ID；不等待无限分页完成 |
| GET `/api/v1/daikin/sources/{sourceId}/sync-jobs/{jobId}` | 查询范围受限的同步结果和失败原因 |
| GET `/api/v1/hvac-monitoring/buildings/{buildingId}/devices` | 分页查询内外机当前状态，按空间/种类/状态/异常筛选 |
| GET `/api/v1/hvac-monitoring/devices/{equipmentId}` | 只读状态及字段来源、时间、未知/过期说明 |
| GET `/api/v1/hvac-monitoring/devices/{equipmentId}/temperatures` | 90 天内有界温度历史，缺口和质量标记 |
| GET `/api/v1/hvac-monitoring/devices/{equipmentId}/state-events` | 1 年内状态观测变化，游标分页 |
| GET `/api/v1/hvac-monitoring/devices/{equipmentId}/runtime` | 厂家统计、修订、区间完整性、同步状态 |
| GET `/api/v1/hvac-monitoring/buildings/{buildingId}/exceptions` | 本建筑来源/设备异常，当前和历史共用查询服务 |

待接入查询、绑定申请继续扩展现有契约和审批类型，不建重复 CRUD。所有枚举提供未知兜底；状态成功、字段有效、时间新鲜、质量允许分别表达。历史区间采用平台统一毫秒时间戳和半开区间；厂家 YYYYMMDD 请求只在适配层转换。

## 12. 安全、迁移和失败处理

- 厂家客户端仅认证/读取路径白名单，正式采集默认关闭；凭据、项目映射、专业口径未就绪时拒绝正式启用并给出缺项，不连接猜测目标。
- 按协议第 6 页实现排序拼接、Salt、UTF-8、MD5 大写签名及 AES/ECB/PKCS5Padding/Base64；这只是兼容厂家协议，不推广为平台通用加密方案。HTTPS 证书与主机名校验不关闭。
- Header 参数是否参与签名、GET 加密载荷位置、字符序列化和空参数签名细节需厂家确认；用正式向量验签前不宣称兼容成功，不从展示样例猜测密钥。
- 凭据通过受保护配置/密钥引用管理，Token 不下发浏览器；日志、样例、审计和错误信息脱敏。仅允许配置的厂家目标，禁止任意 URL 代理。
- 保存配置、通过审批、采集器加载、首次持久化观测是不同阶段，分别显示；失败保留可重试状态。
- 仅通过新增 Flyway 迁移引入所需结构与菜单映射，不改既有已执行脚本；数据与查询先部署，再启用任务和菜单。旧接口/旧菜单兼容迁移，不批量扩大授权。
- 回退先停用新采集/同步与菜单入口，保留历史和审计；不回滚删除共享资产或恢复旧控制功能。温度过期与异常仍需如实显示停采原因。

## 14. 验证和交付

实现拆分顺序：认证/目录适配及隔离契约 → 身份绑定与权限迁移 → 数值/状态/异常持久化 → 运行时长及清理恢复 → 页面集成 → 独立软件验收 → 厂家联调/现场验收。每步保持可关闭，不在设计批准前编码。

| 验证层级 | 必须覆盖 |
|---|---|
| 单元与契约 | 签名加密正式向量就绪前先明确标记本地向量；分页、空值、未知枚举、字段时间、缺口、幂等和旧轮次覆盖 |
| 接入/权限隔离 | 跨建筑拒绝、未知项目隐藏、身份冲突、批量部分失败、停用绑定与独立启用、拒绝绕过旧审批 |
| 定时与异常 | 可控时钟验证 3 轮、超过 5 分钟、来源故障去重、字段缺失不恢复、停机恢复、租约竞争和任务补取 |
| 存储与保留 | MySQL/TDengine 专用隔离环境，90 天查询及清理边界、1 年边界、未恢复异常保留、跨存储重试不重复 |
| 运行时长 | 日/月/年独立结果、零/空/失败、修正、区间去重、每日 03:00 时区、首次补取与恢复补取、历史归属未验证 |
| 前端 | 现有入口兼容、运维与管理员权限、真实后端契约、无数据/过期/部分失败、无控制按钮及凭据泄露 |
| 软件最终检查 | 按仓库验证矩阵运行 Java 与 Vue 检查；外部条件缺失时记录未验证，不用 Mock 宣称现场成功 |
| 厂家和现场 | 正式账号认证、项目设备范围、真实字段/单位、限流和数据时效、抽查开关模式与室温、故障与恢复、厂家同条件运行时长 |

无需等待 90 天或 1 年才能验证保留规则，可用隔离时间数据；真实长期稳定性另记证据，不据此宣称已运行相应时长。容量验收按厂家设备数量、峰值轮询量和保存窗口测算，达到可持续一分钟目标后才能宣称满足刷新要求。
