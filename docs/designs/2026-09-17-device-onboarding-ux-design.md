# 设备报文接入流程与客户可读性优化设计

## 1. 状态与决策边界

- 状态：用户已确认设计，进入实现与软件验证阶段；本文描述目标行为，不代表已经实现。
- 用户已确认本文，并授权完成实现、验证、提交、推送和创建 PR；部署不在本次范围。
- 依据：当前产品模板、协议配置与预览、发布审批和待接入页面，以及用户反馈的技术编码过多、筛选布局失衡、搜索不可用和配置负担问题。
- 发布保留规则及接入辅助功能已经合入主线，直接复用，不重复迁移来源工作树。
- 工程规则见 [AGENTS.md](../../AGENTS.md)、[前端边界](../../web/AGENTS.md)；当前能力见 [PROJECT_STATUS.md](../../PROJECT_STATUS.md)，稳定链路见 [PROJECT_GUIDE.md](../../PROJECT_GUIDE.md)。

## 2. 目标、范围与非目标

目标是让具有设备接入职责的客户或实施人员，通过中文业务名称和明确步骤完成产品选择、字段映射、解析检查、审批发布及设备绑定，减少重复填写、页面跳转和无意义点击。首次接入提供顺序引导，维护已有规则允许直接定位编辑。

纳入范围：

1. 产品模板、协议配置与预览、发布面板和待接入列表的接入相关交互。
2. 产品创建及允许编辑的草稿在主页面抽屉中完成，复用已有产品接口、复制能力和审批逻辑。
3. 产品名称、设备类型、规则版本、发布摘要和审批信息的客户可读展示。
4. 产品及待接入筛选栏的布局、搜索反馈和真实查询行为核验。
5. 发布集合只读预览、历史集合详情及必要的前后端契约测试。

不包含整个平台重设计、大金厂家运维页面重做、新解析语言或协议自动推断、批量设备绑定、业务单位推算、远程控制、数据库数据操作、云端配置变更、生产审批简化。默认不新增数据库结构；如实现证明必须持久化新信息，先说明原因并单独确认。

## 3. 必须保留的现有行为

| 既有约束 | 本次处理 |
|---|---|
| 普通发布按 profileCode 合并，保留其他协议，同编码替换版本 | 保留，新增可读集合清单 |
| 显式历史回退恢复历史完整集合，分配新序号 | 保留，独立入口明确移除和版本变化 |
| 同 Topic 允许不同 JSON 判别路径；每条报文零匹配、多匹配均拒绝 | 保留；单样例预览不得宣称覆盖所有报文组合 |
| 产品、绑定、身份启停与发布的后端权限和审批 | 保留；前端提示不授予权限 |
| 研发自审仅在后端受控测试配置允许且留审计 | 保留；页面只展示实际策略，不提供绕过开关 |
| 数值解析、单位换算与发布集合校验由后端负责 | 保留；前端只做输入辅助与结果呈现 |
| JSON 样例不持久化 | 保留，不新增浏览器本地存储或后端样例保存 |
| 来源工作树仍承担验收服务 | 保留，不停服务、不抢端口、不清理来源、不接触现有数据库 |

## 4. 信息结构和布局

菜单显示名由“协议配置与预览”调整为“设备报文接入”，保留现有路由、权限键和深链接。页面说明其用途是配置经适配器接入的 JSON 报文，避免与厂家 API 接入混淆。如果菜单文字由持久化菜单管理，实施时先核对来源，不能仅为改名操作现有数据库；确需迁移则按第 2 节处理。

主页面沿用现有 Element Plus 组件与 --bec- 样式 Token。顶部为产品名称、草稿保存状态和五阶段导航；中部仅展开当前工作区；底部突出当前主要操作。高级功能保留在“更多操作”，不以大量并列按钮占据主区域。

| 阶段 | 主要内容 | 主要操作 | 完成依据 |
|---|---|---|---|
| 产品与测点 | 产品选择、中文设备类型、启用状态、测点摘要；抽屉创建/编辑 | 配置报文 | 已获取有效产品契约；未启用产品可编辑和预览但不能发布 |
| 报文与映射 | JSON 输入与字段树、身份/判别/时间字段、测点映射 | 检查解析 | 当前样例和配置满足输入要求 |
| 解析检查 | 成功/异常摘要、设备身份、时间来源、测点结果 | 查看发布清单 | 当前配置样例检查通过，并与已保存修订一致 |
| 发布与加载 | 目标、集合变化清单、审批进度、加载回执 | 提交发布申请；随后按职责显示审批操作 | 对应目标、序号和摘要的实际状态 |
| 设备接入 | 携带协议条件打开待接入列表、绑定、身份状态和正式读数入口 | 接入设备或查看读数 | 分别读取真实绑定、启用及正式数据结果 |

步骤可回访，不把五步做成每次必须重走的向导。编辑老草稿直接定位映射；已有不可变版本仍可走发布入口，不要求为了重新发布而重新填写样例。第五阶段复用待接入页，通过显式返回入口回到原草稿；离开前保存配置，样例离开后不保证保留，并提前提示。

## 5. 产品和映射交互

### 5.1 产品

- 搜索选择已有产品；创建和允许编辑的产品草稿在抽屉内完成，成功后自动选中并重新读取后端契约。
- 复用产品复制能力；对已启用或不允许修改的产品尊重 allowedActions，不打开可编辑表单。
- 协议编码、身份类型、目标单位和必填属性来自产品契约，展示为摘要，避免重复填写。
- 切换产品前如会清除或改变映射，说明影响并确认；不得静默丢失用户配置。
- 未启用产品提供既有审批入口，执行后刷新实际产品状态；不能将申请创建成功显示成已启用。

### 5.2 字段与测点

桌面左右分栏：左侧样例和字段样值，右侧产品测点映射；窄屏按顺序堆叠。以启用产品测点为行，必填项标记清晰，不再要求逐条“新增映射”才能看到待配置项。

每行显示测点中文名称、来源字段选择、样例值、来源单位、目标单位和校验状态。未选择来源的可选测点不生成空映射；必填测点未配置阻止进入有效预览。已有禁用映射必须可查看、可恢复，不能因为切换布局而静默删除。

倍率、偏移、映射启停和排序等放入按需展开区域；非默认值在折叠摘要中持续可见。目标单位由产品带入，来源单位和倍率由有依据的模板提供或人工确认，禁止凭数值大小猜测。字段选择提供样例值和类型，不自动认定 SN、型号判别值或时间语义。

必填缺失、重复测点、非数字来源等在对应位置显示；顶部仅汇总待办数量，点击可定位。保留后端校验为最终依据。

## 6. 预览、保存和版本一致性

预览默认显示通过/未通过、解析成功数量、异常数量、设备身份与时间来源。错误行默认展开；成功测点结果可展开查看，完整路径、原值、换算值及错误码位于技术明细。折叠不会删除结果或改变业务判断。

样例和任何影响解析的配置改变后立即使旧预览失效；迟到响应不能覆盖新编辑。保存状态明确区分“未保存”“保存中”“已保存”“保存失败”。草稿保存沿用现有合法性要求，不以“随时保存”承诺当前接口不能接收的不完整草稿。

进入当前草稿的发布确认时，顺序为校验输入、保存变更、确认后端归一化后的配置与有效预览一致、必要时重新预览、冻结对应修订。任一步失败停止后续操作，保留输入和可重试入口；若保存成功但冻结失败，明确告知草稿已保存。并发编辑或产品契约变化返回冲突后，提供重新加载和重新检查入口，不自动覆盖。

前端的预览门槛是操作辅助，不是新后端安全凭证。本次不新增持久化预览证明，也不改变已有服务端版本冻结安全模型。历史不可变版本展示其版本内容，不能标注为“本次样例已通过”。

## 7. 中文名称和技术信息分层

| 信息 | 默认展示 | 追溯信息 |
|---|---|---|
| 产品 | 已登记产品名称；可附型号 | 原 productCode，可复制 |
| 设备类型 | 后端类型字典名称，如空调内机/空调外机 | IDU/ODU 等原编码 |
| 协议规则 | 配置名称、草稿修订或规则版本、测点数 | profileCode、versionId、校验值 |
| 发布记录 | 操作名称、目标名称、配置序号、状态与时间 | 目标 ID、配置校验值、完整集合 |
| 审批 | 业务操作名称、状态和提交时间 | 原审批 ID，可复制 |

规则版本与目标配置序号分别命名，不把草稿 r1 误称为全局发布版本。哈希称“配置校验值”，不称业务“内容摘要”。摘要如“新增外机规则、保留内机规则”从后端集合差异生成，不能根据当前勾选项猜测。

同名项通过型号、版本和必要的次要编码区分，不只依赖颜色或悬停。缺失名称时显示“未命名产品（原编码）”或“未知类型（原编码）”，不猜测用途。列表技术标识单行省略，并提供键盘可访问的详情及复制入口。

公共审批组件修改只增加可选业务展示信息并保持旧调用兼容；不借本任务重做全平台审批页，也不把任意审批 payload 原样展示给客户。

## 8. 筛选和搜索

产品与待接入列表统一为“主要搜索框 + 紧凑状态选择 + 查询 + 重置”。搜索有足够最小可用宽度并占剩余空间；窄屏换行，状态不占满整行挤压输入。

- 产品提示明确为“搜索产品名称、型号或编码”，匹配现有后端能力。
- 待接入按既有设备身份字段查询，提示明确查询对象；实施时核对精确/模糊匹配语义，不擅自扩展为全字段搜索。
- 回车与点击查询共用逻辑；状态变化直接触发查询；查询重置到第一页。
- 重置清空用户筛选；从协议流程带入的协议范围单独显示为范围标签，普通重置保留它，另提供“查看全部设备”显式取消。
- 加载、无匹配、权限不足和请求失败各有明确反馈。请求失败不能伪装为空列表，迟到响应不得覆盖新条件。
- 当前已发现宽度约束不足；用户报告“不能用”的运行原因尚未复现，实施必须验证输入到后端再到结果的完整链路，不能把 CSS 调整视为搜索修复完成。

## 9. 发布只读契约与审批衔接

在既有 /api/v1/protocol-deployments 下新增最小只读计算和详情能力，复用现有管理员权限与服务层校验，不新增发布旁路。

建议契约：

| 接口 | 输入 | 返回和语义 |
|---|---|---|
| POST /preview | targetId、expectedSequence、versionIds | 规范化完整集合、摘要、按 profileCode 的新增/替换/保留项及前后版本；只计算，不创建审批、冻结版本或写部署 |
| POST /rollback-preview | targetId、expectedSequence、historicalSequence | 已加载历史集合及相对当前集合的恢复/移除/版本变化；复用历史回退校验 |
| GET /targets/{targetId}/history/{sequence} | 目标和序号 | 该次不可变发布集合、版本名称和映射数，以及已有状态和时间；不返回凭据 |

DTO 的条目包含业务名称、profileCode、versionId、规则修订和映射数量；前后版本分别给出，前端不自行合并规则。以服务器当前目标期望集合为比较基准，界面明确“待加载配置”与“已确认加载配置”，不能把最新提交集合冒充当前运行集合。

提交申请继续使用原接口和冻结命令；后端重新验证序号、完整集合与权限。目标序号变化则要求刷新清单，不自动提交与用户确认不同的集合。展示用名称不参与版本标识或摘要计算；历史名称优先取版本快照，无法取得历史名称时保留原编码，不推断。

加载阶段展示审批状态和部署状态两条信息，不做虚假线性进度。当前发布待加载时建议每 5 秒查询可见页面的目标及历史状态；离开或页面隐藏停止，恢复可见立即刷新；失败、未知或超过 2 分钟停止自动查询，保留手动刷新并显示最后查询时间。等待超时只说明尚未确认，不自行改成加载失败。

## 10. 验证与验收

设计文档阶段仅检查链接、术语、边界和 git diff --check。实现阶段依照 [验证 Skill](../../.agents/skills/iot-change-verification/SKILL.md) 运行定向测试、前端完整门禁，以及涉及 Java 时的后端要求。

| 场景 | 验收要求 |
|---|---|
| 内机 7 项、外机 11 项样例 | 使用经核对的脱敏样例完成配置和预览；数据仅作隔离测试，不混入正式业务 |
| 中文展示 | 列表和选项优先名称；缺失/同名情况仍可区分；技术编码可追溯 |
| 搜索 | 名称/型号/编码按产品契约命中；设备身份按其契约命中；覆盖回车、状态、组合条件、重置、分页和请求失败 |
| 编辑状态 | 切产品、切草稿、离开页面有丢失提示；迟到请求、保存失败、修订冲突不覆盖输入 |
| 预览与冻结 | 修改后预览失效；实际冻结修订对应所见内容；部分成功有准确提示 |
| 发布集合 | 新增外机不丢内机；同编码替换；同编码多版本拒绝；回退显示移除项；预览无写入副作用 |
| 匹配与权限 | 不同判别路径共存，零/多匹配拒绝；越权拒绝；生产自审限制保留 |
| 加载状态 | 只认对应目标、序号、摘要的回执；等待、失败、未知和旧回执均不显示为新配置已加载 |
| 设备数据 | 解析成功、绑定成功、身份启用和正式读数分开；无数据显示缺失，不生成随机数据 |
| 页面检查 | 桌面及窄屏无筛选挤压、长编码撑列；键盘可操作，状态不只靠颜色传达 |

浏览器验证使用可用连接和隔离环境；无法连接时如实记录未验证，不反复要求用户开关扩展、不宣称视觉验收通过。启动环境遵守仓库开发生命周期规范，不使用来源验收服务或现有数据库。真实设备、云端加载和持续现场验收须另行授权与记录，普通自动化不替代现场证据。

## 11. 实施顺序与批准项

1. 确认本文的信息结构、中文展示、搜索语义、发布契约和刷新策略。
2. 实现产品抽屉、筛选修复、中文名称、测点映射和预览摘要。
3. 实现后端只读集合契约，串接发布确认、审批/加载与设备接入。
4. 完成隔离自动化、可用条件下的浏览器检查及差异审查；报告已实现、已测试和未验证边界。

用户确认本文即批准上述限定范围的编码和必要测试；不包含自动 Git 交付、云端部署或来源清理。若新增数据库结构、权限模型变化或真实环境操作成为依赖，先单独说明并确认。
