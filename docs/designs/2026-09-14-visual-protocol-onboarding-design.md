# 设备协议可视化接入设计

## 1. 状态与目标

状态：设计方案，待实施。用户已确认建设方向；本文的页面、接口、同步协议和验收要求均不代表已实现。文档合并不代表功能上线，也不改变当前正式基线或现场验收状态。

目标：遇到支持范围内的新设备、新 JSON 报文格式，运维人员通过页面完成协议识别、测点映射、解析验证和配置发布，无需手写 SQL；同类设备复用模板，只补设备身份与安装归属。

本次设计交付仅新增本文，不修改运行代码、数据库、前端骨架和云端配置。实施完成必须覆盖“页面配置到适配器确认加载”的闭环，不能把数据库操作留给用户。

## 2. 当前基础与缺口

当前代码提供以下可复用基础：

- [产品与测点模板页面](../../web/src/modules/device-onboarding/pages/ProductTemplatePage.vue)：产品草稿及测点模板维护。
- [待接入设备页面](../../web/src/modules/device-onboarding/pages/PendingDevicePage.vue)：设备发现、绑定准备及审批衔接。
- [JSON 解析器](../../telemetry-adapter/src/main/java/com/platform/adapter/parser/JsonTelemetryAdapter.java)：JSON Pointer 取值、数值换算、必填校验和标准化输出。
- [配置快照提供器](../../telemetry-adapter/src/main/java/com/platform/adapter/profile/JdbcProtocolProfileProvider.java)：读取启用模板和映射，完整加载后替换快照，失败保留旧快照；按精确 Topic 和单字段取值选择唯一规则。
- [内机七测点配置样例](../../telemetry-adapter/src/main/resources/db/indoor-unit-meter-1039.example.sql)：现有字段和单位的参考，不作为自动生产初始化指令。

缺口：原始报文映射没有统一可视化编辑与预览；平台产品模板与云端解析配置分离；缺少受控发布、目标版本加载回执和回退界面。现有数据库定时刷新不等于已有跨系统配置发布功能。

## 3. 范围与硬约束

第一期支持 JSON 对象、嵌套字段和固定数组下标；每包一个设备身份；数字类型测点；倍率与偏移换算；精确 Topic 加一个判别字段的等值条件；产品模板复用。

第一期不支持二进制协议、脚本执行、任意表达式、正则匹配、动态数组拆分多设备、字符串转数字、布尔或枚举测点。超出范围时明确报错，不静默转换。批量绑定与 Excel 导入不是本期交付依赖。

保留以下既有约束：

- Spring Boot 平台后端、Vue 前端和既有适配层职责；不新增微服务拆分。
- MySQL 管理配置，TDengine 保存时序；浏览器不生成业务数据、不重算后端解析结果。
- 设备归属、建筑范围、敏感变更审批和审计继续有效；协议发布不能代替设备身份激活。
- 单位、测点语义与专业参数由配置人员确认；字段名称只能辅助填写，不能自动认定含义。
- 保留 MQTT V1/V2 既有契约和可靠性边界；配置加载回执不是业务报文持久化 ACK，也不升级设备可靠性承诺。
- 不包含控制、下发运行参数、策略执行；不自动纳入公式或能源结算。

## 4. 用户流程与页面

在运维系统“设备接入”下增加“协议配置”，沿用现有视觉骨架。列表展示协议、关联产品、目标适配器、配置版本、审批状态、发布状态、最近加载时间和失败原因。

| 步骤 | 用户输入 | 系统行为 |
| --- | --- | --- |
| 基本信息 | 协议名称、产品模板、设备类型、Topic | 复用已有产品或建立产品草稿 |
| 样例报文 | 粘贴 JSON | 展示字段树、类型和样例值，不默认全选字段 |
| 身份与识别 | 点击 SN 路径、可选判别字段及取值 | 生成 JSON Pointer，校验唯一匹配 |
| 测点映射 | 勾选字段、关联测点、确认单位 | 自动带出路径和已有模板属性 |
| 解析预览 | 点击验证 | 后端执行实际解析逻辑并显示结果 |
| 审批发布 | 提交变更并选择已登记目标 | 审批后同步，显示目标加载状态 |

路径通过点击生成，正确转义 JSON Pointer 中的 `~` 和 `/`。编辑表包含原字段、样例值、标准指标编码、名称、源单位、目标单位、倍率、偏移、必填、启用和顺序。标准指标编码必须与关联产品测点一致，不让用户在两处重复录入。

新增测点可同步准备产品草稿。发布前检查关联产品已批准版本与协议映射兼容；未批准的产品变更不能随协议绕过审批生效。对已启用模板的修改创建新版本，不能直接覆盖。

## 5. 内外机及多设备识别

产品模板定义设备业务类型和测点；协议定义原始字段如何转换为标准指标；设备绑定定义 SN、具体设备及空间归属。这三者不可混为同一条规则。

- 不同 Topic 可以分别配置。
- 同 Topic 的多个规则只允许使用同一判别路径、不同明确取值；运行时必须恰好命中一个。
- 相同取值、多个无条件规则、无条件与条件规则并存，以及不同判别路径且无法证明互斥的组合，均拒绝发布。
- 运行时零命中或多命中都拒绝解析并记录诊断，不按顺序或最新版本猜选。
- 冲突检查以目标适配器的完整启用配置集合为范围，包括迁入的历史规则，不只检查当前编辑项。

例如同 Topic 下可按 `/deviceType` 的 `INDOOR`、`OUTDOOR` 区分。`M=1039` 可能只是电表型号，不能推断所测设备属于内机或外机。

若内外机使用相同电表、相同字段及指标语义，可以共用协议，在产品与设备绑定环节分别归属。若解析方式不同但报文不可区分，第一期要求调整 Topic 或增加判别字段；不承诺按 SN 自动路由，因为当前解析快照不具备该能力。

## 6. 解析契约与预览

后端预览与适配器共用无外部副作用的解析核心和一致的契约测试，不维护两份独立算法。实现时提取现有解析逻辑为可复用模块，保留既有输出契约；不是将适配器服务整体搬入平台。

换算为 `结果 = 原值 × 倍率 + 偏移量`，使用十进制计算。第一期只接收 JSON 数字；缺失可选字段显示“未提供”，不补零；缺失必填字段、非数字和重复指标编码导致整包失败。限制负载大小、嵌套深度、字段数量和预览频率；具体默认值在实现中配置化并测试边界。

时间字段若配置，沿用现有 Unix 毫秒契约并校验；没有设备时间时标记接收时间来源。预览使用显式测试接收时间，标为预览值，不伪装成设备时间。消息标识与 ACK 相关高级字段不得由页面默认提升可靠性等级。

预览输出：命中协议、设备身份、时间来源、测点原值、换算值、单位、缺失与错误路径。预览不发布 MQTT、不写 TDengine、不创建待接入或真实设备。成功仅证明当前样例可解析，不代表现场验收。

样例默认仅用于当前预览；如需保存为回归样例，要求脱敏、限制保留范围，不保存口令或完整生产身份。诊断日志不记录完整原始报文。

## 7. 配置模型与接口边界

以下为拟新增的逻辑模型，数据库结构及迁移编号由实现确定：

| 对象 | 关键内容 |
| --- | --- |
| 协议草稿 | 基本信息、产品引用、识别规则、身份与时间路径、映射、乐观锁版本 |
| 协议版本 | 不可变完整内容、内容摘要、审批引用、解析能力版本 |
| 适配器目标 | 受控登记身份、能力、最近联系时间、允许配置范围 |
| 发布记录 | 目标、完整配置集合、单调发布序号、目标摘要、操作者、审批及结果 |
| 加载回执 | 目标身份、发布序号、已加载摘要、时间和结构化错误 |

平台 MySQL 是批准配置的权威来源；适配器本地持久化完整快照作为运行缓存，禁止双向编辑同步。产品、协议版本和部署状态分别建模。

建议 API 使用 `/api/v1/protocol-configurations` 管理草稿、校验、预览和版本；`/api/v1/protocol-deployments` 管理发布状态与回退；适配器专用 `/api/v1/adapter-configurations` 接口负责拉取与回执。具体 DTO、分页及 OpenAPI 按现有工程契约实现。

Controller 负责鉴权和请求校验，Service 负责审批、版本及事务，Repository 保存配置，独立同步组件负责适配器交互。浏览器不得直连云端 MySQL或持有其凭据。

平台管理员维护共享协议；建筑范围继续由既有设备绑定接口校验。保存使用乐观锁，过期草稿返回冲突；发布幂等键不得导致重复变更。审批关联不可变版本与摘要，审批后编辑必须重新审批。

## 8. 发布、同步与回退

推荐适配器主动通过受保护的 HTTPS 接口拉取批准配置并上报加载回执，不给浏览器开数据库权限，也不为此暴露公共 MySQL。实施前必须验证云端到平台配置服务的连通性；平台仅在本地且不可达时，不得显示为可发布，网络方案需明确后再实施连接部分。

使用独立适配器身份、目标范围授权和凭据安全存储；不可关闭 TLS 校验解决连接问题。配置内容摘要用于一致性检查，不能替代连接认证。

发布完整目标集合而非零散字段更新：

1. 校验目标能力、关联产品及全部启用规则，审批绑定完整发布内容。
2. 保存发布序号和完整快照，适配器拉取并校验类型、摘要和匹配冲突。
3. 候选内容先完整持久化，再原子切换运行快照；过程中继续使用上一版本。
4. 仅在运行切换成功后回报对应发布序号与摘要。回执丢失可幂等重报。
5. 平台核对目标身份、序号与摘要后显示已加载；数据库写成功或请求已发送不算生效。

配置状态为草稿、待审批、已批准、已归档；发布状态为待同步、已加载、加载失败、状态未知。审批状态与运行状态分开展示。多目标发布逐个反馈，不承诺跨适配器同时生效；部分成功不得显示整体完成。

配置无效、断网或拉取失败时保留上一有效版本；冷启动无有效快照时停止解析并报告不可用。已有本地有效快照可离线恢复。忽略旧发布和乱序回执；回退以新的单调发布序号引用历史配置内容，不降低发布序号，也不回退已经写入的遥测数据。

## 9. 既有云端兼容与迁移

现有内机七点通过数据库配置可工作，不意味着旧适配器已有远程同步与回执。首次上线本功能需要一次受控适配器升级；之后在支持能力范围内新增协议仅发布配置。

迁移前备份并导入现有全部规则到平台，核对 Topic、启用状态、路径、单位和契约版本。明确每个目标的唯一配置权威：旧数据库轮询模式与新远程模式不得同时改写运行快照。发布新配置前完成存量解析结果对比，保留旧包与配置恢复方式。

适配器报告解析及输出能力版本；能力不足时阻止发布，不静默升级业务输出。V1/V2 MQTT 输出迁移不是本设计的默认动作。平台同时检查协议标识、产品指标和既有绑定别名，避免配置已加载但标准报文无法被下游识别。

## 10. 实施阶段

1. 配置与预览：版本模型、草稿接口、字段树、产品关联、共用解析核心、预览及错误反馈。
2. 发布闭环：审批衔接、目标能力、同步与持久快照、加载状态、回退和迁移。
3. 接入衔接：复用已有待接入设备绑定，贯通产品、协议及测点，完成隔离环境验收。

第一阶段只能称为配置预览完成；三个阶段通过后才能称为可视化接入闭环完成。设备 SN、安装位置与身份激活仍在绑定环节处理，不要求配置协议时先有真实设备。

## 11. 验收矩阵

| 场景 | 必须证明的结果 |
| --- | --- |
| 内机七点样例 | 全程页面配置，预览得到已确认七项数值与单位，无手写 SQL |
| 新外机 JSON 样例 | 支持范围内无需改代码，独立配置并发布成功 |

| 重启及回退 | 已确认快照可恢复；回退产生新发布记录，解析恢复历史配置行为 |
| 权限与审批 | 越权目标、跨建筑绑定、自审批违规及审批后篡改被拒绝 |
| 真实解析一致性 | 预览与适配器对同一输入产生相同指标、单位及错误语义 |
| 完整接入 | 隔离 Broker 和数据库证明发布、解析及标准报文入库，各层证据分别记录 |

普通测试使用 Mock 或专用测试环境；真实设备、现场网络和持续运行单独验收，不以样例或本地通过替代。前端按仓库验证矩阵执行，Java 覆盖配置并发、鉴权、失败路径和解析兼容；适配器独立验证断网、重启、回退和旧契约。
