# 天气功能前端展示与配置接入设计

状态：本会话确认后的实施设计，已形成前端及必要后端增量活动候选，完成本地自动化与隔离样例浏览器检查，已部署至局域网测试环境。目标 MySQL V67 迁移、服务、发布文件哈希、页面资源与未登录鉴权已核验；真实角色联调及日电量现场验收尚未完成，不提升正式基线。

## 1. 范围与既有约束

建设天气概览、历史天气、天气数据接入三个页面。历史天气内使用“历史气象 / 电耗对照”页签；电耗对照目前只展示日用电量与日均温或日均湿度。未来形成独立分析能力时再讨论迁入能耗管理，本次不预建分析模块。

保留天气后端设计的来源分工、整批回退、位置版本、建筑权限、北京时间日界、24 个有效小时日均规则、六分钟前界及质量/计量关系校验。页面只显示后端结果，不重算日均或日电量，不填零、不连接缺失段，不增加预测模型、归因、控制、导出、系统电量合计或内机电量分摊。

原静态效果图的分区仅作参考，其英文字段、接口路径、重复说明、顶栏统一状态和不符合整批回退规则的样例被本设计替代。后续以真实组件渲染结果进行视觉验收，不把示意图数据当作业务数据。

## 2. 菜单与权限

| 工作区 | 分组 | 页面 | 规范路径 |
|---|---|---|---|
| 智慧运维 | 天气数据 | 天气概览 | `/operations/weather/overview` |
| 智慧运维 | 天气数据 | 历史天气 | `/operations/weather/history` |
| 能碳配置 | 数据接入 | 天气数据接入 | `/configuration/ingestion/weather` |

天气数据分组排序在实时监控之后、能耗管理之前。沿用现有 OfficeLayout、Token、Element Plus、Lucide、ChartView 和模块语言注册。不新增工作区，不复制外壳，不为从未上线的 `/weather/*` 创建兼容重定向。

新叶子同时登记数据库菜单和前端注册表；迁移按规范路径检查冲突，不硬占用户自建菜单 ID。天气读取沿用 BUILDING_OWNER、ENERGY_MANAGER、PLATFORM_ADMIN 与建筑范围。默认授予上述正式角色运维天气入口；配置入口授予 ENERGY_MANAGER、PLATFORM_ADMIN，实际操作按后端返回能力控制。位置维护和天气补采仅管理员；日电量补算要求 ENERGY_MANAGER 或 PLATFORM_ADMIN 且具有 ENERGY_CALCULATION_RUN 职责。菜单显示和按钮隐藏不代替后端复核。

## 3. 统一信息层级

- 主视图只显示业务名称、数值、单位、时间、必要状态和操作。品牌 Open-Meteo 与标准单位保留，字段名及英文枚举不直接显示。
- 常态不堆叠绿色标签；异常明确使用中文文本和颜色，颜色不是唯一提示。
- 当前天气、七日预报、小时序列分别显示自己的数据时间和更新状态，禁止从其中一个状态推断整个页面正常。
- “数据说明”收纳来源、模型属性、实际时间与获取时间、覆盖范围、坐标、位置版本、数据集和原因码；业务原因先显示中文，原码仅在技术详情内提供。
- 未配置、无数据、部分缺失、更新过期、采集失败、访问失败分别呈现。已有值更新失败时保留旧值并标明状态；切换建筑或条件则立即清除旧范围数据并取消在途请求。

## 4. 页面交互

### 4.1 天气概览

顶部只保留标题、建筑选择和刷新。主体为当前天气与七日预报，下方为小时曲线。

当前天气展示温度、中文天气、湿度、风速和风向，短说明为“模型天气”；不称为现场实况。七日卡只显示日期、天气、高低温和精简风信息，范围为今天及未来六天。按后端 selectedSource 整组呈现，不能自行拼源。中国天气网高温缺失时，若备用源合格则显示备用整批并提示“已使用备用预报”；两源都不合格才显示后端旧批次及缺失/过期状态，不猜测源端缺值原因。

图表标题为“小时预报”，显示准确日期范围，不写“从现在起未来 168 小时”。温度、湿度为主图，降水、辐射、风按需展开；保留单位与图例，统计期间放入提示。降水单位 mm（前一小时累计），辐射 W/m²（前一小时平均）。刷新只重读平台保存结果，不触发源站任务。

### 4.2 历史天气

共同保留建筑、日期与页签。默认最近 14 个已结束日，起点不早于 2024-01-01，日查询最长 366 天。页签切换保留合法条件。

历史气象表默认列：日期、天气/高低温、日均温、日均湿度、状态、详情。小时覆盖数在缺失状态或详情中显示，不为完整记录重复增加两列。日均不足 24 个有效小时显示空值并给出覆盖数。点击日期查看小时曲线；小时查询最长 31 天，长范围不把未加载部分呈现为缺失，默认查看选中日并显示实际图表范围。

电耗对照页签先查询合格计量对象，选择展示业务名称；编码和计量边界收在补充信息中。无对象时说明“暂无可对照的计量对象”，不影响历史天气。日期逐日保留，电量柱与天气折线独立缺失。精确与近似日电量采用不同柱形样式和中文图例；近似原因、实际起止时间、日界偏差和质量/关系版本可在日期详情查询。默认表格只显示日期、日电量、气象日均值、状态、详情。详情保留两侧状态，不把历史无电量称为零用电。

### 4.3 天气数据接入

建筑选择与页面权限能力先加载；管理员可见最新位置摘要，任务操作和最近任务按职责展示。位置摘要显示名称、坐标、覆盖层级、生效日和启停；版本/技术信息收起。编辑表单使用日期选择，统一转换为北京时间零点；提示 WGS84 坐标，不自行把其他坐标系当作 WGS84。表单打开时固定乐观锁版本，新版本生效日必须晚于最新版本；背景刷新不能把旧表单套到新版本上。

补采与补算按操作权限显示。数据源和数据类型用中文，来源联动保持后端产品限制；当前与预报日期由产品固定，历史仅已结束日。补算只选择后端认可的计量对象。幂等键在同一次提交及网络不确定重试期间复用，新的明确操作才生成新键；防止双击重复提交。请求只入队，成功提示“任务已提交”，不宣称采集或计算已经完成。

任务列表默认列：任务内容、日期范围、执行状态、创建时间、详情。详情提供任务编号、来源、尝试次数、中文原因及可复制技术码。支持列表与单任务刷新；只读刷新不重试后台任务。完成、排队、运行、重试中、失败、阻断分别显示。

## 5. 必需后端增量

1. 新增 `GET /api/v1/weather/buildings/{building}/energy-comparison/targets`。复用天气读权限和建筑范围，在后端复用当前有效关系与累计 kWh 资格校验，返回稳定排序的有界候选对象。返回对象标识、系统/测点标识、中文业务名称、计量边界、单位和关系版本；列表资格不保证所有历史日期都有电量。无有效关系与合法空列表可解释，越权/服务失败不能伪装为空列表；候选加载后关系改变仍由对照/补算接口复核。
2. 新增 `GET /api/v1/weather/buildings/{building}/management`，返回位置维护、天气补采与日电量补算能力，复用既有角色及动态职责；管理员同时获得最新位置版本（包括尚未生效版本）。不向前端暴露全员职责。操作提交始终重新鉴权，能力快照不是授权凭证。
3. 菜单增量迁移使用 V67；不改已发布 V64 或其他迁移。首次新增时为天气目录让出排序位置，其余同级目录保留相对顺序。覆盖菜单路径冲突、重复插入防护及正式角色授权；目标 MySQL 隔离副本已验证重复执行与冲突阻断，测试部署后已确认 V67 执行成功。

天气 Overview、hourly、daily、comparison、binding-versions 和 jobs 沿用现有契约。建筑下拉使用权限内建筑列表，不以只包含已配置位置的 locations 接口替代全部可访问建筑。

代码进入 `web/src/modules/weather`，按 api、models、composables、components、pages、locales、routes、public 分层。跨模块只经 public.ts。图表复用 shared/charts，样式采用现有 --bec- Token。控件标签简短中文，详情保留可追溯信息。

定向验证覆盖权限、对象资格、UTC/北京时间转换、跨度边界、缺失与零值、来源回退、建筑切换竞态、提交幂等、任务与错误状态、导航授权。再执行仓库 Java 与前端完整门禁。浏览器以隔离接口样例检查三个页面和两种历史视图，在 1366×768、1920×1080 检查布局、表格和图表；样例验证不代替真实数据验收。

真实后端角色联调、目标 MySQL 菜单迁移、现场日电量口径、长期天气采集及正式上线单独验收。交付时如实记录未完成项。
