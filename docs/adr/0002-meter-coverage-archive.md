# ADR-0002：表计现场档案与能源计量治理分开维护

- 状态：设计已获用户确认，实现属于活动候选，现场配置和验收单独报告
- 日期：2026-09-29
- 范围：表计分类、安装位置与一表多设备覆盖清单

## 背景

既有空调电表产品使用内机、外机分类，容易把采集电表当作被测空调。
资产的空间外键也不能证明电表实际安装位置。用户确认需要一块电表覆盖多台设备，
并明确内机侧与外机侧分别查看，不汇总、不自动分摊。

现有整楼关系治理会接管建筑结构归属。仅维护现场表计档案不应自动启用该模式。

## 决策

1. 增加独立的版本化表计档案，沿用资产管理员权限，后端校验表计、空间和被测设备属于同一建筑。
2. 第一阶段只允许设备类型的被测对象，不以房间名称推断设备清单，不将其他电表作为被测设备。
3. 安装位置允许未知。它与资产原空间、被测设备空间分开，不修改原采集路径中的空间或系统归属。
4. 保存产生新版本，包含操作者、原因、服务端生效时间和设备名称/位置快照；并发修改通过版本号拒绝覆盖。
   未配置或空清单不推断覆盖范围；没有有效版本的历史日期保持未知。
5. 清单只表示共同计量覆盖，接口固定返回 `GROUP_ONLY`、`SEPARATE_ONLY`。不提供分摊比例、总分表层级或相加算法。
6. 既有能源语义、计量边界、专业确认、质量策略和关系审批约束全部保留。
   本档案不自动写入能源治理，也不能被聚合模块当作已审核计量分配。
   后续衔接必须携带档案版本并显式确认，不并行计算另一套正式能耗。
7. 纠正已确认电表产品的资产分类，保留存量设备 ID、设备编码、测点、协议和身份绑定。
   新增电表使用独立类型及编码前缀。现场设备清单通过档案接口设置，不写死在通用迁移中。

## 后果与边界

- 设备档案后续改名不会改写历史快照；已经删除的被测设备仍在历史中显示，并标记当前不可用。
- 设备清单不是多联机拓扑。外机与内机的服务关系另行维护，不能从同一系统分组推定。
- 本次不支持回溯设置生效时间。已知历史覆盖需要独立的证据和审批设计，不能用当前关系回填。
- 空间/建筑总表、水表和热量表是后续扩展，当前接口不宣称已支持。
- 数据库迁移与软件测试、服务器实际配置、现场验收分开交付。
