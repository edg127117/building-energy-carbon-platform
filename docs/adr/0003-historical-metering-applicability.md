# 历史计量适用范围独立于关系激活时间

状态：用户已批准实现的活动候选，合并和部署状态以当前交付为准。

## 决策

首次接入已有历史的建筑时，可以依据图纸、原平台关系或测试配置，审核确认某个固定关系版本适用的历史期间。确认支持真实历史和隔离测试数据；数据性质仍由来源与运行环境决定，不因审核变成现场实测。

保留 `effective_at` 的真实激活时间和现有关系投影。另存历史计量适用申请，绑定建筑、已激活关系版本、快照摘要、半开期间、依据和提交审核人。只允许覆盖该建筑首个关系激活之前的空白，不改写已经治理的期间。重叠申请拒绝；驳回后可更正重提；批准记录冻结。

沿用能源管理员提交、平台管理员审核以及现有测试自审配置；批准后，分类查询、封账分类分解和人工月度计算共同使用确认记录。当前及后续采集继续遵循原有激活时间。人工月度计算将确认 ID 固定到证据；旧证据不新增空字段，避免改变既有证据哈希。

原关系治理设计中“立即生效、不追溯生效、不回填历史日期”的约束保留。本决策增加独立历史计量依据，不把关系激活、当前资产归属或历史数据写入时间倒填到过去；冻结历史设计不修改。

## 接口

- `GET /v1/relation-models/{buildingId}/historical-metering-scopes`：查询本建筑申请及状态。
- `POST /v1/relation-models/{buildingId}/versions/{versionId}/historical-metering-scopes`：提交，带 `Idempotency-Key`。
- `POST /v1/relation-models/{buildingId}/historical-metering-scopes/{scopeId}/review`：批准或驳回，带 `Idempotency-Key`。

提交示例，时间为 UTC，对应上海时区 2025-09-01 至 2026-10-01：

```json
{
  "startInclusive": "2025-08-31T16:00:00Z",
  "endExclusive": "2026-09-30T16:00:00Z",
  "evidenceReference": "月度测试数据集及固定计量关系版本",
  "reason": "确认既有历史的计量适用范围"
}
```

审核示例：`{"approved":true,"reason":"已核对来源和计量范围"}`。只提供历史的一部分时，完整月份计算仍拒绝；没有批准记录时沿用原有提示。

## 数据与兼容

V93 只新增 `biz_historical_metering_scope`，不更新已有读数、关系、因子或结果。版本号避开并行前端分支已使用的 V90—V92；发布前应合并检查完整迁移序列，不能先在运行库执行 V93 再期待自动补执行更低版本。这里不包含部署或跨环境迁移。

新增能力没有改变计量公式、源数据质量、单位倍率、封账和碳因子选用。能源绑定、周期口径、分类和因子本身仍须覆盖历史期间；历史适用确认不代替这些配置。
