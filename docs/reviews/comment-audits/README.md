# 中文注释审计归档

本目录永久保存生产代码任务合并时的完整中文注释审计快照。它用于回答“当时哪些生产文件和符号经过了什么判断”，不代替当前源码、测试或业务设计文档。

## 路径和命名

每个包含生产 Java、Vue 或 TypeScript 变化的 PR 新增一份文档：

```text
docs/reviews/comment-audits/<year>/<YYYY-MM-DD>-<task>.md
```

- `<year>` 必须是四位年份，并与文件日期年份一致。
- `<task>` 只使用小写英文、数字和连字符。
- 文件名不使用 PR 编号，保证创建 PR 前即可准备。
- 一个 PR 只引用一份审计文档。
- 纯文档、测试、构建配置或非生产脚本任务不创建空报告。

## 生成和填写

在任务分支完成生产代码修改后运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/New-CommentAuditReport.ps1 `
  -BaseRef origin/main `
  -HeadRef HEAD `
  -OutputPath docs/reviews/comment-audits/2026/2026-08-06-example.md
```

生成器会写入任务元数据、全部变化生产文件、扫描器识别出的全部方法或函数，以及需要人工完成的占位项。提交前必须：

1. 填写文件职责、上游、下游、数据源和结果消费者。
2. 把“现有注释时效”改为“已核验”。
3. 记录扫描器未识别但需要人工审查的符号；没有时明确写“无”。
4. 为每个符号选择允许的判定，并填写业务说明或具体免注释原因。
5. 清除全部“待填写”和“待核验”。
6. 将文档与生产代码一起提交，并在 PR 的“注释审计”章节提供唯一的仓库相对链接。

## 历史不可变规则

- 新任务不能复用已经存在于 base 分支的历史报告。
- 同一 PR 后续提交继续更新本 PR 新增的同一份报告，确保它覆盖最新生产代码差异。
- 报告合并后成为不可变历史快照；后续生产代码变化必须创建新文档，不能回写旧报告。
- 文档中的源码行号只对应报告合并时的提交，不保证与当前 `main` 的行号一致。
- Git 提交天然保存报告所对应的历史版本，因此文档不写会形成自引用的最终 `HEAD SHA`。

门禁会重新扫描 PR 的 base/head 差异，确认链接安全、文档相对 base 为新增，并继续逐项校验文件、符号、注释时效、判定和原因。文档进入仓库不表示人工判断可以省略。
